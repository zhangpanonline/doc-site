Harness 是什么：从「选马」到「做马具」

词源
Harness 意为马具；原作者的判断是「马具对骑乘的影响非常大」，因此也被译为「驾驭工程 / 缰绳工程」。
核心主张
把注意力从「选什么马（模型）」转移到「怎么驾驭模型」——同一匹马，马具不同，结果可以完全不同。
工程化定义
「每当发现 agent 犯错，就花时间设计一个方案，让 agent 永远不再犯同一个错。」
两种落地形态
① 更好的隐式提示（把每条错误沉淀成 AGENTS.md 里的一行）；② 真正的可编程工具（给 agent 自己验证「我做对了」的脚本，例如跑过滤后的测试、截图对比）。

三大核心关注点（一条链，不是三张清单）

关注点要解决什么关键判据
情境与状态管理复杂长周期任务里拿到正确上下文、记住任务状态，避免「失忆」与「跑偏」顺序是 召回 → 规划 → 行动
护栏严格管理 AI 能调用哪些工具、访问哪些数据最小权限原则：只给完成当前任务所必需的权限
可观测三个问题都要有答案：模型知道是否完成了吗？判断依据是什么？从哪里获取判断所需信息？判据的信息必须来自环境（工具真实返回、测试结果），不是模型自述

串起来：知道自己知道什么（情境）→ 只被允许做该做的（护栏）→ 能证明自己做对了（可观测）。

落到课程代码：外壳的五个部件

部件在本课程 agent/ 里的落点
工具面18 章的工具 Schema（type: "function" + name / description / parameters / required）；19 章用 Pydantic 动态建模参数
权限「只注册当前任务需要的工具」——session.tools = registry.schemas() 决定模型能看见什么；执行前参数校验（Tool.__call__ 先校验再执行）
可观测EventEmitter + ModelListener 事件流（一次挂全事件）、Session.print_friendly() 轨迹复盘
错误处理Tool.__call__ 用 try/except + traceback.format_exception 把异常转成字符串回灌会话：单个工具失败不崩进程，模型能读到错误自我修正；代价是失败被「正常化」，需要日志与指标兜住
人工检查点有副作用的动作（写文件、跑命令）要能停下来等人拍板；用 Session.save() / Session.load() 落盘恢复，避免重跑烧掉长任务的时间与成本

易错点

  • 把 Harness 当成「把提示词写长一点」——它主要是工程约束（权限、状态、可观测、检查点）
  • 可观测只记录模型自述（「我完成了」），而没有环境证据（工具返回、测试输出）
  • 给 Agent 一次性开放全部工具（违反最小权限），出事时无法界定影响面
  • 工具失败一律吞掉回灌、不做失败率统计——问题被静默化，最后表现为「Agent 一直重试」
  • 长任务没有落盘/恢复机制，一次中断就要从头再来
