Agent 的组装结构与 ReAct 循环

Agent（入口/编排）
Agent(*, session=None, model=None, model_listener=None)：session or Session()、model or Model()；传入 model_listener 时构造即 listener.listen(self.model)。
Model（模型层）
继承 EventEmitter，封装 chat.completions.create；invoke() / invoke_stream()，流式时边解析边发射事件。
Session（会话层）
管理 messages 与 tools；add_message()、save() / load()、__str__（JSON）、print_friendly()（分段 + 截断）。
Tool registry（工具层）
registry.schemas() 给模型看工具定义；registry.invoke(message) 提取 tool_calls 执行，返回 tool 消息列表，没有调用则返回 None。
Listener（监听层）
ModelListener(ABC) + 实现类 ModelPrinterListener；消费事件流，负责打印、日志等副作用。

ReAct 循环：四步与出口

agent.invoke(q)
  1. session.add_message({"role": "user", "content": q})
  2. while True:
       resp = model.invoke_stream(session)        # 内部已把 assistant 消息写进 session
       call_msg = registry.invoke(session.messages[-1])
  3.   if call_msg is None:                       # 没有 tool_calls
         responses.append(resp); break           # ← 唯一出口
       else:                                     # 有 tool_calls
         session.messages += call_msg            # 追加 role="tool" 的结果消息
         responses.append(resp)                  # 回到第 2 步
  4. return responses                            # 每轮一个 InvokeResult，最终答案在最后一个
  • 退出判据是有没有工具调用，不是正文有没有内容——模型可以先解释一句再调工具，此时循环必须继续。
  • role: "tool" 的消息必须紧跟那条带 tool_calls 的 assistant 消息；本章靠 _process 先写 assistant、再追加 tool 的天然顺序保证。
  • while True 没有停止条件——官方提醒 Agent 常需最大迭代次数这类停止条件来保持控制。

事件监听链路

Event（事件常量）
  reasoning_start / reasoning / reasoning_end
  content_start   / content   / content_end
  tool_call_start / tool_call / tool_call_end
  complete                                   # 已定义，本章没有 emit 点

EventEmitter（事件总线）
  _listeners: dict[str, list[Callable]] = field(default_factory=lambda: defaultdict(list))
  on(event, callback)   → _listeners[event].append(callback)   # 只 append，不去重
  emit(event, **data)   → for cb in _listeners.get(event, []): cb(event, **data)

ModelListener(ABC)
  listening = True                       # 开关：挡的是回调，不是事件
  listen(model) → 遍历 Event 上的事件常量，逐个 model.on(event=e, callback=self._model_print_callback)
  _model_print_callback(e, **args) → if not listening: return; self._handler(e, **args)
  _handler(e, **args)  @abstractmethod   # 子类必须实现，否则 ABC 不允许实例化

ModelPrinterListener._handler
  reasoning_start → 思考中...      reasoning_end → 换行
  content_start   → 内容：         content       → 绿色增量片段
  tool_call_end   → 青色「调用工具：xxx」

解耦收益：Model 只负责 emit，打印 / 日志 / 前端推送各自派生监听器，Model 一行不用改（分析.md 设计亮点 2）。

流式解析：三个 Builder 与结果封装

Builder盯什么字段发射的事件结束条件
ReasoningBuilderreasoning_content / reasoning（兼容取值）reasoning_start / reasoning / reasoning_end出现 content 或 tool_calls，或 finish_reason 非空
ContentBuildercontentcontent_start / content / content_endfinish_reason 非空
ToolCallsBuildertool_callstool_call_start / tool_call / tool_call_endfinish_reason 非空
  • 每个 chunk 同时喂给三个 Builder，各自用 getattr(delta, field_name, None) 判断有没有自己的值——互不干扰。
  • ToolCallsBuilder.append_value：按 tc_delta.index 归位（不足处补占位 dict），arguments 是字符串分片拼接；_normalize_tool_calls 再把对象统一成 dict。参数在流中途是半截 JSON，不能提前 json.loads。
  • InvokeResult：message（进会话）+ raw（原始响应）；print_raw() 查看原始数据。is_end 统一看 chunk.choices[0].finish_reason。

排错清单（本章高频坑）

现象根因修法
终端一片安静，任务却跑完了没有传 model_listener（监听器是可选的）构造时传 Agent(model_listener=ModelPrinterListener())
循环提前结束，工具没执行误把「正文非空」当退出条件判据只能是 registry.invoke(...) 是否为 None
同一段输出打印两遍监听器重复注册（on 只 append 不去重，listen 不幂等）注册前查重，或让 listen 幂等
进程停不下来、成本飙升while True 无停止条件，模型持续调工具加最大迭代次数 / 超时 / 预算，重复工具调用熔断
调用方拿到的是中间旁白responses 是每轮结果的列表，最终答案在最后一个直接返回最终 InvokeResult，轨迹交给监听器/日志
