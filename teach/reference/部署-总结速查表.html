部署全景

  1. PR → CI（装依赖 + 跑测试）——合入前质量门禁
  2. tag → CD（构建 + 部署）——显式发布信号
  3. Dockerfile 多阶段构建 → 推 ACR（版本 tag，不用 latest）
  4. ACK 部署 Pod（Helm + secret 注入）
  5. ALB 路由 → 域名 CNAME → HTTPS（80 重定向 443）

面试讲述框架（作业题）

① 架构定位
微服务架构，AI 服务不直接对外，由业务后端调用。
② 链路顺讲
PR→CI；tag→CD：Dockerfile→ACR→ACK→ALB→域名。
③ 划清职责
自己：Dockerfile/依赖/健康检查；运维：集群与网络。
④ 兜底
短时间学习，自建流水线没问题。

诚实层级：未亲自参与但了解流程，细节不深——坦诚 + 有料 > 术语堆砌。
