实现MCP服务器速查表

配合《实现MCP服务器互动教学课程》使用。

四步建一个 MCP 服务端（本章全景）

# ① 装包（课程锁定 1.28.1，对应 python-sdk 的 v1.28.1 标签）
uv add mcp==1.28.1

# ② 建服务
from mcp.server.fastmcp import FastMCP
mcp = FastMCP("Weather Service", json_response=True)

# ③ 注册工具（类型标注 = JSON Schema，docstring = 工具描述）
@mcp.tool()
async def get_weather(city: str = "成都") -> dict[str, str]:
    """Get weather data for a city"""
    return {"city": city, "temperature": "22", "condition": "多云", "humidity": "65%"}

# ④ 跑起来（底层 starlette + uvicorn，默认挂载在 /mcp）
mcp.run(transport="streamable-http")

# Notebook 场景：别阻塞内核，把服务丢进独立线程
import threading
def run():
    """在独立线程中运行服务器"""
    mcp.run(transport="streamable-http")
threading.Thread(target=run).start()

测试服务：npx -y @modelcontextprotocol/inspector@1.0.0，在 UI 里连 http://localhost:8000/mcp。

装饰器 → 协议定义：各自的唯一说明书

源码里写的东西协议里对应字段谁在看它
函数名 get_weathertools/list 的 name客户端路由 tools/call 的键
docstringdescription模型——决定它选不选这个工具
类型标注 city: strinputSchema.properties模型——决定参数怎么填
无默认值的参数inputSchema.required服务端与客户端双侧校验
有默认值的参数不进 required（可选）模型可以不传 → 服务端回落到默认值
返回类型标注结构化输出 / outputSchema 校验客户端解析结果

官方原话：「no JSON Schema（a: int, b: int is the schema）、no request parsing、no validation code、no protocol handling」——省掉的是样板代码，省不掉的是把 docstring 和参数说明写清楚。

三种原语：别都会塞进 @mcp.tool()

原语定位该不该有副作用
@mcp.tool()让模型执行动作（类似 POST）预期有计算与副作用
@mcp.resource()把数据读给模型（类似 GET）不应做重计算或产生副作用
@mcp.prompt()可复用的提示词模板只产出消息

工具在 MCP 里是 model-controlled：模型自行发现并调用；规范同时要求始终保留人在环路中，客户端应展示调用参数并让用户可拒绝。

传输与端点速查

传输进程模型默认端点什么时候用
stdio客户端把服务端当子进程拉起，消息走 stdin/stdout（换行分隔，stdout 只能是合法 MCP 消息）无网络端点本地一对一、桌面客户端集成
streamable-http独立进程，可同时处理多个客户端连接；POST 送消息、GET 可选开 SSE 流/mcp（本地 http://localhost:8000/mcp）生产部署首选
sse（已被取代）独立进程，事件流单向、端点点分离/sse仅为兼容老客户端
json_response=True
响应格式从 SSE 事件流改为一次性 JSON。是服务端的配置决定：规范要求客户端两种格式都必须支持。
stateless_http=True
去掉会话状态。官方对高扩展场景的建议组合是 stateless_http=True + json_response=True。
会话 ID
有状态模式下服务端在 initialize 响应带 Mcp-Session-Id；客户端后续请求必须带。服务端终止会话后对该 ID 回 404，客户端收到 404 必须重新初始化。
协议版本头
HTTP 场景下客户端须在后续请求带 MCP-Protocol-Version；服务端收到非法或不支持的版本必须回 400。
挂到已有 ASGI 应用
mcp.streamable_http_app() + Starlette 的 Mount；用 settings.streamable_http_path 改挂载路径。浏览器直连需配 CORS 并 expose_headers=["Mcp-Session-Id"]。

错误模型：两张表不能混

类型典型场景怎么表达
协议错误未知工具、参数不合法、服务端错误JSON-RPC error 对象
工具执行错误第三方 API 失败、限流、业务逻辑失败结果里 isError: true + 文本内容
from mcp.server.fastmcp.exceptions import ToolError

@mcp.tool()
def divide(a: float, b: float) -> float:
    """Divide two numbers."""
    if b == 0:
        raise ToolError("Cannot divide by zero")   # 推荐：可预期失败
    return a / b
# 未处理异常也会被框架捕获成 isError=True，不会弄崩服务端
# 需要精细控制时返回 CallToolResult(content=[...], isError=True)

上线前的安全与易错清单

项要求依据
Origin 头校验必须校验所有入站连接的 Origin，防 DNS rebinding规范 MUST
绑定地址本地运行只绑 127.0.0.1，不要 0.0.0.0规范 SHOULD
认证对所有连接做认证（SDK 支持 OAuth 2.1）规范 SHOULD
工具入参校验全部入参、做访问控制、对调用限流、清洗输出规范 MUST/SHOULD
超时为每个请求设超时，防挂死与资源耗尽规范 SHOULD
  • 易错 1：Notebook 里直接 mcp.run(...) → 内核被阻塞，后面的单元格永远不执行；用子线程。
  • 易错 2：拿根路径 http://localhost:8000/ 探测服务 → 必然 404，Streamable HTTP 的端点是 /mcp。
  • 易错 3：参数留了默认值（如 city: str = "成都"）→ 在 inputSchema 里不是必填，模型可以不传，你只会一直拿到默认结果。要么去掉默认值，要么在 docstring 里把默认语义讲清。
  • 易错 4：把业务失败当协议失败抛 → 客户端以为工具不存在；限流、API 失败应走 isError: true（ToolError）。
  • 易错 5：只用裸 curl POST 测端点 → 缺规范要求的 Accept 头（须同时含 application/json 与 text/event-stream）；命令行验证优先用 Inspector 的 --cli 模式。
  • 易错 6：Inspector 版本与协议对不上导致握手失败 → 先对齐课程锁定的 @modelcontextprotocol/inspector@1.0.0（新版官方文档要求 Node 22.19.0+），再怀疑业务代码。
