uv 命令速记

uv init .                # 初始化 uv 工程（生成 pyproject.toml）
uv add numpy             # 运行时依赖 → project.dependencies
uv add --dev jupyter     # 开发期工具 → dependency-groups
uv remove jupyter        # 装错字段时先移除，再按正确字段装回
uv sync                  # 按 uv.lock 复现同一套环境
uv run python -c "import numpy; print(numpy.__version__)"   # 在工程环境里验证
命令写到哪什么时候用
uv add <pkg>project.dependencies（对外发布的依赖）运行这个工程的程序时需要的库，如 numpy / pandas
uv add --dev <pkg>dependency-groups（本地开发用的依赖）只在写代码、探索数据时用的工具，如 jupyter

判据一句话：「跑起来需要它吗」——需要用 uv add，只在开发时用 uv add --dev。--dev 不等于「不写进配置」，它照样进 pyproject.toml 与锁文件。

解释器选择要点

内核（kernel）
真正执行单元格的进程，由某个具体 Python 解释器启动；VS Code 右上角的解释器/kernel 选择器决定 Notebook 挂到谁身上。
工程环境 .venv
uv 放在 pyproject.toml 旁边的持久虚拟环境，uv add 装的包都在这里；换台机器 uv sync 即可复现。
怎么选
选择器里选带 .venv 路径的那一项（macOS/Linux：.venv/bin/python；Windows：.venv\Scripts\python）——切勿用系统 Python 或 conda base。
刚装完包
正在运行的内核不会自动看到新包：重启内核后再 import，并从上游单元格重新执行一遍。
检查清单
工程存在吗（有 pyproject.toml）→ 依赖落到对字段了吗（dependencies / dependency-groups）→ 内核挂到 .venv 了吗。

常见报错与修法

现象根因修法
ModuleNotFoundError: No module named 'numpy'内核跑的是别的解释器，包装进了工程 .venv 之外的环境右上角选择器切到带 .venv 路径的 Python，重启内核；确认依赖已 uv add
给工程 uv add jupyter 后，交付产物里多出 Notebook 工具链把开发期工具当成了运行时依赖uv remove jupyter 后改用 uv add --dev jupyter
依赖都在，运行单元格仍报 import 失败安装发生在内核启动之后重启内核，再从头（Run All）执行需要的单元格
NameError: name 'df' is not defined单元格是按需执行的，跳着跑就缺上游定义的变量重启内核并从第一个单元格顺序执行；关键逻辑沉淀成 .py 模块
改动上游单元格后结果没变下游单元格仍在使用内核里旧的变量值重新执行上游单元格，或「重启内核 + 全量重跑」后再看结果
