token统计速查表

配合《token统计互动教学课程》使用。

事前统计 vs 事后统计

维度事前统计事后统计
时机把文本发送给大模型之前模型服务商 API 调用之后
数据来源本地分词器（tiktoken / transformers）或服务商的免费统计接口API 接口会告知你本次 token 用量
用途拦截超窗输入、额度预校验、预算审批、报价展示账单核算、与预估值对账校准
局限是估算——消息结构、模型口径变化都会带来偏差拿到时请求已经发出并计费，拦不住任何东西

四个典型落地场景（课件原文）：单轮输入长度拦截（10 万字合同超 100k token → 直接提示分段，不发起无效 API 调用）、用户额度 / 充值计费预校验、企业预算前置审批、报价前置展示。

三条统计路线对照

路线适用模型依赖 / 网络核心调用
服务商 API 接口该服务商自己的模型（如 Kimi）需要 API Key，走网络；接口免费POST /v1/tokenizers/estimate-token-count，读 data.total_tokens
tiktoken（SDK）OpenAI 模型无需 API Key；首次联网下载词表并缓存，之后完全本地encoding_for_model("gpt-4o") → len(encoding.encode(text))
transformers（SDK）开源模型（Hugging Face 上发布）首次下载分词器文件（仅几 MB，不含权重），之后本地AutoTokenizer.from_pretrained("deepseek-ai/DeepSeek-V3") → len(tokenizer.encode(text))

国内访问 Hugging Face 需配置镜像：os.environ["HF_ENDPOINT"] = "http://hf-mirror.com"（可直连时删掉这行）。

核心代码速查

# ① 服务商 API 接口（以 Moonshot / Kimi 为例，免费统计）
import requests, os
from dotenv import load_dotenv
load_dotenv('../.env')
API_KEY = os.environ.get("MOONSHOT_API_KEY")

response = requests.post(
    "https://api.moonshot.cn/v1/tokenizers/estimate-token-count",
    headers={"Authorization": f"Bearer {API_KEY}",
             "Content-Type": "application/json"},
    json={"model": "kimi-k3",
          "messages": [{"role": "user", "content": text}]},
)
result = response.json()
print(result['data']['total_tokens'])          # Token 数

# ② tiktoken（OpenAI 官方分词库，本地统计，无需 API Key）
import tiktoken
encoding = tiktoken.encoding_for_model("gpt-4o")   # 首次联网下载词表并缓存
tokens = encoding.encode(text)                     # Token 序列
print(len(text), len(tokens))                      # 字符数 vs Token 数

# ③ transformers（Hugging Face 官方库，开源模型）
import os
os.environ["HF_ENDPOINT"] = "http://hf-mirror.com"  # 国内镜像，可直连则删
from transformers import AutoTokenizer
tokenizer = AutoTokenizer.from_pretrained("deepseek-ai/DeepSeek-V3")
tokens = tokenizer.encode(text)
print(len(text), len(tokens))

依赖安装（课件口径）：uv add requests python-dotenv · uv add tiktoken · uv add transformers。

易错点与工程口径

字符数 ≠ token 数
同一段文本的 len(text) 与 len(tokens) 并不相等；中英文、不同模型的切法都不同，计费与窗口判断只能按 token 算。
模型要配对分词器
tiktoken 只对应 OpenAI 模型的编码；其它模型用服务商接口或其配套分词器。拿错词表会把预估算错且不易察觉。
词表只需预热一次
tiktoken 与 transformers 首次都要联网下载（词表 / 分词器文件），之后统计纯本地；生产上编码实例应缓存复用，不要每个请求重建。
预估值与账单的差
消息的角色、名称等结构本身也占 token；具体口径还会随模型更新变化。预估用于拦截与报价，最终以 API 返回的用量为准。
拦截要发生在调用之前
先统计、再与模型上下文上限比较，超限直接提示分段/摘要——发出去等报错等于白付一次调用。
输入输出分开计价
报价时除输入 token 外，还要把输出上限一起折算；缓存命中的部分通常单价更低。
