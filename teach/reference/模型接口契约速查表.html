本地模型方案选型

方案定位什么时候选它
Pytorch + Transformers本地训练 / 微调 / 推理要改模型本身；推理需自行适配硬件加速
Ollama命令行一键部署运行开源大模型默认入口：内置量化支持与 GPU 加速，带 OpenAI 兼容接口
llama.cppC/C++ 高性能推理引擎CPU 推理、多种量化方案
vLLM高吞吐推理框架（PagedAttention）生产环境部署、要吞吐
MLXApple 官方 ML 框架Apple Silicon 本地推理
LM Studio图形界面桌面应用一键下载/运行模型，想要 GUI
LocalAI本地推理服务（OpenAI 兼容 API）让现有应用无缝切换后端

一句话：训练微调找 Transformers，命令行体验找 Ollama，压榨 CPU 找 llama.cpp，上生产要吞吐找 vLLM。

Ollama：命令与接口速查

ollama -v                          # 版本
ollama pull qwen3-vl               # 拉取模型
ollama list                         # 已下载的模型
ollama show <模型名称>             # 模型信息
ollama run <模型名称>              # 运行模型
ollama rm <模型名称>               # 删除模型
ollama ps                           # 当前服务
# 环境变量：OLLAMA_MODEL_SERVER="https://mirror.ollama.com"（换镜像源）
# 服务地址：http://localhost:11434/

# 模型列表
curl http://localhost:11434/v1/models

# 聊天接口（非流式）
curl -X POST http://localhost:11434/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model": "qwen3-vl", "messages": [{"role": "user", "content": "你好，请介绍一下自己"}], "stream": false}'
兼容范围
Ollama 支持的是 OpenAI API 的子集：Chat completions / Streaming / JSON 模式 / Vision / Tools / 推理控制都在清单里，Logprobs 等不在。
图片输入
兼容清单中 Base64 encoded image 已支持、Image URL 未支持——本地传图必须走 Base64 data URL。
API Key
客户端仍然要求一个 key 值，但本地服务会忽略它（照官方示例写 api_key="ollama" 一类的占位值即可）。
模型名约定
依赖默认名（如 gpt-3.5-turbo）的工具，可用 ollama cp 把已有模型复制成一个临时名来对接。

_current_dir = os.path.dirname(os.path.abspath(__file__))
_env_file = os.path.abspath(os.path.join(_current_dir, "../.env"))
load_dotenv(_env_file)
OPENAI_API_KEY / OPENAI_BASE_URL / OPENAI_MODEL = os.environ.get(...)

# 客户端：不传参，SDK 自动从环境变量取 key 与 base_url
from openai import OpenAI
client = OpenAI()

# 模型列表
print(client.models.list().to_json())

# 基本对话
response = client.chat.completions.create(
    model=config.OPENAI_MODEL,
    messages=[{"role": "user", "content": "你是谁"}],
)

# 关闭思维链（协议外的扩展参数 → 走 extra_body 透传）
response = client.chat.completions.create(
    model=config.OPENAI_MODEL,
    messages=[{"role": "user", "content": "你是谁"}],
    extra_body={"thinking": {"type": "disabled"}},   # qwen3-vl 无法直接关闭思考模式
)
resp.json 字段含义 / 易错点
id / object / created / model / system_fingerprint这次响应的身份信息；object 为 chat.completion
choices[0].message.role通常是 assistant
choices[0].message.content正文——非流式取这一层
choices[0].message.reasoning思考过程，单独一个字段；只打印 content 会把推理整段丢掉
choices[0].finish_reason结束原因，正常结束为 stop
usage.prompt_tokens / completion_tokens / total_tokens$total\_tokens = prompt\_tokens + completion\_tokens$；思考文本也算生成量

流式响应：delta 与事件流

stream = client.chat.completions.create(
    model=config.OPENAI_MODEL,
    messages=[{"role": "system", "content": "少思考，简洁回答"},
              {"role": "user", "content": "从1数到10"}],
    stream=True,
)
for chunk in stream:
    print(chunk)
    sys.stdout.flush()          # 不 flush 看不到实时效果

# utils/stream_print.py
print_stream(stream)
读哪里
非流式读 choices[0].message.content；流式读 choices[0].delta.content。delta 里可能是 role 标记、一段 content，或流结束时的空对象。
推理字段兼容
先 getattr(delta, "reasoning_content", None)，取不到再退回 getattr(delta, "reasoning", None)——不同服务端/模型命名不统一。
空 choices 守卫
循环开头 if len(chunk.choices) == 0: continue：带用量的收尾帧 choices 为空数组，不跳过就会 IndexError。
事件序列
Chunk(type, content) 由 chunk_generator 产出：reasoning_start → reasoning… → reasoning_end → content_start → content… → 固定收尾 content_end。没有推理时 不会出现 content_start，渲染层不能假设它一定来。
拿用量
流式请求带 stream_options={"include_usage": True}：末尾额外一个 chunk 带整次请求的 usage，其余 chunk 的 usage 为 null，且这最后一帧的 choices 恒为空数组。
代价
流式让首字更早到达，但部分补全更难审核评估——生产环境要为此补一层内容策略。

视觉（多模态）输入

# utils/img_base64.py
to_base64(path)  -> base64.b64encode(open(path,"rb").read()).decode("utf-8")
to_dataurl(path) -> f"data:{mime};base64,{b64_data}"
# mime 按扩展名推断：.png / .jpg|.jpeg / .gif / .webp / 其它 → image/octet-stream

# 消息组装：content 从字符串换成数组
dataurl = to_dataurl("menu.png")
stream = client.chat.completions.create(
    model=config.OPENAI_MODEL,
    messages=[{
        "role": "user",
        "content": [
            {"type": "text", "text": "请描述这张图片的内容"},
            {"type": "image_url", "image_url": {"url": dataurl}},
        ],
    }],
    stream=True,
)
print_stream(stream)
易错点说明
传本地路径模型看不到你的磁盘，路径字符串没有意义——必须转 Base64/data URL。
传公网 URL 给本地服务Ollama 兼容清单里 Image URL 未勾选，本地场景请统一走 Base64。
忘了 content 用数组文本与图片是同一条 user 消息里的两个 part（type 为 text / image_url）。
体积与 tokenBase64 约放大到 4/3（字符数 $4 \times \lceil n/3 \rceil$），大图先压缩再传。
关思考的差异extra_body 里的扩展参数是服务端特定的，换模型/换后端可能直接失效。
