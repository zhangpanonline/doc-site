tools速查表

配合《tools互动教学课程》使用。

Tool Calling：分工与闭环

一句话：模型只会「文本进、文本出」，它输出的是调用意图，执行函数是你的代码的责任。

步骤谁在做产出 / 动作
① 绑定工具你的代码session.tools = [...]，随请求发出去（厂商拼到系统上下文末尾）
② 调用模型模型返回 tool_calls：id + function.name + function.arguments（JSON 字符串），finish_reason 为 tool_calls
③ 执行函数你的代码json.loads(arguments) → 查表拿函数 → func(**arguments)，执行前校验参数
④ 回填结果你的代码{"role": "tool", "tool_call_id": <id>, "content": ...}，紧跟带 tool_calls 的 assistant 消息
⑤ 再问一次模型基于工具结果生成自然语言回答
# 本章闭环（课件《18.tools》）
import json
tc = session.messages[-1]["tool_calls"][0]
tool_id   = tc["id"]
tool_name = tc["function"]["name"]
arguments = json.loads(tc["function"]["arguments"])
func = {"read_file": read_file, "write_file": write_file}.get(tool_name)  # 课件用 globals().get()
if callable(func):
    result = func(**arguments)
session.add_message({"role": "tool", "tool_call_id": tool_id, "content": str(result)})

工具描述（schema）速查

字段取值作用
type固定 "function"目前各厂商只支持 function 这一种工具类型
function.name函数名（唯一）会影响模型输出结果；官方限 a-z / A-Z / 0-9 / 下划线 / 连字符，≤128 字符
function.description自然语言供模型理解「何时以及如何调用」，是选型准确率的第一抓手
function.parametersJSON Schema顶层 "type": "object" 固定；properties 逐项写 type + description；required 列必填参数
function.stricttrue / falseBeta：强制输出严格符合 JSON Schema（需 base_url=.../beta，且每个 function 都要开）
tool_choicenone / auto / required / {type,function:{name}}控制调用行为；无 tool 默认 none，有 tool 默认 auto；思考模式不支持 required 与指定工具（返回 400）
# 本章两个工具的 schema 骨架
session.tools = [
    {"type": "function",
     "function": {
         "name": "read_file",
         "description": "读取文件",
         "parameters": {
             "type": "object",
             "properties": {"filepath": {"type": "string",
                                         "description": "文件的绝对路径，或相对于cwd的路径"}},
             "required": ["filepath"]}}},
    {"type": "function",
     "function": {
         "name": "write_file",
         "description": "写入文件",
         "parameters": {
             "type": "object",
             "properties": {"filepath": {"type": "string", "description": "文件的绝对路径，或相对于cwd的路径"},
                            "content":  {"type": "string", "description": "要写入的内容，该内容会完全覆盖文件原本内容"}},
             "required": ["filepath", "content"]}}},
]

成本提醒：工具定义每轮都随请求重发，输入 token 大致为 $T_{\text{prompt}} = T_{\text{sys}} + \sum_{i} T_{\text{tool}_i} + \sum_{j} T_{\text{msg}_j}$——工具越多，每轮越贵。

事件流：三个构建器怎么拼消息

事件常量（agent/events.py）由谁发出说明
REASONING_START / REASONING / REASONING_ENDReasoningBuilder字段名用 _get_reasoning_field_name 兼容 reasoning_content / reasoning
CONTENT_START / CONTENT / CONTENT_ENDContentBuilder正文增量，逐块累加
TOOL_CALL_START / TOOL_CALL / TOOL_CALL_ENDToolCallsBuilder按 index 归位、arguments 分片 +=，最后 _normalize_tool_calls 拍成纯字典
COMPLETE—整轮完成的收尾事件
# 事件总线（发布订阅）
class EventEmitter:                       # @dataclass
    _listeners: dict[str, list[Callable]]  # default_factory=lambda: defaultdict(list)
    def on(self, event, callback): self._listeners[event].append(callback)
    def emit(self, event, **data):
        for cb in self._listeners.get(event, []): cb(event, **data)

# Builder 骨架：首块发 START → 后续 append_value → is_end 发 END 并置 compoleted = True
# 流式响应承载增量的字段是 delta（不是 message）；结束块的 delta 可能是空对象
# ReasoningBuilder.is_end: bool(delta.content) or bool(delta.tool_calls) or super().is_end(chunk)
#    → 模型「先思考、再直接发起工具调用」时没有正文，只看 finish_reason 会让思考段拖到最后
Model
@dataclass class Model(EventEmitter)；invoke() 走非流式，invoke_stream() 走流式；流式下三个 Builder 依次 emit(chunk)，再把各 Builder 的 value 合成 {"role": "assistant", "content": ""} 起始的消息并写入会话。
ModelPrinterListener
遍历 Event.__dict__ 里的事件名逐个 model.on(...) 订阅；listening = False 可一键静音流式打印。
Session.tools
本章给 Session 加了 tools 字段（默认 []），__str__ 里连同 messages 一起序列化，方便 session.print() 查看上下文。

易错点

忘记 json.loads
arguments 是模型生成的 JSON 字符串；直接 func(**arguments) 报 TypeError: argument after ** must be a mapping。
把模型参数当可信输入
官方提醒：模型并不总是生成有效的 JSON，还可能臆造 schema 未定义的参数——调用前必须校验；strict 模式可从源头约束。
用 globals().get 裸派发
名字对不上时静默不执行；被提示注入还可能命中意外符号。工程做法是显式注册表白名单派发（下一章《19.封装tools》）。
角色与位置写错
工具结果必须用 role: "tool" + tool_call_id，并紧跟在带 tool_calls 的那条 assistant 消息之后；不能用 user 消息代替。Chat Completion 接口不支持在对话中间插入工具调用消息。
描述含糊导致乱选
description 是模型选型的依据。两个工具都写「文件操作」，模型就会在只读场景调写入工具。写清用途、边界与后果。
tool_choice 滥用
思考模式下不支持 required 与指定具体工具（返回 400）；没有 tools 时也不用传。
流式拼接不按 index
并行工具调用的增量会交错到达；不按 index 归位就把两次调用的 arguments 拼成一段，json.loads 必炸。
