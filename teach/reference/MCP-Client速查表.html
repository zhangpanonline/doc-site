两种传输对照

stdioStreamable HTTP
服务器在哪客户端作为子进程启动（uvx …）独立进程 / 远端，客户端连一个 MCP endpoint URL
配置字段{"type": "stdio", "command": "uvx", "args": ["mcp-server-time"]}{"type": "http", "url": "https://learn.microsoft.com/api/mcp"}
连接对象StdioServerParameters(command=…, args=[…])URL 字符串
解包形状stdio_client(params) as (read, write) —— 二元组streamable_http_client(url) as (read_stream, write_stream, _) —— 三元组
关掉时关服务器输入流 → 等它退出（必要时 SIGTERM / SIGKILL）关闭关联的 HTTP 连接

两种传输拿到 read / write 之后的写法完全一样：ClientSession(read, write) → initialize()。差别全被 connect_mcp 吃掉。

本章验证对象：uvx mcp-server-time（get_current_time、convert_time）· https://learn.microsoft.com/api/mcp（microsoft_docs_search、microsoft_code_sample_search、microsoft_docs_fetch）。

@asynccontextmanager
async def connect_mcp(server_config: dict):
    """按 type 连接并 initialize，yield 已就绪的 ClientSession"""
    if server_config["type"] == "stdio":
        params = StdioServerParameters(command=server_config["command"],
                                       args=server_config.get("args", []))
        async with stdio_client(params) as (read, write):
            async with ClientSession(read, write) as session:
                await session.initialize()
                yield session
    elif server_config["type"] == "http":
        async with streamable_http_client(server_config["url"]) as (read, write, _):
            async with ClientSession(read, write) as session:
                await session.initialize()
                yield session
    else:
        raise ValueError(f"不支持的服务器类型: {server_config['type']}")

class MCPClient:
    def __init__(self, config):        self.servers = config["servers"]
    async def alist_tools(self):       # 遍历所有服务器 → [{"server", "tools"}]
    async def acall_tool(self, server_name, tool_name, arguments=None)
    def list_tools(self):              return run_async(self.alist_tools())
    def call_tool(self, server_name, tool_name, arguments=None)
                                       #  return run_async(self.acall_tool(...))
第一层 connect_mcp
@asynccontextmanager + yield session：把「必须最先发生的 initialize()」封在 yield 之前，调用方拿到的 session 天然已就绪。
第二层 单服务器函数
list_server_tools(config) / call_server_tool(config, name, args)：async with connect_mcp(config) as session: 一行进上下文。
第三层 MCPClient
吃整份配置；alist_tools() 遍历全部服务器（N 个服务器 = N 次连接），acall_tool() 只按名字连一个。

同步封装 run_async 与易错点

import threading

def run_async(coro):
    """在独立线程中运行异步协程，同步等待并返回结果"""
    result = None
    error = None

    def _run():
        nonlocal result, error
        try:
            result = asyncio.run(coro)
        except Exception as e:
            error = e

    t = threading.Thread(target=_run)
    t.start()
    t.join()          # 串行等待：没有并发，也不支持取消 / 超时

    if error:
        raise error
    return result
易错点现象 / 正确做法
HTTP 抄成两元组streamable_http_client 解出三个值，必须写 as (read_stream, write_stream, _)
漏写 type 或不支持的类型命中 else: raise ValueError，且会打断 alist_tools() 的整轮遍历
直接 asyncio.runJupyter 自身有事件循环，同线程内调用会报错——所以课件改用独立线程（每个线程一个事件循环）
在异步 Agent 里套同步皮工具链路里已经有事件循环，直接 await；run_async 是兼容层，不是并发层
漏传必填参数如 get_current_time 的 timezone：返回 isError: true + Input validation error，不抛异常
工具名写错两种可能：协议错误（JSON-RPC error，如 Unknown tool: …）或工具执行错误（isError: true，错误文本在 content 里）——都要检查，别当正常结果
列表缓存当永久真相tools/list 分页；服务器可发 notifications/tools/list_changed，需重取或设 TTL
每次调用都重连acall_tool 每次都会重新连接 + initialize()（stdio 还要重启子进程）；高频场景要评估长连接复用

健壮性底线（官方规范建议）：为所有发出的请求设置超时，否则 t.join() 会无限期阻塞主线程。
