一句话：Tool 管「一个函数 ↔ 一份 Schema」，_ToolRegistry 管「工具 ↔ session ↔ tool_calls」。

Pydantic 速查（校验与 Schema 一次定义、两处复用）

uv add pydantic==2.13.4

class Counter(BaseModel):
    n: int = Field(description="计数值", default=0)

Counter()                    # 自动适配默认值 → n=0
Counter(n="123")             # 自动转换类型 → n=123（int，不是字符串）
Counter(n=[1,2,3])           # 无法转换 → ValidationError
Counter().model_dump()       # {'n': 0} —— 喂给原函数
Counter.model_json_schema()  # {'properties': {'n': {...}}, 'title': 'Counter', 'type': 'object'}

# 从函数签名动态生成参数模型
def create_params_model(func, param_descriptions={}):
    model_name = f"{func.__name__}_params"
    args = {}
    for pname, param in inspect.signature(func).parameters.items():
        py_type = param.annotation if param.annotation is not param.empty else Any
        desc = param_descriptions.get(pname, "")
        if param.default is param.empty:            # 必填：不设默认值
            args[pname] = (py_type, Field(description=desc))
        else:                                       # 可选：带上默认值
            args[pname] = (py_type, Field(default=param.default, description=desc))
    return create_model(model_name, **args)
「校验」的真实含义
Pydantic 保证的是输出的类型与约束，不是输入数据；默认宽松转换（"123" → 123），只有「转换不了」才报 ValidationError。
必填 / 可选的分界
param.default is param.empty → 进 required；有默认值 → 不进。有默认值的参数绝不能写成 Field(description=…)，否则模型必须每次显式编值。
无类型标注的参数
退回 Any，其 Schema 里没有 type 键，最终在 Tool.schema() 中回落到 "string"。
模型名
固定为 f"{func.__name__}_params"，方便在报错信息里认领是哪个工具的参数炸了。

Tool 类 / 装饰器 / 调度中心

class Tool:
    def __init__(self, func, param_descriptions={}):
        self.func = func
        self.name = func.__name__                      # 名字来自函数
        self.description = inspect.getdoc(func) or ""  # 描述来自 docstring
        self.param_descriptions = param_descriptions or {}
        self.param_model = create_params_model(func, param_descriptions)

    def schema(self) -> dict:      # {"type": "function", "function": {name, description, parameters}}
    def __call__(self, **kwargs):  # 校验 → 执行 → str(结果)；异常 → traceback 堆栈字符串

def tool(**args):
    def decorator(func):
        return Tool(func, param_descriptions=args)
    return decorator

class _ToolRegistry:
    def register(self, tool): self._tools[tool.name] = tool
    def schemas(self): return [t.schema() for t in self._tools.values()]
    def invoke(self, message):   # 无 tool_calls → None；否则逐条执行 → list[dict]
点要记住的行为
schema() 的 parameters遍历 model_json_schema()["properties"]，只保留 type 与 description（prop.get("type","string")）；required 直接沿用参数模型的 required
__call__ 的返回值永远是字符串（str(self.func(...))）；失败时是完整堆栈字符串，不抛异常——让模型自己看堆栈纠错
invoke() 的返回形状list[dict] | None：每项 {"role": "tool", "tool_call_id", "name", "content"}，靠 tool_call_id 与请求配对；None 表示本次无须调用工具
@tool 的代价被装饰的名字变成 Tool 实例，不再是函数——别指望后续还能对它做 inspect.signature() 反射
@tool 的位置工具本身是普通模块级函数，装饰器直接压在 def 上即可；不要和 @staticmethod 之类描述符混着叠，顺序会悄悄改变拿到手的东西

易错点清单

  • KeyError 抢在判空之前：tool = self._tools[name] 对不存在的工具名直接抛 KeyError，后面 if not tool: 的「无此工具」提示是死代码；应改用 self._tools.get(name)，把幻觉出来的工具名变成一条可回灌的观察结果。
  • 忘注册：工具写好了但没在 agent/tool/__init__.py 里 registry.register(...)，Schema 里就没有它 → 模型永远不会调用。排查第一步永远先 registry.schemas()。
  • 默认值漏写：可选参数没走 Field(default=param.default, ...)，于是进了 required，模型每次都被迫编一个值。
  • 对普通聊天轮漏判空：session.messages += call_msg 在 call_msg is None 时等于 list.extend(None) → TypeError。要么保留 None 语义 + 调用方 if call_msg:，要么让 invoke 统一返回空列表。
  • 把类型转换当校验："50" → 50 会被静默接受；要真拦截得开严格模式或在 Field 上加约束。
  • prompt 里的描述 ≠ 参数名：param_descriptions 只改描述文本，改不了参数名；模型按 Schema 里的名字回传，对不上就会收到 Field required [type=missing]。
