表间关系速查表

配合《表间关系互动教学课程》与《03.表间关系》使用。建议打印一份放在手边。

三种关系与实现

关系实现方式典型例子
1:1任意一方外键 + UNIQUE用户 ↔ 用户详情
1:N（最常见）「多」的一方放外键，不加 UNIQUE部门 ↔ 员工
M:N中间表：双外键组成联合主键，可加关系属性学生 ↔ 课程（+成绩）

外键约束行为

选项父表被删/改时备注
NO ACTION有子记录则禁止PG 默认；支持延迟检查
RESTRICT有子记录则禁止不支持延迟检查
CASCADE子表自动跟随（级联删/改）方便但误删风险大
SET NULL子表外键置 NULL外键列必须允许 NULL

ERD 符号

矩形 = 实体（表）        连线 = 关系
||--||    一对一
||--o{    一对多
}o--o{    多对多（中间表实现）
PK 主键  FK 外键  UK 唯一键

外键优缺点

优点缺点
保证数据完整性，防止脏数据降低写入性能（每次写入要检查）
关系清晰、语义明确分库分表、分布式场景难用
数据库层面自动约束级联操作难以追踪

⚠️ 大厂实践：高并发/分库分表/微服务 → 应用层保证完整性（应用层校验 + 事务 + 对账巡检 + 逻辑外键）；ERP/财务等单体强一致场景 → 保留外键。

核心要点

  • 判断口诀：「一个 A 对应几个 B？一个 B 对应几个 A？」两个都 1 → 1:1；一边多 → 1:N；都多 → M:N
  • 1:N 外键放「多」边，1:1 才加 UNIQUE
  • M:N 必经中间表，联合主键 + 关系属性
  • PG 默认 NO ACTION，与 RESTRICT 现阶段视为等同
  • CASCADE 慎用：误删父表连带清子表
