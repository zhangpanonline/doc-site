异常处理速查表

配合《异常处理互动教学课程》与《14.异常处理》使用。建议打印一份放在手边。

try 四件套

子句触发时机典型用途
try—监控的代码块
except X as e捕获匹配异常（顺序匹配）按类型处理错误
else无异常时与 try 成功绑定的事务逻辑
finally无论有无异常释放资源、关闭文件

异常层次（节选）

BaseException
 ├── SystemExit / KeyboardInterrupt   ← 一般不要捕获
 └── Exception                        ← 业务异常的基类
      ├── ArithmeticError ─ ZeroDivisionError
      ├── LookupError ─ IndexError / KeyError
      ├── TypeError
      ├── ValueError ─ UnicodeError
      └── 自定义：class MyError(Exception)

捕获顺序：先具体（子类）后宽泛（父类）。

常用模板

# 安全除法
def safe_divide(a, b):
    try:
        return a / b
    except ZeroDivisionError:
        return 0
    except TypeError:
        print("参数类型错误")
        return None

# 重试装饰器
def retry(max_attempts, delay=1):
    def decorator(func):
        def wrapper(*args, **kwargs):
            for attempt in range(1, max_attempts + 1):
                try:
                    return func(*args, **kwargs)
                except Exception as e:
                    if attempt == max_attempts:
                        raise
                    time.sleep(delay)
        return wrapper
    return decorator

# 异常链
raise RuntimeError("错误B")          # 隐式：__context__ = 原异常
raise RuntimeError("错误B") from e   # 显式：__cause__ = e

常见误区

  • 父类 except 放在前面会「吞掉」子类异常：后面的 except 永远不执行。
  • 不要捕获 BaseException：会把 Ctrl+C（KeyboardInterrupt）一起吞掉。
  • except 里裸 raise 是重新抛出：不是抛出 RuntimeError。
  • 自定义异常要继承 Exception：调用方才可能用 except 你的异常 精确捕获。
  • finally 里的 return 会覆盖之前的返回值：清理逻辑不要 return。
