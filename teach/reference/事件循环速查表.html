事件循环速查表

配合《事件循环互动教学课程》与《24.事件循环》使用。建议打印一份放在手边。

术语表

事件循环
AbstractEventLoop 类的对象，负责调度所有回调；异步的基础手段。
ready 队列
存放「就绪待执行」回调的队列，_run_once 每轮执行它的副本。
延时队列
存放「定时」回调的队列，回调到期后才进入 ready 队列。
call_soon
loop.call_soon(f)：把 f 放入 ready 队列，尽早调度。
call_later
loop.call_later(delay, f)：把 f 放入延时队列，delay 秒后进 ready。
run_forever
反复执行 _run_once 直到 stop()；没有 stop 就永不返回。
_run_once
调度一轮：处理延时队列 → 计算 timeout → 等待 I/O → 复制并执行 ready。
异步
单线程上让任务不阻塞线程的编程模式；适合 I/O 密集任务。

语法速查

创建、绑定、运行、停止

import asyncio

loop = asyncio.new_event_loop()   # 创建事件循环对象
asyncio.set_event_loop(loop)      # 绑定到当前线程
loop.run_forever()                # 陷入循环，直到 stop() 被调用
loop.stop()                       # 停止事件循环

调度回调

loop.call_soon(f)                 # f 进入 ready 队列，尽早执行
loop.call_later(1, f)             # f 进入延时队列，1 秒后进 ready
loop.call_later(0, f)             # 延时 0 秒：先入延时队列，下一轮 _run_once 开始才进 ready

_run_once 五步骤

  1. 检查延时队列，到期的回调加入 ready 队列
  2. 计算 timeout：ready 非空 → 0；延时队列非空 → 队首时间 − 当前时间；都空 → None
  3. 用 timeout 阻塞等待 I/O；期间 I/O 任务到达立刻进 ready；超时则回到第 1 步
  4. 复制 ready 队列，得到本轮回调清单
  5. 执行复制的队列（保证清单内全部执行）

⚠️ 执行的是副本：执行期间新注册的回调（call_soon / call_later 到期）要等下一轮。

预测输出三步法

  1. 同步代码先行：print 等同步语句按书写顺序立即输出
  2. 推演每轮 _run_once：延时队列到期的先进 ready，再复制执行
  3. 检查有没有 stop()：没有 → 死循环，后续代码永不执行

场景对比

维度同步异步（事件循环）多线程
阻塞行为一个任务阻塞，全部干等任务登记回调后让出线程阻塞在线程内，互不干扰
并发载体无并发单线程 + 回调队列多线程，操作系统调度
适用场景简单顺序逻辑海量 I/O 密集（爬虫、Web）运算密集 / 实时性高的 I/O
资源开销最低极低，单线程即可高，每线程栈空间数 MB
