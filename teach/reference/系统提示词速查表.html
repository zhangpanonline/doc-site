系统提示词速查表

配合《系统提示词互动教学课程》使用。

它是什么，为什么在「最前面」

位置
往往出现在所有消息的最前面；模型在训练过程中会重点关注系统提示词。
作用域
它不在某一轮对话里，而是作用于整条对话的每一轮——写坏了不会报错，只会让行为慢慢跑偏。
载体（本章工程）
agent/message.py 用 @dataclass 定义 Message 基类，SystemMessage / UserMessage / AssistantMessage 三个子类分别承载角色。
最小示例
SystemMessage("当用户向你打招呼时，你仅需回答你好即可") + UserMessage("你好")——第一条消息就把行为定死。

五条核心原则（正反对照）

原则管什么反例 → 修法
精简说多少「你现在要充当一名专业代码顾问……希望你认真仔细地阅读……」→「你是代码顾问。精准解答编程问题，不懂直接说明，禁止编造信息。」
自洽别打架「回答务必详尽，多角度展开；同时所有回复控制在 30 字以内」→ 删掉互相矛盾的规则
全局约束放对地方「当用户要求写数据分析类代码时，应使用 Python」是局部规则，不该放系统提示词
保持静态别乱动「当前用户是：<动态内容>，时间是：<动态内容>」→ 动态内容走消息，系统提示词保持固定
结构化怎么排版用 Markdown / XML 分层，把核心指令、硬性约束、输出规范用标记隔离

记忆抓手：精简管说多少 · 自洽管别打架 · 全局约束管放对地方 · 保持静态管别乱动 · 结构化管怎么排版。

从 .j2 模板到系统提示词

1) 收集环境信息
   get_cwd()      → os.getcwd()
   get_is_git()   → git rev-parse --is-inside-work-tree（返回码 0 且输出 true 才算在仓库里）
   get_platform() → 平台信息

2) 交给 Jinja2 渲染
   env = Environment(loader=FileSystemLoader(template_dir))
   template = env.get_template("system.j2")
   text = template.render(...)

3) 封装通用入口
   render_prompt(prompt_name)
     template_dir = os.path.dirname(__file__) / "prompt"
     取 f"{prompt_name}.j2" 并渲染

4) 模板结构（system.j2）
   # System / # Doing tasks / # Using your tools / # Tone and style / # Language

本章 agent/ 新增 7 个文件：__init__.py、config.py、message.py、model.py、printer.py、prompt.py、prompt/system.j2；依赖：uv add jinja2==3.1.6、uv add pydantic-settings==2.14.1。

两类静默故障（不报错但结果错）

故障现象修法
变量名写错Jinja2 默认把未定义变量渲染成空字符串 → 模板里少了一段，模型照常回答开启 StrictUndefined，或渲染后断言关键片段存在
块标签留空行{% for %} / {% if %} 控制行会留下多余空行，长提示词被撑大用 {%- ... -%} 控制空白，或渲染后统一压缩连续空行
  • 把动态内容（用户、时间、cwd）写进系统提示词 → 破坏缓存命中、也让行为随环境漂移
  • 系统提示词里塞局部规则 → 模型在其它场景也照做
  • 以为「模型没照做」一定是指令不够强——先检查模板渲染后到底长什么样
