知识速览

先花几分钟把核心机制过一遍——细节都在《02.DDL》里，测验和考核会考。

SQL 四分类

CREATE / ALTER / DROP / TRUNCATE ─ 操作结构 ─▶ DDL 数据定义
INSERT / SELECT / UPDATE / DELETE ─ 操作数据 ─▶ DML 数据操作
GRANT / REVOKE · BEGIN / COMMIT / ROLLBACK ─ 权限 / 事务 ─▶ DCL / TCL

⚙️ 学习顺序 DDL → DML：先有结构，才能装数据。

类型与约束要点

  1. 精确 vs 不精确：NUMERIC(m,n) 定点精确（金额用它）；REAL / DOUBLE PRECISION 浮点不精确（科学计算用）。
  2. SERIAL = INTEGER + 自动序列：自增主键的懒人写法，BIGSERIAL 对应 BIGINT。
  3. 字符串三兄弟：VARCHAR(n) 变长有上限、CHAR(n) 定长不足补空格、TEXT 不限长。
  4. PRIMARY KEY = NOT NULL + UNIQUE：主键自带非空与唯一，无需重复声明。
  5. JSON vs JSONB：JSONB 是二进制存储，支持索引、查询更快——能选 JSONB 就不选 JSON。

DELETE / TRUNCATE / DROP 一句话对比

DELETE    删「行」——慢、逐行、可带 WHERE、可回滚、结构在
TRUNCATE  清「数据」——快、整表、不可带 WHERE、PG 中可回滚、结构在
DROP      删「表」——最快、连结构带数据一起删、不可回滚

⚠️ PostgreSQL 特有：TRUNCATE 在 PG 里支持事务回滚（与 MySQL 不同）；DELETE 在 PG 的 MVCC 下只是把行标记为 dead tuple，空间要等 VACUUM 回收，大量 DELETE 后表会膨胀。

分级测验

三道一组，先做后点——点击选项立刻出对错与解释。

🌱 初级 · 概念

1. DDL 操作的对象是？
DDL = Data Definition Language，操作结构：CREATE/ALTER/DROP/TRUNCATE 针对数据库、表、列、约束。行数据归 DML，权限归 DCL，事务归 TCL。
2. id SERIAL PRIMARY KEY 中 SERIAL 是什么？
SERIAL 不是真类型，是 INTEGER + 自动序列 的组合：插入时不给值就自动取序列的下一个数。对应大整数用 BIGSERIAL。
3. PRIMARY KEY 自带哪两个特性？
主键 = 唯一标识一行：值不能重复（唯一性）、不能为 NULL（非空）。声明 PRIMARY KEY 就自带这两个约束，还能用多列组合成复合主键。

🌿 中级 · 应用

4. price NUMERIC(10,2) 的含义是？
NUMERIC(m, n)：m = 总位数（含小数），n = 小数位数。NUMERIC(10,2) 最多 10 位、2 位小数，且是定点精确存储——金额字段的标准选择。
5. 想把 score NUMERIC(5,2) 改成 INTEGER，但现有数据无法隐式转换，正确做法是？
USING 子句给数据库显式转换规则：score::INTEGER 把每个值强转成整数。没有 USING 时数据库只尝试隐式转换，失败即报错。
6. 存「商品信息 JSON 字段」，并且以后要按字段内容查询，选哪种类型？
JSONB 是二进制 JSON：解析好再存储、支持 GIN 索引、按字段查询高效——代价是写入稍慢、不保留原始格式。JSON 只是原样文本存储，查询要每次解析。TEXT/VARCHAR 则完全失去结构化查询能力。

🎯 高级 · 综合

7. 在 PostgreSQL 中，BEGIN 事务里执行 TRUNCATE 再 ROLLBACK，数据会？
这是 PG 与 MySQL 的重要差异：PostgreSQL 中 TRUNCATE 支持事务回滚（课件对比表专门标注了「是（PostgreSQL 中支持事务回滚）」）。DROP 则不可回滚。面试若遇到通用答案「TRUNCATE 不可回滚」，要区分数据库。
8. DROP TABLE students CASCADE; 与不带 CASCADE 的区别是？
CASCADE = 级联：把依赖这张表的对象（视图、外键约束等）一并删除。不带 CASCADE 时，若存在依赖对象，PG 会拒绝删除并报错。
9. code CHAR(3) 存字符串 "AB" 后，读出来是什么？
CHAR(n) 是定长：不足 n 字符补空格（比较时 PG 会忽略尾部空格）。VARCHAR(n) 是变长，存多长占多长。定长换取存取速度、浪费空间——「空间换时间」。

最终考核

下面是《02.DDL》源课程作业「让 AI 帮你生成 SQL 完成建库建表 + 导出恢复」的四道改编题——这就是本课的最终考核。规则：不查资料，先在脑中写出语句，再点击核对。全部答对且能讲清理由，才算过关。

考核一：为「学生表」选建表语句——需求：姓名、年龄、性别（作业原题）。哪条最合适？
要点：自增主键 SERIAL PRIMARY KEY；姓名用 VARCHAR(50) NOT NULL；年龄是整数，加 CHECK 防负数；性别短字符串 VARCHAR(10)。其他项的错误：age TEXT 类型错、age NUMERIC 类型错、gender BOOLEAN 语义错。
考核二：为「课程表」选建表语句——需求：课程名称、课程描述、授课老师（作业原题）。哪条最合适？
课程名 VARCHAR(100) 且 NOT NULL；课程描述长文本用 TEXT（第二项里 description TEXT 正确）；老师 VARCHAR(50)。陷阱项：name CHAR(3) 放不下课程名；description VARCHAR(10) 更放不下描述；teacher SERIAL 把老师当自增数。
考核三：作业第 4 步「导出 courses_db 为 SQL，只要干干净净的建表语句」，应该用什么？
pg_dump -s（= --schema-only）只导出表结构定义（CREATE TABLE 语句），不含数据——正是「干干净净的建表语句」。不带 -s 的全量导出会把数据也打成 INSERT。pg_dump 是 PG 官方备份工具（官方文档）。
考核四：作业第 5 步「删除并重建干净的数据库，再用导出的 SQL 恢复」，正确顺序是？
干净恢复 = 删库 → 建库 → 执行结构 SQL → 验证。注意两点：DROP DATABASE 会连数据一起销毁（这正是「干净」的目的）；导出的 SQL 只含 CREATE TABLE，执行它就把表结构原样重建出来。
