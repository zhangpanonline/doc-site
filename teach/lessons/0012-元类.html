元类

本课目标

完成本课后，你将能：

  1. 说清 class 语句是语法糖：底层就是 type("Dog", (), {})
  2. 写出自定义元类：class MyMeta(type) + 重写 __new__(mcs, name, bases, namespace)
  3. 用元类实现单例、自动注册、方法日志——最终考核的三道实现题

知识速览

先花几分钟把核心机制过一遍——细节都在《12.元类》里，测验和考核会考。

两条时间线

创建类：class Dog(metaclass=MyMeta) → type.__call__(MyMeta, ...) → MyMeta.__new__ → 得到 Dog 类
创建实例：Dog() → MyMeta.__call__(Dog) → Dog.__new__ → 得到实例

⚙️ 关键区分：__new__ 只在「创建类」时执行一次；__call__ 只在「实例化」时执行——单例元类改的是 __call__。

三个要点

  1. 元类 __new__ 的四个参数：mcs（元类自己）、name（类名）、bases（父类元组）、namespace（类体字典）；必须 return super().__new__(mcs, name, bases, namespace)，否则类创建失败。官方文档：Metaclasses
  2. 元类 __call__ 拦截实例化：Dog() 走 type(Dog).__call__(Dog)——在元类 __call__ 里缓存实例，就是「元类版单例」。
  3. 子类自动继承元类：class Child(Base) 且 Base 的元类是 MyMeta，Child 也用 MyMeta——自动注册插件的机制正基于此。官方文档：Determining the appropriate metaclass

分级测验

点击选项立即获得反馈。答错也没关系——仔细读解释，它会把文档里对应的小节指给你。三级难度：初级考概念，中级考应用，高级考综合与陷阱。

🌱 初级测验 · 概念

1. class Dog: pass 的等价写法是？
class 语句是语法糖：收集类体命名空间后，底层调用 type(类名, 父类元组, 属性字典) 创建类。详见「类的创建过程」一节。
2. 元类（metaclass）是什么？
元类是「创建类的类」：type(Dog) → type，默认元类就是 type。继承 type 可以自定义元类。详见「元类」与第 7 课「类型与元类」。
3. 元类 __new__ 中，下面哪一步是必须的？
真正创建类对象的是 type.__new__，自定义元类只是包装层——必须 return super().__new__(mcs, ...)，否则类创建失败（返回 None）。详见「自定义元类」一节。

🌿 中级测验 · 应用

4. class Child(Base)，Base 的元类是 MyMeta，Child 的元类是？
子类自动继承父类的元类：type(Child) → MyMeta。Plugin 插件的自动注册正是利用这一点：所有继承 Plugin 的类都会走 PluginMeta.__new__。详见「深入：元类的查找顺序」一节。
5. 两个父类元类不同导致冲突（TypeError），如何解决？
元类冲突的解法：定义 class CommonMeta(MetaA, MetaB) 同时继承两个元类，再用 metaclass=CommonMeta 创建子类。详见「深入：元类的查找顺序」一节。
6. 想用元类实现「单例」（拦截实例化），应该重写？
实例化 Dog() 走 元类.__call__——单例要拦截的是「每次实例化」，所以重写 __call__ 缓存实例。元类的 __new__ 只在创建类时执行一次，拦不住实例化。详见「两条时间线」图。

🎯 高级测验 · 综合

7. 执行 class Dog(metaclass=DogMeta) 创建类时，DogMeta.__call__ 会被调用吗？
创建类时，DogMeta 的类型是 type，入口是 type.__call__，其内部转调 DogMeta.__new__——DogMeta.__call__ 此时不参与。等到 Dog() 实例化时，type(Dog) = DogMeta，DogMeta.__call__ 才出场。详见文档「深入：DogMeta 调用协议拆解」。
8. 自动注册插件：希望「定义子类」时就注册（不要求实例化），注册代码应该放在元类的哪里？
定义子类触发的是元类 __new__（创建类），所以注册必须在 __new__ 里、super().__new__ 之后（拿到新类再注册）。放 __call__ 里则必须实例化才注册 ✗。详见「两条时间线」图。
9. 单例元类里，实例缓存 cls._instance 应该存成什么结构，才能支持多个不同的类各自单例？
元类是所有用它的类共享的：_instance = {} 按 cls 作键缓存，Database 与 Player 才能各自单例（源答案 p1.py 正是 cls not in cls._instance）。单变量会让所有类共享同一个实例 ✗。

最终考核

下面是《12.元类》源课程作业的三道实现题改编——这就是本课的最终考核。规则：不查资料、不运行代码，先在心里选出正确实现，再点击核对。

考核一（作业一·单例元类）：用元类实现单例——Database("localhost") 与 Database("remote") 返回同一实例（is 为 True，host 保持 localhost）。下列实现中正确的是？
实例化走 元类.__call__，所以单例要重写 __call__：用 cls not in cls._instance 判断，未缓存时 super().__call__(*args, **kwds) 创建并缓存，最后统一返回缓存实例。第二个改的是 __new__——它只在「创建类」时执行一次，拦不住实例化 ✗；第三个不缓存 ✗；第四个第一次调用就崩 ✗。
查看源课程参考答案（作业一） 
class SingletonMeta(type):
    _instance = {}

    def __call__(cls, *args, **kwds):
        if cls not in cls._instance:
            ins = super().__call__(*args, **kwds)
            cls._instance[cls] = ins
        return cls._instance[cls]

class Database(metaclass=SingletonMeta):
    def __init__(self, host):
        self.host = host

db1 = Database("localhost")
db2 = Database("remote")
print(db1 is db2)   # True
print(db1.host)     # localhost
考核二（作业二·自动注册）：用元类把 Plugin 的所有子类自动注册进 PluginMeta.registry（键为类名）。下列实现中正确的是？
正确答案：在 __new__ 里先 cls = super().__new__(mcs, name, bases, namespace)，再 if name != "Plugin": mcs.registry[name] = cls，最后 return cls。这样定义子类（不实例化）就会触发注册。第二个把 Plugin 基类也注册了 ✗；第三个要求实例化才注册 ✗；第四个条件错误，什么都注册不上 ✗。
查看源课程参考答案（作业二） 
class PluginMeta(type):
    registry = {}

    def __new__(mcs, name, bases, namespace):
        cls = super().__new__(mcs, name, bases, namespace)
        if name != "Plugin":
            mcs.registry[name] = cls
        return cls

class Plugin(metaclass=PluginMeta):
    pass

class ImagePlugin(Plugin):
    pass

print(PluginMeta.registry)
# {'ImagePlugin': <class '__main__.ImagePlugin'>, ...}
考核三（作业三·方法日志）：用元类自动为类中每个非私有方法（不以 _ 开头）加日志——调用前打印 [LOG] 调用 方法名。下列实现中正确的是？
正确答案：在 __new__ 创建类之前遍历 namespace，对 not key.startswith("_") and callable(value) 的成员，用打印日志再调用原函数的 wrapper 替换 namespace[key]，然后才交给 super().__new__。第二个把 _ 开头（私有）方法也包裹 ✗；第三个方法被吞掉 ✗；第四个不替换就没有效果 ✗。
查看源课程参考答案（作业三） 
class LogMeta(type):
    def __new__(mcs, name, bases, namespace):
        for key, value in namespace.items():
            if not key.startswith("_") and callable(value):
                namespace[key] = mcs.log_wrapper(value)
        return super().__new__(mcs, name, bases, namespace)

    @staticmethod
    def log_wrapper(func):
        def wrapper(*args, **kwargs):
            print(f"[LOG] 调用 {func.__name__}")
            return func(*args, **kwargs)
        return wrapper

class Calculator(metaclass=LogMeta):
    def add(self, a, b):
        return a + b

calc = Calculator()
print(calc.add(3, 5))
# [LOG] 调用 add
# 8

创建类时，DogMeta 的类型是 type，入口是 type.__call__，其内部转调 DogMeta.__new__——DogMeta.__call__ 此时不参与。等到 Dog() 实例化时，type(Dog) = DogMeta，DogMeta.__call__ 才出场。详见文档「深入：DogMeta 调用协议拆解」。

⚡ 中级面试题

面试题一（元类概念·高频）：什么是元类？在什么场景下会用到？
元类是创建类的类（默认 type），class 语句底层就是调用元类创建类。应用场景：命名检查、自动注册、方法增强（日志）、ORM、单例——凡是「要在类创建时统一做手脚」的需求。面试建议顺带说出一个自己写过的真实例子。出处：博客园「史上最全 python 面试题详解（三）」
面试题二（单例元类·高频追问）：单例模式的「元类实现」核心思路是？
元类实现单例：在元类 __call__（实例化入口）里按 cls 缓存实例——cls not in cls._instance 时创建并缓存，之后直接返回缓存。相比 __new__ 方案，元类方案对「所有使用该元类的类」统一生效。出处：51CTO「你想要的 Python 面试题都在这里了」

🔥 高级面试题

面试题三（元类冲突·深水区）：A 的元类是 MetaA、B 的元类是 MetaB（互不继承），执行 class C(A, B): pass 会怎样？
两个父类元类不同且互不继承时，Python 无法确定 C 的元类 → TypeError: metaclass conflict（类定义时就报错）。解法：class CommonMeta(MetaA, MetaB): pass 创建兼容元类，再 class C(A, B, metaclass=CommonMeta)。出处：博客园「史上最全 python 面试题详解（三）」
面试题四（元类分工·机制）：元类的 __new__ 与 __init__ 的分工是？
与普通类同构：元类 __new__(mcs, name, bases, namespace) 创建类对象并 return（真正创建靠 super().__new__）；元类 __init__(cls, name, bases, namespace) 在类对象创建后做初始化（不返回值）。「类创建的完整生命周期」是元类深水区的基础。出处：博客园「史上最全 python 面试题详解（三）」

🧠 专家面试题

专家题一（元类应用·实现题）：用元类实现「方法名必须小写开头」的规范检查（违反时类定义报错），下列正确的是？
元类 __new__ 在类定义时执行——遍历 namespace 中 callable 成员的方法名，违规（如大写开头）直接 raise 即可在「写类的瞬间」拦截。第二个实例化才检查，太晚 ✗；第三个静默改名改变行为 ✗；第四个与元类无关 ✗。ORM/框架的命名约束正是这样做。出处同面试题四
专家题二（查找顺序·机制）：类成员查找时，元类属性什么时候会被访问到？
类成员查找顺序：① 自身 MRO 链条 → ② 元类 MRO 链条。类自己的属性优先，找不到才落到元类——所以「在元类上放类属性」可以给一批类提供共享默认值。与实例查找（数据描述符 → 实例 → 类 MRO）对照记忆。出处同面试题四
