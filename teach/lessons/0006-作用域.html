知识速览

先花几分钟把核心机制过一遍——细节都在《6.作用域》里，测验和考核会考。

LEGB 查找链

L 局部 ─ 找不到 ─▶ E 外层函数 ─ 找不到 ─▶ G 全局 ─ 找不到 ─▶ B 内置

⚙️ 读取按 L → E → G → B 逐层向外找；写入（赋值）默认创建/使用当前层变量，不会自动去改外层。

三个要点

  1. 编译期就定作用域：函数内只要出现赋值语句，该名字就被判定为局部变量——所以「先读全局、后赋值」会抛 UnboundLocalError。想改全局必须 global。官方文档：Name Resolution
  2. global 指向全局，nonlocal 指向外层函数：global count 声明「我改的是模块级变量」；nonlocal count 声明「我改的是外层函数的变量」。用错对象会报错。
  3. 闭包 = 内层函数捕获外层变量：外层函数返回内层函数，内层函数「记住」外层的变量——配合 nonlocal 就能保存状态（计数器、账户余额）。官方教程：Defining Functions

分级测验

点击选项立即获得反馈。答错也没关系——仔细读解释，它会把文档里对应的小节指给你。三级难度：初级考概念，中级考应用，高级考综合与陷阱。

🌱 初级测验 · 概念

1. Python 查找变量的 LEGB 顺序是？
查找从内向外：L（局部）→ E（外层函数）→ G（全局）→ B（内置）。详见「LEGB 规则」一节。
2. global 关键字声明的是？
global x 声明「函数内的 x 指全局那个 x」，读写都作用于全局变量。详见「global vs nonlocal」对比表。
3. nonlocal 关键字声明的是？
nonlocal x 声明「x 是我外层函数里的变量」，用于嵌套函数修改外层状态。详见「修改外层变量」一节。

🌿 中级测验 · 应用

4. 函数内只读取全局变量（不赋值），需要声明 global 吗？
读取沿 LEGB 自动向外找：读全局不需要声明，只有修改才需要 global。详见「全局作用域」一节。
5. count = 0 在全局；函数内写 count += 1（无 global 声明）会怎样？
赋值语句让 count 在编译期被判定为局部变量，而 += 需要先读它——局部还没定义就读取 → UnboundLocalError。详见「在函数内修改全局变量」一节。
6. make_counter() 返回的计数器连续调用输出 1、2、3，靠的是？
闭包里 nonlocal count 让内层函数直接修改外层函数的 count，状态在多次调用间保留。详见「修改外层变量」一节。

🎯 高级测验 · 综合

7. 以下代码依次输出的是？ 
x = "global"

def outer():
    x = "enclosing"

    def inner():
        x = "local"
        print(x)

    inner()
    print(x)

outer()
print(x)
三层嵌套逐层推演：inner 有自己的 x = "local" → 打印 local；outer 打印自己的局部 x → enclosing；赋值只是新建局部变量，全局 x 从未被修改 → global。顺序：local → enclosing → global。详见「作用域速查」代码。
8. 以下代码依次输出的是？ 
count = 0

def outer():
    count = 10

    def inner():
        global count
        count += 1
        print(count)

    inner()
    print(count)

outer()
print(count)
global count 让 inner 改的是全局的 count（0 + 1 = 1），不是 outer 的局部 count！所以：inner 打印 1；outer 的局部 count 仍是 10 → 打印 10；全局 count 已被改成 1 → 打印 1。顺序：1 10 1。若想改外层应使用 nonlocal。
9. 以下代码的输出是？ 
def make_multiplier(n):
    def multiply(x):
        return x * n
    return multiply

double = make_multiplier(2)
triple = make_multiplier(3)
print(double(7), triple(7))
每次调用 make_multiplier 都创建独立的变量环境：double 记住 n=2（7×2=14），triple 记住 n=3（7×3=21）——闭包之间互不干扰。这正是源作业四「闭包计数器」的原理基础。

最终考核

下面是《6.作用域》源课程作业的四道改编题——这就是本课的最终考核。规则：不查资料、不运行代码，先在心里算出答案，再点击核对。全部答对且能讲清理由，才算过关。

考核一（作业一·LEGB 查找）：以下代码依次输出的是？ 
x = 1

def func_a():
    x = 2

    def func_b():
        print(x)

    func_b()
    print(x)

func_a()
print(x)
逐层推演：func_b 里没有局部 x，按 LEGB 向外找到外层函数的 x = 2 → 输出 2；func_a 自己的局部 x 也是 2 → 输出 2；全局 x 未被修改 → 输出 1。顺序：2 2 1。
考核二（作业二·global 陷阱）：以下代码依次输出的是？ 
count = 0

def outer():
    count = 10

    def inner():
        global count
        count += 1
        print(count)

    inner()
    print(count)

outer()
print(count)
global count 让 inner 改的是全局的 count（0 + 1 = 1），不是 outer 的局部 count！所以：inner 打印 1；outer 的局部 count 仍是 10 → 打印 10；全局 count 已被改成 1 → 打印 1。顺序：1 10 1。若想改外层应使用 nonlocal。
考核三（作业三·修复代码）：以下代码运行会抛 UnboundLocalError，正确的修复是？ 
call_count = 0

def process_data(data):
    result = sum(data)
    call_count += 1   # 这里报错
    return result
call_count 是模块级（全局）变量，函数内要修改它必须声明 global call_count。nonlocal 用于外层函数变量，这里没有外层函数会报错 ✗；改成 = 0 会每次归零 ✗；删除则计数器失效 ✗。
查看源课程参考答案（作业三·修复后） 
call_count = 0

def process_data(data):
    global call_count      # 声明使用全局计数器
    result = sum(data)
    call_count += 1
    return result

print(process_data([1, 2, 3]))   # 6
print(process_data([4, 5, 6]))   # 15
print(f"总共调用了 {call_count} 次")  # 总共调用了 2 次
考核四（作业五·闭包账户）：实现 create_account(initial_balance)，返回存款/取款两个函数，用闭包保存余额（不暴露余额变量）。下列实现中正确的是？
正确答案：两个闭包都用 nonlocal balance 修改外层函数的余额变量，状态在多次调用间保留。第二个选项会抛 UnboundLocalError ✗；第三个在模块级找不到 balance 会抛 NameError ✗；第四个每次重置余额，存款/取款状态丢失 ✗。
查看源课程参考答案（作业五） 
def create_account(initial_balance):
    balance = initial_balance

    def dep(n):
        nonlocal balance
        balance += n
        return balance

    def draw(n):
        nonlocal balance
        if n > balance:
            return "余额不足"
        balance -= n
        return balance

    return dep, draw

deposit, withdraw = create_account(100)
print(deposit(50))    # 150
print(withdraw(30))   # 120
print(withdraw(200))  # 余额不足

# 各账户相互独立
deposit2, withdraw2 = create_account(50)
print(deposit2(10))   # 60
