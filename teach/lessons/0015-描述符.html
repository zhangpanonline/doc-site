知识速览

先花几分钟把核心机制过一遍——细节都在《15.描述符》里，测验和考核会考。

描述符与查找顺序

数据型描述符（有 __set__） ─ 优先级 1 ─▶ 实例属性 __dict__ ─ 优先级 2 ─▶ 普通类属性 ─ 优先级 3 ─▶ 父类…

⚙️ 描述符只有作为类属性才有意义；实现了 __set__/__delete__ 的叫数据型描述符（最常用）。

三个要点

  1. 描述符拦截属性的读/写/删：__get__(self, instance, owner)、__set__(self, instance, value)、__delete__(self, instance)——通过类访问时 instance 是 None。官方文档：Descriptors
  2. 数据型描述符压过实例字典：a.__dict__["x"] = ... 塞进实例字典也白搭——读 a.x 时数据描述符优先（考核四思考题）。
  3. @property 就是描述符：getter/setter/deleter 是官方提供的描述符语法糖——只读属性、范围验证、惰性计算的标配。官方文档：property

分级测验

点击选项立即获得反馈。答错也没关系——仔细读解释，它会把文档里对应的小节指给你。三级难度：初级考概念，中级考应用，高级考综合与陷阱。

🌱 初级测验 · 概念

1. 一个类实现了下面哪个方法就可以叫描述符类？
描述符协议规定：实现 __get__、__set__、__delete__ 任意一个实例方法的类就是描述符类。详见「认识术语」一节。
2. 数据型描述符的判定条件是？
实现了 __set__ 或 __delete__ 的描述符对象是数据型描述符；只实现 __get__ 的是非数据型。详见「认识术语」一节。
3. 描述符对象放在哪里才有意义？
描述符对象只有作为类属性时才会触发 __get__/__set__ 拦截；实例属性不经过描述符协议。详见「认识术语」一节。

🌿 中级测验 · 应用

4. 实例成员查找的优先级顺序是？
访问实例成员：① 数据型描述符（类属性）→ ② 实例属性 → ③ 普通类属性 → ④ 父类。数据描述符会「压过」实例字典。详见「访问顺序」一节。
5. __set_name__(self, owner, name) 的作用是？
__set_name__ 钩子（3.6+）在类体完成赋值后触发，告诉描述符「你在 X 类的 Y 属性上」——类型检查描述符用它记录属性名。详见「钩子函数」一节。
6. @property 与描述符的关系是？
property 是内置的数据描述符类，@property/@x.setter/@x.deleter 就是官方提供的描述符语法糖。详见「@property 装饰器」一节。

🎯 高级测验 · 综合

7. 数据型描述符 D 挂在类属性 x 上，执行 a.__dict__["x"] = "instance" 后，a.x 读到什么？
查找顺序：数据描述符 → 实例属性——即使 "instance" 被塞进实例字典，读 a.x 仍走描述符的 __get__。实例字典里的值被「压住」了（考核四思考题的完整推演）。
8. 非数据型描述符（只有 __get__）与实例属性同名时，读到什么？
只有 __get__ 的非数据型描述符排不过实例字典：实例 __dict__ 里有同名键时优先返回实例属性。惰性计算描述符正是利用这一点——首次计算后把结果写回实例字典「缓存」。
9. 惰性计算描述符（非数据型）的缓存原理是？
惰性计算模板：__get__ 里 value = self.func(instance); setattr(instance, self.name, value); return value——第一次计算后写回实例字典，第二次访问因「实例属性优先于非数据描述符」直接读缓存，不再计算。详见「应用场景：惰性计算」一节。

最终考核

下面是《15.描述符》源课程作业的四道改编题——这就是本课的最终考核。规则：不查资料、不运行代码，先在心里选出正确实现，再点击核对。

考核一（作业一·只读属性）：ImmutablePoint 创建后 p.x = 10 要抛 AttributeError。下列实现中正确的是？
只定义 getter 的 property 是只读属性：赋值 p.x = 10 时找不到 setter，抛 AttributeError: can't set attribute。第二个随便改 ✗；第三个读不到值 ✗；第四个不报错，不符合题意 ✗。
查看源课程参考答案（作业一） 
class ImmutablePoint:
    def __init__(self, x, y):
        self._x = x
        self._y = y

    @property
    def x(self):
        return self._x

    @property
    def y(self):
        return self._y

p = ImmutablePoint(3, 4)
print(p.x)   # 3
# p.x = 10   # AttributeError! 不能修改只读属性
考核二（作业二·范围验证）：Temperature 的 celsius 必须在 -273.15～1000 之间，fahrenheit/kelvin 只读自动计算。下列实现中正确的是？
正确实现：@celsius.setter 里 value < -273.15 或 > 1000 时 raise ValueError；fahrenheit（c × 9/5 + 32）与 kelvin（c + 273.15）是只读 property，自动计算。第二个静默截断不符合「抛 ValueError」要求 ✗；第三个没法设初值 ✗；第四个绕过 setter 赋值就漏检 ✗。
查看源课程参考答案（作业二） 
class Temperature:
    def __init__(self, celsius):
        self._celsius = celsius

    @property
    def celsius(self):
        return self._celsius

    @celsius.setter
    def celsius(self, value):
        if value < -273.15:
            raise ValueError("温度不能低于绝对零度")
        if value > 1000:
            raise ValueError("温度不能超过1000")
        self._celsius = value

    @property
    def fahrenheit(self):
        return self._celsius * 9 / 5 + 32

    @property
    def kelvin(self):
        return self._celsius + 273.15
考核三（作业三·访问计数器）：描述符 AccessCounter 统计某类属性被访问/修改的次数（obj.value 3 次读 + 1 次写 → 访问 3、修改 1）。下列实现中正确的是？
正确实现：__get__ 里 _access_count += 1 并返回 self._value；__set__ 里 _modify_count += 1 并存值。计数器必须是类属性，所有实例共享（3 次读跨两个 print 累计）。第二个计反 ✗；第三个按实例隔离，总数对不上 ✗；第四个读操作漏计 ✗。
查看源课程参考答案（作业三） 
class AccessCounter:
    _access_count = 0
    _modify_count = 0

    def __init__(self, init_value):
        self._value = init_value

    def __get__(self, instance, owner):
        AccessCounter._access_count += 1
        return self._value

    def __set__(self, instance, value):
        AccessCounter._modify_count += 1
        self._value = value

    @classmethod
    def get_access_count(cls):
        return cls._access_count

    @classmethod
    def get_modify_count(cls):
        return cls._modify_count
考核四（作业四·思考题）：以下代码最后两行的输出是？ 
class Descriptor:
    def __get__(self, instance, owner):
        print(f"__get__ called, instance={instance}, owner={owner}")
        return 42

    def __set__(self, instance, value):
        print(f"__set__ called, instance={instance}, value={value}")

class A:
    x = Descriptor()

a = A()
print(a.x)                    # 触发 __get__
a.x = 100                     # 触发 __set__
a.__dict__["x"] = "instance"  # 直接塞进实例字典
print(a.x)                    # ?
print(a.__dict__)             # ?
这是数据型描述符的优先级体现：虽然 "instance" 被塞进了实例字典，但读 a.x 时查找顺序是「数据描述符 → 实例属性」——__get__ 仍被触发，返回 42；而 a.__dict__ 直接看实例字典，就是 {'x': 'instance'}。实例属性被数据描述符「压住」了。
