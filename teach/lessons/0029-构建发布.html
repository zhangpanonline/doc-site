构建发布

本课目标

完成本课后，你将能：

  1. 读懂 pyproject.toml 的 [build-system] 与 [project] 配置
  2. 走通完整流程：构建 → 校验 → 发布 → 安装（官方仓库与私有仓库）
  3. 用 pip install -e . 可编辑安装提升日常开发效率——最终考核围绕源作业的构建流程复述展开

知识速览

先花几分钟把核心机制过一遍——细节都在《29.构建发布》里，测验和考核会考。

构建发布流水线

源码 + pyproject.toml ─ 构建 ─▶ dist/（sdist + wheel） ─ 校验 ─▶ twine check ─ 上传 ─▶ PyPI / 私有仓库

⚙️ 构建前端（build/uv）负责发起构建，构建后端（hatchling/setuptools）按 PEP 517/427 产出标准产物。

三个要点

  1. [build-system] 声明「用什么工具构建」：requires 列出后端依赖，build-backend 指定入口（如 hatchling.build）。PEP 517（构建协议） · PEP 427（wheel 标准）
  2. 发布用 twine，token 代替密码：twine check dist/* 校验产物 → twine upload dist/* 上传；私有仓库在 pip 配置里加 index-url/trusted-host。官方文档：twine
  3. 可编辑安装 = 开发模式：pip install -e . 在 site-packages 里放指向源码的 .pth 链接——改源码即时生效，无需反复构建。官方文档：Editable installs

分级测验

点击选项立即获得反馈。答错也没关系——仔细读解释，它会把文档里对应的小节指给你。三级难度：初级考概念，中级考应用，高级考综合与陷阱。

🌱 初级测验 · 概念

1. pyproject.toml 中 [build-system] 的作用是？
[build-system] 是构建配置：requires = ["hatchling"] + build-backend = "hatchling.build"；名称版本等在 [project] 里。详见「pyproject.toml 构建配置」。
2. python -m build 的产物放在哪里、包含什么？
构建产物在 dist/：.tar.gz（sdist 源码分发包）+ .whl（wheel 二进制分发包）。详见「构建步骤」一节。
3. version = "0.1.3" 中的语义化版本含义是？
语义化版本：主.次.补丁——0.x 表示尚未稳定（API 可随时变）。详见「pyproject.toml 构建配置」注释。

🌿 中级测验 · 应用

4. 发布前校验构建产物完整性的命令是？
twine check dist/* 校验产物（README 渲染、元数据完整性等），通过后再 twine upload。详见「发布前的准备」一节。
5. pip install -e .（可编辑安装）的原理是？
可编辑安装创建指向项目源码的 .pth 链接（不是复制）——源码修改立即生效，无需重新构建安装。详见「可编辑依赖」一节。
6. 私有仓库的 pip 配置里 trusted-host 的作用？
私有仓库常自签证书或走 http：trusted-host = packages.aliyun.com 让 pip 信任该主机。详见「发布到私有仓库」一节。

🎯 高级测验 · 综合

7. 一个库从零到可安装，正确的操作顺序是？
标准流程：python -m venv .venv → source .venv/bin/activate → pip install build → python -m build → 产物在 dist/。构建在前、上传在后，twine 只上传不构建。
8. [project] 段的 name、version、requires-python、dependencies 各自的含义分别是？
[project] 四件套：name（发行版名称，小写连字符）、version（语义化版本）、requires-python（如 ">=3.14"）、dependencies（第三方依赖清单）。详见「pyproject.toml 构建配置」。
9. 构建完成发布到 PyPI 的正确顺序是？
发布流程：注册 PyPI 账号 → 创建 API token（比密码安全）→ twine check dist/* 校验 → twine upload dist/* 上传。顺序不能反：先校验再上传。

最终考核

下面是《29.构建发布》源课程作业的改编题——这就是本课的最终考核。规则：不查资料、不运行代码，先在心里选出答案，再点击核对。

📣 源作业还要求费曼复述：把「一个库从源码到可安装」的完整构建流程讲一遍（源码+配置 → 构建 → 校验 → 上传 → 安装），讲不通就回到对话里让 AI 老师给你反馈。

考核一（构建流程排序）：一个库从零到可安装，正确的操作顺序是？
标准流程：python -m venv .venv → source .venv/bin/activate → pip install build → python -m build → 产物在 dist/。构建在前、上传在后，twine 只上传不构建。
考核二（pyproject 配置）：duyi-utils 库声明 name/version/requires-python/dependencies，下列 [project] 配置中正确的是？
[project] 段：name（发行版名称，小写连字符）、version（语义化版本号）、requires-python（支持的 Python 版本）、dependencies（第三方依赖清单）。带空格的名字 ✗；非数字版本 ✗；依赖放错段 ✗。
考核三（发布流程）：构建完成后发布到 PyPI，正确的操作是？
发布流程：注册 PyPI 账号 → 创建 API token（比密码安全）→ twine check dist/* 校验 → twine upload dist/* 上传。私有仓库则按仓库指南配置 index-url 后安装。
考核四（可编辑安装预测）：项目 A 用 pip install -e ../duyi-utils 安装了公共库，随后修改了 duyi-utils 的源码，项目 A 需要做什么？
可编辑安装通过 .pth 链接直指源码：源码一改，下次导入/调用立即用新代码——这正是开发模式下「改完即测」的核心价值。

四道考核全部答对且费曼复述能讲清楚，说明你已经掌握构建发布——可以继续学习《28.项目管理工具》了。
