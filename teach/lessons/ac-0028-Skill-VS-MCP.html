Skill VS MCP

配合《28.Skill VS MCP》使用预计 15–20 分钟9 道分级测验 + 面试实战

本课目标

完成本课后，你将能：

  1. 说清 Skill 与 MCP 的关系——课件原话「完全是两个东西」，为什么还要放一起比
  2. 复述两者的共同点：各有事实标准、因此形成社区与聚合站、功能体验重叠（天气既可用 Skill 也可用 MCP）
  3. 背下差异表八个维度（上下文消耗命中/未命中、接入成本、可扩展性、贡献人群、确定性、通用工具依赖、越权风险），并能解释「未命中低 / 命中高」这类反直觉的成因
  4. 用最佳实践做选型判断：MCP 定义底层工具，Skill 定义业务流程——看任务要的是确定性还是灵活性

知识速览

先花几分钟把「为什么这两个东西会被放在一起比、比出来的差异怎么用」这条线过一遍——细节都在《28.Skill VS MCP》里，测验和面试会考。

共同点：标准、社区、体验重叠

  • 前提：Skill 和 MCP 完全是两个东西；它们之所以放到一起讨论，是因为在使用感官上有一些共同点
  • 标准化：无论是 Skill 还是 MCP，都有各自的事实标准——Skill 侧是 SKILL.md 那套目录与 frontmatter 约定，MCP 侧是协议规范
  • 有标准就有生态：由于有标准，就容易形成社区和聚合站；我们通过社区或聚合站，能使用到大量现成的 SKILL 和 MCP 工具
  • 功能体验重叠：以获取某个城市的天气为例，它既可以用 Skill 来实现，也可以使用 MCP 来实现——所以「能不能做」不构成选型依据

定位差异：谁来做 VS 怎么做

  • 课件原话：MCP 告诉模型「谁来做」，Skill 告诉模型「怎么做」
  • 读法：MCP 提供的是一个已经实现好、可以确定性执行的外部执行者（工具/数据源通过标准协议暴露）；Skill 提供的是让模型自己动手时的方法与流程知识
  • 所以两者的产物完全不同：MCP 的产物是带 schema 的接口，Skill 的产物是可插拔的专业提示词模块
  • 这正是「功能体验重叠」却仍需对比的根因——重叠的是能力，不重叠的是定位

  • 未命中为什么要看：Skill 未命中时系统提示词里只挂着描述，成本低；MCP 的工具定义通常是预加载进上下文的，未命中也要付这份钱——除非像官方工程实践那样做渐进式披露
  • 命中为什么反过来：Skill 一旦命中，整份正文被读进上下文，成本高；MCP 命中时只是把一次调用的结果落进上下文，比读一整篇流程文档便宜
  • 确定性与越权是一体两面：MCP 的行为被 schema 与实现钉死，越权空间小；Skill 靠自然语言指挥模型，灵活但可能被越权提问带偏——所以才有 no-permission 这类的拦截型 Skill

最佳实践：MCP 定义底层工具，Skill 定义业务流程

  • 分层判据：MCP 负责实现底层工具——文件读写、命令执行、网络搜索、接口搜索与调用、代码执行，以及其他对确定性、安全性要求高的操作
  • Skill 负责定义业务流程——机票怎么定、行程怎么规划；退货能不能退、怎么退；怎么介绍产品；怎么成交，以及其他对灵活性、专业性要求高的流程
  • 一句话记忆：底层要稳（MCP）→ 上层要活（Skill）；Skill 里描述流程时可以调用 MCP 暴露的工具作为执行底座

分级测验

即时反馈：点击选项立刻显示对错与解释。题目只考本课与《28.Skill VS MCP》覆盖的内容。

🌱 初级测验 · 概念

1. 课件对 Skill 与 MCP 关系的定位是？
课件原文：「Skill 和 MCP 完全是两个东西，它们之所以放到一起讨论，是因为在使用感官上，它们有一些共同点。」
2. 「以获取某个城市的天气为例，它既可以用 Skill 来实现，也可以使用 MCP 来实现」——这句话在课件里用来说明？
这一句是「共同点 → 功能体验重叠」小节的例子：同一个需求两种方式都能落地，因此选型要看差异表里的取舍，而不是看可行性。
3. 课件给出的定位差异原话是？
课件「差异点」小节原文：MCP 告诉模型谁来做，Skill 告诉模型怎么做。MCP 提供的是已实现好、可确定性执行的外部工具；Skill 提供的是流程与方法知识。

🌿 中级测验 · 应用

4. 关于「上下文消耗」，课件差异表给出的组合是？
差异表原文：Skill「未命中 低 / 命中 高」，MCP「未命中 高 可通过渐进式披露解决 / 命中 低」。Skill 未命中时只有描述挂在提示词里、成本低，命中后整份正文进上下文、成本高；MCP 的工具定义通常预加载，未命中也要付费，但单次命中的结果比读一整篇流程便宜。
5. 团队要快速沉淀一大批「本公司专属话术与流程」并让贡献者都能参与，按差异表判断应优先选哪种形态？
差异表：Skill 在接入成本（低）、可扩展性（高）、贡献人群（广）三项占优，代价是确定性低、越权风险高。MCP 恰好相反——接入成本高、可扩展性低、贡献人群窄，换来高确定性与低越权风险。所以「快速堆量 + 多人贡献」的流程沉淀选 Skill，硬骨头（确定性/安全性要求高）交给 MCP。
6. 接入了十几个 MCP 服务器后，Agent 还没开始干活就吃掉几十万 token（工具定义全量预加载）。按差异表的注释，最对症的解法是？
差异表在 MCP「上下文消耗（未命中）＝ 高」后面专门标了「可通过渐进式披露解决」。方向上应保留 MCP 的高确定性，只改上下文策略：让模型先看到工具名的轻量清单，需要时再读完整定义与 schema。

🎯 高级测验 · 综合

7. 某客服 Agent 同时挂了「退货 Skill」和「订单 MCP」。团队抱怨：模型经常不退就直接按自己理解编流程答复用户，甚至答应不该答应的事。按本章的差异表与最佳实践，最合理的整改是？
最佳实践：MCP 定义底层工具，Skill 定义业务流程。退货「能不能退、怎么退」属于对灵活性、专业性要求高的流程 → Skill；退款执行属于对确定性、安全性要求高的操作 → MCP。选项 1 把流程塞进 MCP 会丢掉灵活性；选项 3 重复描述会同时抬高两侧的上下文成本，且没解决「该不该退」的判定问题；选项 4 与确定性背道而驰。
8. 一个 Agent 里同时存在：SKILL.md（描述公司销售话术与成交节奏）、MCP 文件读写工具、MCP 代码执行工具、一个本地的 read_file 工具。下面哪种说法符合本章结论？
两条结论合起来用：① 功能体验重叠是常态（天气那节的例子），所以「都有文件读写」不构成谁替代谁的证据；② 分工按「确定性/安全性 vs 灵活性/专业性」切——底层工具用 MCP（或本地工具），业务流程用 Skill。
9. 业务方要求「三十天内上线 20 条渠道专属的成交流程，且每条流程每周都可能微调」。你只有一名工程师。按本章差异表，最务实的路径与需要配套的风控是？
差异表指向很清楚：接入成本低、可扩展性高、贡献人群广 → Skill 是承载「多、常改、业务方自己维护」的流程的正确形态；但表里同时写着 Skill「确定性 低 / 越权风险 高」，所以必须配套边界约定与高危动作的 MCP 兜底，这正是最佳实践里的分层。选项 1、4 把 MCP 的低可扩展性用在了最不合适的地方；选项 3 回到第 23 章讲的提示词膨胀。
