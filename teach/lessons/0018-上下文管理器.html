知识速览

先花几分钟把核心机制过一遍——细节都在《18.上下文管理器》里，测验和考核会考。

with 的等效形式

__enter__() ─ 返回值给 as ─▶ 执行代码块 ─ 无论成败 ─▶ __exit__(异常三元组)

⚙️ __exit__ 收到 (exc_type, exc_val, exc_tb)，无异常时是 (None, None, None)；返回 True 表示「异常我处理了」，不再向上传播。

三个要点

  1. 上下文管理器 = 实现 __enter__ + __exit__ 的对象：两个方法缺一不可，否则 with 报错。官方文档：Context Managers
  2. @contextmanager 用生成器写上下文管理器：yield 之前的代码等于 __enter__，之后（写在 finally 里最稳妥）等于 __exit__。官方文档：contextlib.contextmanager
  3. 清理代码写在 finally：yield 后的清理若不在 finally 中，代码块抛异常时会跳过清理——考核四的两版 demo 就是这个差别。

分级测验

🌱 初级测验 · 概念

1. with 表达式 as 变量名: 首先调用的是？
进入 with 先调 __enter__()，其返回值赋给 as 后的变量；代码块结束后（无论异常与否）调 __exit__。详见「with 语句的等效形式」。
2. __exit__ 返回 True 表示什么？
__exit__ 返回 True 吞掉异常（如 SuppressError 忽略指定异常）；返回 False（或 None）则异常继续传播。详见「异常处理」一节。
3. 自定义上下文管理器必须实现哪些方法？
必须同时实现 __enter__ 和 __exit__，缺一个 with 语句直接报错。详见「基本用法」一节的说明。

🌿 中级测验 · 应用

4. @contextmanager 装饰的生成器中，yield 前后代码对应什么？
yield 之前是进入逻辑（__enter__），yield 之后是退出逻辑（__exit__）。详见「使用 @contextmanager 装饰器」一节。
5. with 块正常结束（无异常）时，__exit__ 收到的三个参数是？
无异常时 __exit__(None, None, None)；有异常时传 (异常类型, 异常值, 追踪信息)。用 exc_type is None 就能判断是否正常退出。详见「with 语句的等效形式」。
6. 同时使用两个上下文管理器的简洁写法是？
Python 3.1+ 支持 with A() as a, B() as b: 一行并列（按顺序进入、逆序退出）。详见「多个上下文管理器」一节。

🎯 高级测验 · 综合

7. with A() as a, B() as b: 退出时 __exit__ 的调用顺序是？
多个上下文管理器按后进先出退出：B 的 __exit__ 先执行，A 的后执行——与嵌套 with 的行为完全一致（一行写法只是语法糖）。
8. __exit__ 返回 False，而 with 块里抛了异常，会发生什么？
__exit__ 返回 False（或 None）=「我没处理异常」——异常继续向外传播，就像没有 with 一样。返回 True 才是吞掉。这是资源清理型上下文管理器（TempDirectory）的标准选择。
9. @contextmanager 中清理代码放在 yield 后但不在 finally 里，块内抛异常时会怎样？
块内异常会从 yield 处抛进生成器：yield 之后的代码被跳过，清理不执行（异常继续传播）。把清理写进 try/finally 才能保证必执行——这是 @contextmanager 的第一要诀。

最终考核

下面是《18.上下文管理器》源课程作业的改编题——这就是本课的最终考核。规则：不查资料、不运行代码，先在心里选出正确实现，再点击核对。

考核一（作业一·timer 计时）：用 @contextmanager 实现——with timer("数据处理") 块结束时打印 数据处理 耗时: X.XXXX 秒（异常时也要打印）。下列实现中正确的是？
正确结构：start = time.time(); try: yield; finally: print(耗时)——finally 保证异常时也打印。第二个块里抛异常会跳过打印 ✗；第三个计的是 0 秒 ✗；第四个吞异常改变语义 ✗。
查看源课程参考答案（作业一） 
import time
from contextlib import contextmanager

@contextmanager
def timer(name):
    start = time.time()
    try:
        yield
    finally:
        elapsed = time.time() - start
        print(f"{name} 耗时: {elapsed:.4f} 秒")

with timer("数据处理"):
    time.sleep(1)
    print("处理完成")
# 处理完成
# 数据处理 耗时: 1.0012 秒
考核二（作业二·TempDirectory）：进入时创建临时目录（返回路径），退出时自动删除整个目录。下列实现中正确的是？
正确结构：__enter__ 里 self.path = tempfile.mkdtemp() 并 return self.path；__exit__ 里 shutil.rmtree(self.path)（递归删内容）并 return False（不吞异常）。第二个拿到的是对象不是路径 ✗；第三个目录里的文件删不掉 ✗；第四个吞异常不合题意 ✗。
查看源课程参考答案（作业二） 
import os
import tempfile
import shutil

class TempDirectory:
    def __enter__(self):
        self.path = tempfile.mkdtemp()
        return self.path

    def __exit__(self, exc_type, exc_val, exc_tb):
        shutil.rmtree(self.path)
        return False

with TempDirectory() as tmp_dir:
    print(f"临时目录: {tmp_dir}")
    with open(os.path.join(tmp_dir, "test.txt"), "w") as f:
        f.write("hello")

print("临时目录已清理")
考核三（作业四·思考题1）：以下代码的输出是？ 
@contextmanager
def demo():
    print("进入")
    yield
    print("正常退出")

with demo():
    print("执行中")
    raise ValueError("出错了")
    print("这行不会执行")
块内 raise 后，@contextmanager 把异常从 yield 处抛进生成器——生成器不继续执行，print("正常退出") 被跳过，异常向外传播。完整输出：进入 → 执行中 → ValueError。这正是清理代码必须写进 finally 的原因（下一题）。
考核四（作业四·思考题2）：把 demo 改成 try: yield / except Exception as e: print(f"捕获异常: {e}") / finally: print("清理")，with 块里同样 raise ValueError，输出是？
except 把异常接住了：打印「捕获异常: 出错了」后生成器正常收尾，finally 打印「清理」——with 块像没发生过异常一样继续。这就是上下文管理器「吞异常」的完整演示（等价于 __exit__ 返回 True）。

下面是真实面试官会问的问题，选自中文互联网面试题集（出处附后）。先自己回答，再点击核对。三级面试难度：中级考应用，高级考陷阱，专家考机制与设计。

⚡ 中级面试题

面试题一（with 原理·必问）：with 语句的工作原理与好处？
with 背后是 __enter__/__exit__ 协议：进入时 __enter__（返回值给 as），退出时无论是否异常都调 __exit__——资源（文件、数据库连接、锁）一定被释放，不会因中途出错而泄漏。注意 __exit__ 返回 True 会压制异常，通常不推荐。出处：腾讯云「Python 高级特性解析与面试应对策略」
面试题二（实现方式·高频）：自定义上下文管理器的两种实现方式？
两种方式：① 类实现——定义 __enter__（返回资源给 as）与 __exit__（清理）；② @contextmanager 生成器——yield 前是进入逻辑、yield 后是清理逻辑，代码更简洁。面试时要两种都会写。出处同面试题一

🔥 高级面试题

面试题三（retry 设计·深水区）：为什么「失败重试」必须用装饰器实现，而上下文管理器实现不了？
本质区别：装饰器可以在 wrapper 里循环调用函数（每次调用都是一次完整执行，失败后重来）；而 with 块只能进入一次——__exit__ 只能决定「吞异常还是传播」，无法让代码块重新执行一遍（源课程作业三正是注明「这道题有问题，上下文管理器无法实现 retry」）。工具的职责边界本身就是考点。出处：腾讯云「Python 高级特性解析与面试应对策略」
面试题四（吞异常代价·机制）：为什么说「__exit__ 返回 True 压制异常」通常不推荐？
__exit__ 返回 True 会静默吞掉异常——调用方完全不知道发生过错误，问题被埋进运行时。除非是 SuppressError 这类「明确要忽略特定异常」的场景，资源管理型上下文管理器应返回 False 让异常正常传播。出处同面试题三

🧠 专家面试题

专家题一（标准工具·机制）：contextlib.suppress 与 redirect_stdout 分别做什么？
contextlib.suppress(FileNotFoundError) 忽略指定异常（比 try/except pass 更声明式）；redirect_stdout(f) 把 print 等输出临时重定向到文件（如捕获命令行输出）——contextlib 里的现成工具，面试问到说明熟悉标准库。出处同面试题三
专家题二（职责边界·设计）：上下文管理器与装饰器的职责边界是？
上下文管理器围绕资源的进入与退出（文件、锁、连接：with 块期间有效）；装饰器围绕函数调用的前后（计时、缓存、重试：对任意函数生效）。边界清晰：需要「块级生命周期」用 with，需要「可重复调用的包装」用装饰器。出处同面试题三
