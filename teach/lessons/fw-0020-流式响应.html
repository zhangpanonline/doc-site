知识速览

先花几分钟把核心机制过一遍——细节都在《20.流式响应》里，测验和面试会考。

SSE（Server-Sent Events）

  • 单向：服务端 → 客户端；基于标准 HTTP；text/event-stream，每条消息以 \n\n 结尾
  • 原生自动重连；适合新闻推送、股票行情、日志流、简单问答模式
  • 中间件：请求/响应经过全部 HTTP 中间件，后续流式内容不经过
  • 异常：响应过程中的异常走异常处理器，流式内容中的不走

WebSocket

  • 全双工：HTTP 101 升级为独立协议（ws:// 或 wss://）；文本+二进制帧
  • 重连需手动实现；适合在线聊天、多人协作、实时游戏、Agent 工作流
  • 中间件/异常都不经过（协议升级后脱离 HTTP 链路）；依赖注入在连接断开后才迭代结束
  • token：浏览器不支持自定义头，只能 query 携带

分级测验

🌱 初级测验 · 概念

1. SSE 和 WebSocket 最本质的区别是？
课件对比表第一条：SSE 服务端→客户端单向；WebSocket 全双工双向。这是选型的根。
2. SSE 消息的结尾分隔符是？
课件 SSE 特征：数据格式 text/event-stream，每条消息以双换行符（\n\n）结尾——事件流协议的分帧约定。
3. WebSocket 建立连接的第一步是？
课件 WebSocket 时序图：GET /ws 带 Connection: Upgrade / Upgrade: websocket → 服务端回 101 Switching Protocols → 之后全双工帧通信，Close 帧优雅关闭。

🌿 中级测验 · 应用

4. SSE 流式内容推送过程中，异常处理器还管用吗？
课件 FastAPI 结合表：响应过程中的异常会经过异常处理函数，后续流式内容不经过——HTTP 头已发出去，无法再改状态码，只能带内发 error 事件。
5. WebSocket 的请求会经过 ch10 的 HTTP 中间件吗？
课件 FastAPI 结合表：WebSocket 的请求/响应都不会经过 HTTP 中间件——所以信封响应、耗时统计这类 ch10 中间件对 WS 无效，需在 WS 路径里另做。
6. 原生 EventSource 的 token 只能放 query，为什么？
课件 token 携带行：原生 EventSource 只能将 token 放 query；自定义或第三方库可以任意方式携带 token——浏览器 API 的限制，不是协议限制。

🎯 高级测验 · 综合

7. SSE 断了之后怎么办？WebSocket 呢？
课件对比表「自动重连」行：SSE 原生支持，WebSocket 需手动实现——SSE 的 EventSource 断线自动重试（可带 Last-Event-ID 续传），WS 要自己写心跳与重连。
8. 「AI 多人在线协作」和「AI 简单问答」分别选什么？
课件对比表「适用AI场景」：SSE 适合简单的问答模式（用户发问一次，模型逐 token 推答案）；WebSocket 适合 Agent 工作流、多人在线 AI 协作（双向频繁交互）。
9. WebSocket 的依赖注入（如 get_db）什么时候结束迭代？
课件 FastAPI 结合表：WebSocket 依赖注入「连接断开后才会迭代结束」——长连接期间 get_db 的 session 一直持有，需要注意连接时长与资源占用（对比 SSE：全部流式内容完成后迭代结束）。
