子查询与集合运算

本课目标

知识速览

先花几分钟把核心机制过一遍——细节与测验依据都来自官方文档 §7.2 与 §7.4。

子查询四形态

  • 标量子查询：当做一个值表达式用——必须恰好返回一行一列
  • FROM 子查询：子查询结果作为派生表，外层继续 JOIN/过滤/聚合
  • EXISTS：存在匹配行即为真；内层引用外层列 → 相关子查询
  • IN：等值匹配集合；NULL 三值逻辑是经典陷阱

集合运算三兄弟（官方原文）

  • UNION：把 query2 结果附加到 query1 结果，并删除所有重复行（像 DISTINCT）——除非用 UNION ALL
  • INTERSECT：返回同时存在于两个查询结果中的行
  • EXCEPT：返回在 query1 中但不在 query2 中的行（差集）
  • 并操作兼容：两查询必须返回相同数量的列且类型兼容

分级测验

即时反馈：点击选项立刻显示对错与解释。题目只考本课与官方文档覆盖的内容。

🌱 初级测验 · 概念

1. 官方文档说标量子查询可以当作什么来使用？
官方原文：把标量子查询当做一个值表达式来用——放在 SELECT 列表或比较运算右侧。
2. EXISTS (SELECT 1 FROM t2 WHERE c2 > fdt.c1) 中，内层引用了外层的 fdt.c1。这叫什么？
官方原文：外层查询的列名范围扩展到它的内层查询——里层引用外层列就是相关子查询，是 EXISTS 类题目的核心。
3. UNION 与 UNION ALL 的区别是？
官方原文：UNION 附加结果后删除所有重复行，就像 DISTINCT 做的那样，除非你使用了 UNION ALL。

🌿 中级测验 · 应用

4. INTERSECT 返回什么？
官方原文：INTERSECT 返回那些同时存在于 query1 和 query2 的结果中的行。
5. EXCEPT 的语义是？
官方原文：EXCEPT 返回所有在 query1 的结果中但不在 query2 的结果中的行——两个查询的「差」。
6. 官方对「并操作兼容」的要求是？
官方原文：为了计算并、交、差，两个查询必须是「并操作兼容的」——返回相同数量的列且类型兼容。

🎯 高级测验 · 综合

7. 标量子查询返回了两行，会发生什么？
标量子查询被当作单个值使用，返回多行时数据库无法把它压成一个值——直接报错。
8. 合并两个月的日志表做统计，行数必须精确。应该用？
日志行即使内容相同也是不同事件——UNION 的去重会吞掉重复行；统计场景必须 UNION ALL 保真，也更快。
9. 「找出有未结订单的客户」——下列哪种写法语义最直接？
「存在关联行」的语义用 EXISTS 最直接（短路、不受 NULL 影响）；相关子查询里 o.customer_id = c.id 把内外层关联起来。

最终考核

四道题覆盖本课全部要点——答完它们，子查询与集合运算就过关了。

考核一：EXCEPT 返回空集说明什么？
差集为空 = query1 没有「query2 之外」的行 = query1 的行全在 query2 里——「包含关系」的判断技巧。
考核二：`SELECT a FROM t1 UNION SELECT b FROM t2` 报类型错误。最可能的原因？
并操作兼容要求列数相同且对应列类型兼容——text 与 integer 直接组合会报类型错误，需要显式转换。
考核三：相关子查询与普通子查询的执行方式差异是？
相关子查询里层引用外层列（官方：外层列名范围扩展），因此依赖外层当前行——语义上逐行相关，这正是 EXISTS 短路的意义。
考核四：三个查询的列数分别是 2、2、3，两两 UNION 合法的是？
并操作兼容要求两查询列数相同——2 与 2 可以，2 与 3 直接报错。

四道考核全部答对，说明你掌握了子查询与集合运算——继续学习 pg-04 · CTE 与递归查询。
