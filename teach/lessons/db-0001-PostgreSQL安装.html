为什么选 PostgreSQL

社区开发 · PostgreSQL License ─ 定位 ─▶ 开源免费，无许可费
MVCC + 流复制/逻辑复制 ─ 并发 ─▶ 读写互不阻塞，复制成熟
Extension（PostGIS 等）+ JSONB ─ 扩展 ─▶ 生态丰富，可作文档库

⚙️ 对照 MySQL 记：MySQL 的 ACID 依赖 InnoDB、SQL 方言多、扩展少；PG 原生完整 ACID、最贴近标准 SQL。

docker run 参数拆解

  1. -d 后台运行：容器在后台跑，不占用当前终端；交互式进入用 docker exec -it。
  2. -e POSTGRES_PASSWORD 必填：不设置这个环境变量，postgres 镜像会拒绝启动（初始化超级用户密码）。POSTGRES_USER 默认 postgres，POSTGRES_DB 默认取用户名。
  3. -p 宿主机端口:容器端口：-p 5432:5432 把宿主机 5432 转发到容器内 5432。顺序反了含义就反了。
  4. -v 本地路径:/var/lib/postgresql/data 是数据保命的参数：容器是易失的，docker rm 删除容器后，没挂卷的数据随可写层一起消失；挂卷后数据落在宿主机，容器删了数据还在。

psql 验证三步

docker exec -it pg16 psql -U admin -d admin   # 进入容器连接数据库
\conninfo        # 当前连接信息
\l               # 列出所有数据库
SELECT current_user;   # 当前用户

记住：psql 里 \ 开头的是元命令（psql 自己处理），SELECT 才是发给数据库的 SQL。

分级测验

三道一组，先做后点——点击选项立刻出对错与解释。

🌱 初级 · 概念

1. PostgreSQL 的许可证是？
PostgreSQL 由社区开发，使用 PostgreSQL License，开源且完全免费。GPL/商用双许可对应 MySQL；社区免费企业付费也是 MySQL 的模式。见《01.PostgreSQL安装》对比表「协议/许可」「费用」两行。
2. 配置 Docker 镜像加速器（registry-mirrors）的作用是？
registry-mirrors 是镜像仓库加速：把官方 Docker Hub 的拉取请求转发到国内镜像源，解决国内网络拉取镜像慢的问题。与 SQL、容器启动、磁盘都无关。配置位置：Docker Desktop → Settings → Docker Engine。
3. 对比表中的「MVCC」指的是？
MVCC = Multi-Version Concurrency Control，多版本并发控制：读操作不阻塞写、写操作不阻塞读。PG 原生支持；MySQL 依赖 InnoDB 引擎才支持——这是 PG 的并发优势。

🌿 中级 · 应用

4. docker run -p 5432:5432 中两个端口的含义是？
格式是 -p 宿主机端口:容器端口——左宿右容。所以 -p 5432:5432 是把宿主机 5432 转发到容器内 5432。想避开宿主机端口冲突可以写成 -p 5433:5432。
5. -v 本地路径:/var/lib/postgresql/data 这个参数的作用是？
-v 是数据卷挂载：把宿主机路径挂到容器内的数据目录 /var/lib/postgresql/data。没有它，docker rm 删除容器后所有表数据随可写层一起消失；有它，数据在宿主机上，重建容器挂同一路径即可找回。
6. psql -U admin -d admin 中 -U 参数的含义是？
-U = User，连接用户名；-d = database，连接数据库名；-h 才是主机。所以 psql -U admin -d admin 是用 admin 用户连接 admin 数据库。

🎯 高级 · 综合

7. 启动容器时没有挂任何数据卷，随后 docker rm 删除容器再重建一个同名容器，之前的表数据会？
容器是易失的：不挂卷时，数据写在容器自己的可写层，docker rm 删除容器即删除该层，数据彻底丢失。镜像里只有初始化的空库模板，不含你的数据。所以要持久化必须 -v 挂卷。
8. 在 psql 提示符下，\l 和 SELECT current_user; 分别输出什么？
\l 是 psql 元命令，列出服务器上所有数据库；SELECT current_user; 是 SQL，返回当前连接用户（本例为 admin）。元命令由 psql 客户端处理，SQL 才发给服务器执行。
9. pgAdmin 容器用 -p 5050:80 启动后，在浏览器访问 http://localhost:5050 能打开页面的原理是？
pgAdmin 的 Web 服务监听在容器内 80 端口，-p 5050:80 把宿主机 5050 转发过去——所以浏览器访问 localhost:5050。端口映射本身就是宿主机访问容器的通道，与 --link（容器间互通）无关。

最终考核

下面是《01.PostgreSQL安装》源课程作业「完成数据库环境搭建」的四道改编题——这就是本课的最终考核。规则：不查资料、不复制命令，先在脑中推演再点击核对。全部答对且能讲清理由，才算过关。

考核一：环境搭建的正确顺序是？
正确链路：安装 Docker Desktop → 配置 registry-mirrors 加速器 → docker pull postgres:16 → docker run 建容器 → docker exec psql 验证。加速器要先配好再拉镜像才有加速效果；镜像要先拉下来（或 run 时自动拉）才能建容器。
考核二：下面哪条命令能正确启动 PostgreSQL 且数据可持久化？
四个要素：① 密码必填（缺 POSTGRES_PASSWORD 镜像拒绝启动）② 端口映射（否则宿主机连不上）③ 数据卷挂载（否则删容器丢数据）④ 挂载点必须是容器数据目录 /var/lib/postgresql/data（挂到 /data 不起作用）。第一项缺卷、第二项缺密码和端口、第四项挂错路径。
考核三：进入容器后，哪组命令能完整验证「连上了、能看到所有库、知道当前是谁」？
\conninfo 看当前连接（用户/库/主机），\l 列出所有数据库，SELECT current_user; 确认当前用户。三连即可确认环境就绪。docker ps / docker info 是容器层面的检查，不是数据库连接验证。
考核四：不小心 docker rm 删掉了 pg 容器，什么情况下数据还能找回？
数据找回的唯一前提：启动时挂了数据卷——数据在宿主机目录里，重建容器挂同一路径即可找回。stop 只是暂停不删容器（数据仍在可写层），rm 才删除；镜像与 --restart 都与数据持久化无关。
