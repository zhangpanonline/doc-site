知识速览

先花几分钟把核心机制过一遍——细节都在《24.事件循环》里，测验和考核会考。

为什么需要事件循环

任务1 阻塞请求 ─ 卡住 ─▶ 线程等待，任务2 干等
任务1 登记回调 ─ 让出 ─▶ 线程先去执行任务2
结果返回 ─ 回调 ─▶ 回来接着处理任务1

⚙️ 异步 = 单线程内让任务不阻塞线程；运算密集选多线程，I/O 密集（爬虫、Web 服务）选异步。

事件循环对象

import asyncio

loop = asyncio.new_event_loop()      # 创建事件循环对象
asyncio.set_event_loop(loop)         # 绑定到当前线程
current_loop = asyncio.get_event_loop()
current_loop.run_forever()           # 陷入循环，直到 stop() 被调用
current_loop.stop()                  # 停止循环

run_forever 与 _run_once

def run_forever(self):
    while True:
        self._run_once()
        if self._stopping:
            break

每一次 _run_once 调度两个队列——ready 队列（待执行回调）与延时队列（定时回调）：

检查延时队列 ─ 到期 ─▶ 加入 ready 队列
计算 timeout ─ ─▶ ready 非空=0 / 有延时=队首−当前 / 都空=None
阻塞等待 I/O ─ 到达 ─▶ I/O 任务立刻进 ready；超时则重新处理延时队列
复制 ready 队列 ─ ─▶ 得到本轮回调清单
执行复制的队列 ─ 保证 ─▶ 清单内回调全部执行

⚙️ 执行的是副本——执行期间新进 ready 的回调（比如 call_soon）要等下一轮 _run_once。

三个要点

  1. 两个队列分工：call_soon(f) 把 f 放入 ready 队列；call_later(delay, f) 把 f 放入延时队列，到期才进 ready。官方文档：call_soon · call_later
  2. 副本语义：_run_once 执行的是 ready 队列的副本，执行期间新注册的回调本轮不会执行——考核第 3 题考的就是这一点。
  3. 没有 stop 就死循环：run_forever 不会自己结束，代码必须安排 stop()，否则后续代码永远执行不到——考核第 1、2 题的坑就在这里。

🌱 初级测验 · 概念

1. 同步代码里，task1 的 requests.post(...) 阻塞了线程，此时 task2 会怎样？
同步代码按顺序执行：task1 的请求阻塞线程，task2 只能排队干等，CPU 资源被浪费。这正是异步要解决的问题——详见《24.事件循环》「同步代码的问题」一节。
2. 爬取大量网页（海量 I/O 请求）的任务，更适合哪种方案？
运算密集选多线程，I/O 密集选异步——爬虫是典型的海量 I/O 任务，单线程事件循环就能并发处理成千上万个请求，开销远小于线程。详见《24.事件循环》「异步 VS 多线程」一节。
3. 在 Python 中，事件循环是什么？
一个事件循环就是一个 AbstractEventLoop 类的对象，通过 new_event_loop() 创建、set_event_loop() 绑定到当前线程。详见《24.事件循环》「AbstractEventLoop类」一节。

🌿 中级测验 · 应用

4. run_forever() 什么时候才会停止循环？
run_forever 是 while True 死循环：每轮 _run_once 后检查 _stopping，只有 stop() 把它置真才会退出。没有 stop()，后续代码永远执行不到。
5. loop.call_soon(f) 的作用是？
call_soon 把回调放入 ready 队列（尽早调度）；call_later(delay, f) 才放入延时队列，到期后进 ready。两个队列是 _run_once 调度的对象。
6. loop.call_later(1, f) 中 f 什么时候执行？
call_later(1, f) 把 f 放进延时队列：_run_once 每轮检查到期项，1 秒后 f 才进入 ready 队列被执行——「至少」1 秒（取决于调度时机）。

🎯 高级测验 · 综合

7. 执行 _run_once 期间，回调里又 call_soon 了一个新回调，它何时执行？
_run_once 执行的是 ready 队列的副本——执行期间新进 ready 的回调要等下一轮。所以若本轮同时调用了 stop()，那个新回调就永远轮不到了（考核第 3 题）。
8. _run_once 计算 timeout 的规则是？
timeout 决定「阻塞等 I/O 等多久」：ready 有活就不等（0）；只有延时任务就等到最近一个到期；什么都没有就无限等（None）。这是 _run_once 五步的第 2 步。
9. 以下代码的输出是？ 
loop = asyncio.new_event_loop()

def delayed():
    print("B")
    loop.stop()

def soon():
    print("A")

loop.call_later(0, delayed)
loop.call_soon(soon)
loop.run_forever()
print("C")
第一轮 _run_once：延时队列的 delayed（0 秒到期）先进 ready → ready = [soon, delayed] → 打印 A 后打印 B，delayed 里调 stop()；本轮结束 _stopping 为真 → run_forever 退出 → 打印 C。完整输出：A → B → C。call_later(0) 也要等一轮，不会先于 call_soon。

最终考核

下面是《24.事件循环》源课程作业的三道预测题——这就是本课的最终考核。规则：不查资料、不运行代码，先在纸上预测输出，再点击选项核对。每一道都要能说清「为什么是这个顺序」才算过关。

考核一：预测以下代码的输出结果（注意最后一行是否会打印） 
import asyncio

loop = asyncio.new_event_loop()

def task1():
    print("任务1")

def task2():
    print("任务2")

def task3():
    print("任务3")

loop.call_soon(task1)
print("task1 over")
loop.call_soon(task2)
print("task2 over")
loop.call_soon(task3)
print("task3 over")

loop.run_forever()
print("已结束")
三行 print("taskX over") 是同步代码，立即输出；三个 call_soon 只是把回调放入 ready 队列。随后 run_forever 执行 ready：依次输出 任务1、任务2、任务3。但代码里没有 stop()——循环不会退出，print("已结束") 永远执行不到，程序卡死。这正是要点 3：没有 stop 就死循环。
考核二：预测以下代码的输出结果（call_later(0) 表示延时 0 秒） 
import asyncio

loop = asyncio.new_event_loop()

def delayed():
    print(1)
    loop.call_later(0, lambda: print(2))
    loop.call_soon(lambda: print(3))

def soon():
    print(4)
    loop.call_soon(lambda: print(5))

loop.call_later(0, delayed)
loop.call_soon(soon)

loop.run_forever()
print("done")
第一轮 _run_once：延时队列里 delayed 到期（0 秒）先进 ready，ready = [soon, delayed]；执行副本——soon 输出 4 并 call_soon 5，delayed 输出 1、call_later 2 进延时队列、call_soon 3。第二轮：2 到期进 ready，ready = [5, 3, 2]，输出 5 3 2。全程没有 stop()，done 永不输出。完整顺序：4 1 5 3 2。
考核三：预测以下代码的输出结果（3 会打印吗？） 
import asyncio

loop = asyncio.new_event_loop()

def first():
    print(1)

def second():
    print(2)
    loop.call_soon(lambda: print(3))
    loop.stop()

def third():
    print(4)

loop.call_soon(first)
loop.call_soon(second)
loop.call_soon(third)

loop.run_forever()
print("循环已停止")
本轮 ready 的副本是 [first, second, third]：first 输出 1；second 输出 2、call_soon 3（进入下一轮的 ready）并 stop()；third 仍在本轮副本中，继续输出 4。本轮结束后 _stopping 为真，循环退出——下一轮的 3 永远轮不到。输出：1 2 4 循环已停止。要点 2（副本语义）+ 要点 3（stop 终止循环）的叠加。
