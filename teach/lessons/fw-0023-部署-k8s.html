知识速览

先花几分钟把核心机制过一遍——细节都在《23.部署-k8s》里，测验和面试会考。

集群与工具链

  • ACS：阿里云容器计算服务——托管 k8s 集群（duyi-cluster，同 VPC，两个带 pod 的交换机）
  • kubectl：命令行入口，config 公网访问；kubectl get nodes 验证连通
  • Helm：包管理器——upgrade --install 带参部署（--set secret.* 注入密钥）
  • 镜像版本纪律：等集群期间删掉 ACR 的 latest 镜像，改用带版本号 tag

拉取凭证与流量链路

  • docker-registry secret：kubectl create secret docker-registry——集群 pull 私有镜像的身份信息
  • ALB：公网负载均衡（同 VPC、两个不带 pod 的交换机）→ 域名 CNAME 指向 ALB DNS
  • Ingress：路由规则——服务 duyi-service、端口 8080；80 重定向 443（HTTPS）
  • 链路：域名 → ALB(443) → Ingress → Service → Pod(8080)

分级测验

🌱 初级测验 · 概念

1. Kubernetes 是什么？（课件原文）
课件开头：K8s 全称 Kubernetes——用于自动部署、扩缩和管理容器化应用程序的开源系统（ch21 容器的规模化编排层）。
2. kubectl 是什么？怎么验证连上了集群？
课件步骤 2/5：安装 kubectl → 获取长期 config（公网访问）→ 本地 kubectl get nodes 看节点——看到即集群可达。
3. Helm 在部署里扮演什么角色？
课件步骤 8/9：brew install helm；helm upgrade --install duyi-service ./k8s --set secret.dbPassword=... ——chart 定义资源，--set 注入配置。

🌿 中级测验 · 应用

4. 创建集群时为什么选「带有 pod 名称的」两个交换机？
课件集群配置：选两个交换机（带有 pod 名称的）——ch22 建的 4 个交换机在此分工：2 个给 pod 网络、2 个留给 ALB；跨可用区成对保证高可用。
5. docker-registry secret 解决什么问题？
课件步骤 6：kubectl create secret docker-registry acr-registry-secret --docker-server/--docker-username/--docker-password——ACR 是私有的，集群拉镜像要有身份。
6. helm 命令里 --set secret.dbPassword="$DB_PASSWORD" 的用意？
课件步骤 9：先 export DB_PASSWORD/JWT_SECRET_KEY（会话级），helm --set 引用注入——敏感值不进 git（ch02/ch21 的密钥纪律延续）。

🎯 高级测验 · 综合

7. 等待集群创建时「删掉 ACR 的 latest 镜像」是为了什么？
课件等待期提示：删除 latest、改用带版本号标记——进入 k8s 后版本可追溯是底线（ch22 面试题同款），ch24 流水线会自动化打版本 tag。
8. 流量从域名到 Pod 的完整链路是？
课件步骤 11：CNAME 指向 ALB DNS → ALB Ingress Controller → 创建 Ingress（服务 duyi-service、端口 8080）→ 转发到 Service/Pod。Pod 地址会漂移，入口永远锚在 ALB。
9. ALB 的 80 端口规则「重定向到 443」解决什么？
课件步骤 11.4：80 端口已自动创建，编辑转发规则重定向到 443——证书绑定 443，所有 HTTP 流量强制升级 HTTPS。
