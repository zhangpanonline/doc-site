知识速览

先花几分钟把核心机制过一遍——细节都在《10.对象的创建过程》里，测验和考核会考。

创建三步

1. cls.__new__(cls) ─ 分配并返回实例 ─▶ 2. isinstance(obj, cls)？ ─ 是才继续 ─▶ 3. obj.__init__()

⚙️ __new__ 负责「造出来」，__init__ 只负责「初始化」。返回的不是本类实例时，__init__ 会被跳过。

三个要点

  1. __new__ 是静态方法，第一参数是 cls：必须 return super().__new__(cls) 才能真正分配实例，忘了 return 会得到 None。官方文档：object.__new__
  2. 单例/对象池重写 __new__：把实例缓存到类属性，命中缓存就直接返回旧对象——因为 __new__ 发生在 __init__ 之前，能拦截住实例的创建。
  3. __new__ 可以返回别的类型：PositiveInt(-3) 返回 0（int 实例），于是 __init__ 被跳过——「类型检查」正是对象创建伪代码的第二步。

分级测验

点击选项立即获得反馈。答错也没关系——仔细读解释，它会把文档里对应的小节指给你。三级难度：初级考概念，中级考应用，高级考综合与陷阱。

🌱 初级测验 · 概念

1. 对象创建的完整顺序是？
先 __new__ 创建实例；然后检查实例是否属于 cls（isinstance(obj, cls)）；是才调用 __init__ 初始化；最后返回对象。详见「对象创建的伪代码」一节。
2. 实现单例模式需要重写的是？
单例要拦截「创建」环节，而 __new__ 发生在 __init__ 之前——在 __new__ 里缓存实例并复用即可。若只在 __init__ 里做文章，对象已经创建出来了，拦不住。详见「单例模式」一节。
3. super().__new__(cls) 在单例中的作用是？
我们重写的 __new__ 只是「包装层」——真正分配内存创建实例的是父类 object.__new__，所以必须 return super().__new__(cls)，否则返回 None。

🌿 中级测验 · 应用

4. 为什么说 __init__ 不是「构造函数」？
__init__ 被调用时实例已经存在（由 __new__ 创建），它只是往实例上装属性。真正「构造」对象的是 __new__。
5. ConnectionPool 用相同 conn_id 两次创建，两个对象的关系是？
对象池按 conn_id 缓存实例：相同 id 命中缓存，pool1 is pool2 → True；不同 id 各建各的，pool1 is pool3 → False。详见「对象池/缓存」一节。
6. PositiveInt(-3) 返回 0（int 实例），此时 __init__ 会执行吗？
__new__ 返回的 0 不是 PositiveInt 的实例，isinstance(obj, cls) 检查失败——__init__ 被跳过。所以 n = PositiveInt(-3) 得到的是纯 int 的 0。详见「正整数」一节。

🎯 高级测验 · 综合

7. 单例类 Database 实例化两次（有 __init__ 且用 _instance 缓存），__init__ 会被调用几次？
单例的经典坑：__new__ 每次返回同一个实例，而实例是 cls 的实例（isinstance 通过），所以 __init__ 每次实例化都会执行——第二次创建会覆盖第一次的属性（如 host）。需要时可在 __init__ 里加「已初始化」标志跳过。
8. 重写 __new__ 但忘记 return super().__new__(cls)，实例化会得到什么？
__new__ 不 return 时返回 None——实例化得到 None（且 __init__ 不会执行，因为 None 不是 cls 的实例）。这是重写 __new__ 的第一大坑。
9. 以下代码的输出是？ 
class PositiveInt:
    def __new__(cls, value):
        if value < 0:
            return 0
        return super().__new__(cls)

    def __init__(self, value):
        print("__init__ 被调用")
        self.value = value

p = PositiveInt(5)
n = PositiveInt(-3)
print(type(p).__name__, type(n).__name__)
PositiveInt(5) 正常：__new__ 返回本类实例 → __init__ 执行（打印一次）；PositiveInt(-3)：__new__ 返回 int 的 0 → __init__ 被跳过（不再打印）。所以 type(p) 是 PositiveInt、type(n) 是 int，__init__ 只打印一次。

最终考核

下面是《10.对象的创建过程》源课程作业（自己写一遍单例模式）的四道改编题——这就是本课的最终考核。规则：不查资料、不运行代码，先在心里算出答案，再点击核对。

考核一（作业·单例实现）：实现单例类 Database——多次实例化返回同一个对象。下列 __new__ 中正确的是？
正确答案：cls._instance is None 时调用 super().__new__(cls) 创建并缓存，最后无条件 return cls._instance——第一次创建、之后复用。第二个忘了 return，实例化得到 None ✗；第三个不缓存，每次都是新对象 ✗；第四个条件写反 ✗。
查看源课程参考答案（作业·单例模式） 
class Database:
    _instance = None

    def __new__(cls, *args, **kwargs):
        if cls._instance is None:
            cls._instance = super().__new__(cls)
        return cls._instance

conn1 = Database()
conn2 = Database()
print(conn1 is conn2)  # True，说明是同一个实例
考核二（正整数类预测）：以下代码输出是？ 
class PositiveInt:
    def __new__(cls, value):
        if value < 0:
            return 0
        return super().__new__(cls)

    def __init__(self, value):
        print("__init__ 被调用")
        self.value = value

n = PositiveInt(-3)
print(type(n))
print(n)
__new__ 对负数直接 return 0——返回的是 int 实例，不是 PositiveInt 实例，isinstance 检查失败 → __init__ 被跳过（不打印）。type(n) 是 int，n 是 0。
考核三（对象池预测）：以下代码输出是？ 
class ConnectionPool:
    _pool = {}

    def __new__(cls, conn_id):
        if conn_id not in cls._pool:
            cls._pool[conn_id] = super().__new__(cls)
        return cls._pool[conn_id]

pool1 = ConnectionPool("conn_1")
pool2 = ConnectionPool("conn_1")
pool3 = ConnectionPool("conn_2")
print(pool1 is pool2, pool1 is pool3)
缓存键是 conn_id：pool1 创建并缓存 "conn_1"；pool2 命中缓存 → pool1 is pool2 → True；pool3 用新键 "conn_2" → 新对象 → pool1 is pool3 → False。输出：True False。
考核四（机制理解）：单例类 Database 实例化两次，__init__ 会被调用几次？（假设定义了 __init__ 且单例用 _instance 缓存）
这是单例的经典坑：__new__ 每次返回同一个实例，而实例是 cls 的实例（isinstance 通过），所以 __init__ 每次实例化都会执行——第二次创建会覆盖第一次的属性（如 host）。需要时可在 __init__ 里加「已初始化」标志跳过。
