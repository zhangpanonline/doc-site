本课目标

完成本课后，你将能：

  1. 说清 token 统计为什么分「事前统计」与「事后统计」，各自在哪个环节拿到数
  2. 复述事前统计的四个落地场景：长度拦截、额度预校验、预算审批、报价展示
  3. 会用三条统计路线——服务商 API 接口、tiktoken、transformers，并说清各自的适用边界
  4. 解释 len(text) 与 token 数为什么不同，把 token 数接到上下文窗口拦截与成本换算上

知识速览

先花几分钟把 token 统计的时机、路线与换算过一遍——细节都在《08.token统计》里，测验和面试会考。

统计的时机：事前 vs 事后

  • 事后统计：调用模型服务商的 API 之后，服务商会告知本次 token 用量——数最准，但它只在你已经付过费、请求已经发出去之后才拿得到
  • 事前统计：把文本发给大模型之前先算出来，用于拦截与预估；课件的四个典型场景都靠它
  • ① 单轮输入长度拦截：用户粘贴 10 万字合同，事前算出超 100k token，直接弹窗「文本过长，请分段上传」，不发起无效 API 调用
  • ② 用户额度 / 充值计费预校验：调用前预估总 token，额度不足直接拦截并提示充值，不用等 API 返回才告知超限
  • ③ 企业预算前置审批：本地算出预估 token 并换算成人民币成本，超过部门月度阈值就走审批再允许调用
  • ④ 报价前置展示：页面实时显示「本次预估消耗 XX token，约 XX 元」，用户确认后再执行，减少账单争议

三条统计路线，各有各的边界

  • 服务商 API 接口：某些服务商提供免费的 token 统计接口。课件以 Moonshot AI（Kimi）为例：POST https://api.moonshot.cn/v1/tokenizers/estimate-token-count，请求体传 model 与 messages，从 result['data']['total_tokens'] 取结果；需要 Authorization: Bearer <API Key>（Key 在 platform.moonshot.cn 申请，用 python-dotenv 从 .env 读）
  • tiktoken（SDK，本地）：OpenAI 官方的分词库。课件用 encoding = tiktoken.encoding_for_model("gpt-4o") 拿编码，tokens = encoding.encode(text) 得到 token 序列，len(tokens) 就是 token 数；首次运行会联网下载词表并缓存，之后统计完全在本地进行，无需 API Key
  • transformers（SDK，本地）：Hugging Face 的官方库，开源模型用它统计。课件用 AutoTokenizer.from_pretrained("deepseek-ai/DeepSeek-V3") 下载分词器文件（仅几 MB，不含模型权重），再 tokenizer.encode(text) 取 token 数
  • 国内网络：访问 Hugging Face 需配置镜像——课件里是 os.environ["HF_ENDPOINT"] = "http://hf-mirror.com"（能直连就删掉这行）

从 token 数到「钱」和「窗口」

  • 字符数不是 token 数：课件里同一段文本同时打印 len(text) 与 len(tokens)，两个数字并不相等；不同模型、不同语料的切法不一样，所以统计必须用目标模型配套的分词器
  • 成本换算：预估 token 数 × 服务商单价 = 预估成本；输入与输出通常分开计价，预估时要连输出上限一起算（课件「报价前置展示」「企业预算前置审批」都是这条链路）
  • 上下文窗口：把统计结果与模型的上下文上限比较，超限就分段/摘要，而不是发出去等报错——这是「单轮输入长度拦截」的实现方式
  • 预估值永远是估算：消息的角色、名称等结构本身也占 token，具体口径还会随模型更新变化，所以要用 API 返回的用量做对账校准

🌱 初级测验 · 概念

1. 按「什么时候算」，token 统计分成哪两类？
课件原文：Token 统计是指将一段文本序列转换为 Token 数量的过程，分为事前统计和事后统计。事后统计靠服务商 API 告知用量，事前统计是在把文本发送给大模型之前先算出来。
2. 「事后统计」的 token 用量数据从哪里来？
课件原文：事后统计——使用模型服务商的 API 接口会告知你本次 token 用量。它是最贴近账单的口径，但拿到它时请求已经发出去了。
3. 课件用 tiktoken 统计 token 时，哪一句真正拿到了 token 数？
encoding_for_model 只是按模型名加载编码（词表），encoding.encode(text) 把文本切成 token 序列（课件里打印为「Token 序列」），对它取 len() 才是 token 数——课件输出里「Token 数」这一行正是 len(tokens)。

🌿 中级测验 · 应用

4. 用户粘贴了一份 10 万字合同，产品要求「不发起无效 API 调用就拦住超长输入」，正确做法是？
课件「单轮输入长度拦截」原文：用户粘贴 10 万字合同，事前算出超 100k token，直接弹窗「文本过长，请分段上传」，不发起无效 API 调用。字符数不等于 token 数，截断则可能截掉有效内容——两者都不是拦截该有的做法。
5. tiktoken 第一次运行必须联网，之后却能完全离线统计，原因是？
课件注释原文：tiktoken 是 OpenAI 官方的分词库；首次运行会联网下载词表并缓存，之后统计完全在本地进行，无需 API Key。因为统计只需要词表，不需要模型权重，也不需要把文本发给任何人。
6. 要统计开源模型 DeepSeek-V3（分词器发布在 Hugging Face 上）的 token 数，最合适的是？
课件「transformers 库」一节：开源模型可以使用 transformers 库进行统计，以开源模型为例用 AutoTokenizer.from_pretrained(...) 加载配套分词器，再 tokenizer.encode(text)。tiktoken 是 OpenAI 模型的官方分词库，Moonshot 的接口算的是 Kimi 的 token，系数估算则会系统性偏离。

🎯 高级测验 · 综合

7. SaaS 产品要「上传文档后立刻显示预估 token 与费用，用户确认后再调用」，还要求预估与服务商账单口径尽量一致。架构上最稳的是？
课件给了三条统计路线（API 接口 / tiktoken / transformers）与「报价前置展示」「企业预算前置审批」两个场景：估值要与账单口径一致，就必须用目标模型自己的分词口径，再乘服务商单价；而事后拿到的用量（usage）是最权威的对账依据。先真实调用再报价会把成本转嫁给平台；只用本地估算而不校准，则会在模型更新后慢慢失真。
8. 为什么不能直接用 len(text) 代替 token 数做计费拦截与报价？
课件在两处同时观察这件事：一是每个统计示例都并排打印「文本长度：len(text)」与「Token 数：len(tokens)」，两个数不相等；二是三种路线的 token 数各自不同。同一个字符数，中英文切法不同、模型词表不同结果就不同，计费与窗口判断只能按 token 算。
9. 代码审查：工程师写 enc = tiktoken.encoding_for_model("kimi-k3") 来给 Kimi 模型的请求做预统计，运行直接抛 KeyError。最合理的根因与修法是？
课件把两条路线分得很清楚：tiktoken 是「OpenAI 官方的分词库」，按 encoding_for_model("gpt-4o") 这类 OpenAI 模型名取编码；而其它厂商的模型要在它自己的口径上统计——Kimi 用 Moonshot 的 estimate-token-count 接口，开源模型用 transformers 加载配套分词器。改成 gpt-4o 只是换了个词表算别家模型的账，数字依然不对。
