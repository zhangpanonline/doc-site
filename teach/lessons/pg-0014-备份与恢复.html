知识速览

先花几分钟把核心机制过一遍——细节与测验依据都来自官方文档 §25.1。

SQL 转储（官方要点）

  • 思想：创建由 SQL 命令组成的文件，回放后重建与转储时状态一样的数据库（官方原文）
  • 基本用法：pg_dump dbname > dumpfile（输出到标准输出）；恢复：psql dbname < dumpfile
  • pg_dump 是普通客户端应用——可在任何能访问该库的远端主机上备份（官方原文）
  • 特权：pg_dump 不跑特殊权限——必须对备份对象有读权限，备份全库几乎总要以超级用户运行

格式与工具

  • 纯文本外，pg_dump 支持其他格式——支持并行与细粒度的对象恢复（如单表恢复，官方原文）
  • pg_restore：从 custom 格式恢复，-t 表名 只恢复指定对象
  • pg_dumpall：转储整个集簇（含角色与表空间）

分级测验

即时反馈：点击选项立刻显示对错与解释。题目只考本课与官方文档覆盖的内容。

🌱 初级测验 · 概念

1. 官方说 SQL 转储方法的思想是？
官方原文：思想是创建一个由 SQL 命令组成的文件，回馈给服务器时重建与转储时状态一样的数据库。
2. pg_dump 的定位（官方）是？
官方原文：pg_dump 是一个普通的 PostgreSQL 客户端应用（尽管是个相当聪明的东西）。
3. 官方说 pg_dump 的输出默认去哪里？
官方原文：pg_dump 把结果输出到标准输出——因此基本用法是 pg_dump dbname > dumpfile。

🌿 中级测验 · 应用

4. 官方说 pg_dump 备份整个数据库几乎总要以什么身份运行？
官方原文：pg_dump 不会以任何特殊权限运行——必须有想备份的表的读权限，备份整个库几乎总要以超级用户运行。
5. 官方说 pg_dump 可以在哪里运行备份？
官方原文：你可以在任何可以访问该数据库的远端主机上进行备份工作——客户端应用的直接推论。
6. 只恢复一张表，官方推荐的工具链是？
官方原文：pg_dump 可以用其他格式创建文件以支持并行和细粒度的对象恢复——pg_restore -t 正是单表恢复姿势。

🎯 高级测验 · 综合

7. 「备份必须演练恢复」的原因是？
转储文件「能回放」才算备份——从未演练恢复的备份在灾难时才发现问题（权限/版本/损坏），等于没有备份。
8. pg_dumpall 与 pg_dump 的区别是？
pg_dump 按库转储；pg_dumpall 覆盖整个集簇——角色/表空间这类集簇级对象只能靠它。
9. pg_dump 是逻辑备份。什么场景它不够用（要上文件系统级/PITR）？
逻辑转储回放 = 重新执行全部 SQL——超大库恢复可能数小时；需要快速恢复用官方 §25.2/§25.3 的文件系统级备份或 PITR。

最终考核

四道题覆盖本课全部要点——答完它们，备份与恢复就过关了。

考核一：备份命令 pg_dump dbname > dumpfile 的正确恢复命令是？
转储文件是 SQL 命令流——用 psql 回放进目标库；方向别反。
考核二：备份时表正在被写入，pg_dump 的一致性靠什么保证？
pg_dump 在单事务快照下工作——转储的库是「某一时刻」的一致视图，写入不阻塞（MVCC 的应用）。
考核三：用非超级用户做部分备份（只备份自己的 schema），官方怎么说？
官方原文：没有足够特权备份整个库时，仍可使用诸如 -n schema 的方式限定范围——读权限决定能备份什么。
考核四：cron 里每天 pg_dump 到本地磁盘，还有哪些风险要补？
备份三件套：异机存储（防单点）、失败告警（备份静默失败是最危险）、恢复演练（能回放才算数）。

四道考核全部答对，说明你掌握了备份与恢复——继续学习 pg-15 · 日常维护。
