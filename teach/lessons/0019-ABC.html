抽象类规则

class Shape(ABC) ─ 不能实例化 ─▶ @abstractmethod 标记的接口 ─ 子类必须实现 ─▶ 全部实现后才能实例化

⚙️ 漏掉任意一个抽象方法，子类仍是抽象类；抽象类可以带普通方法（有默认实现）。

三个要点

  1. ABC + @abstractmethod 是接口契约：实例化抽象类直接 TypeError；子类缺实现也 TypeError——在创建对象时就拦住错误，而不是运行时才发现。官方文档：abc
  2. 抽象属性：@property 在上、@abstractmethod 在下，顺序不能颠倒（@property @abstractmethod def salary）。
  3. 抽象类常用于插件接口：定义 connect/read/close 契约，具体数据源各自实现，调用方只依赖抽象类型——考核一、二的思路。

🌱 初级测验 · 概念

1. 定义抽象类的标准做法是？
抽象类继承 abc.ABC，抽象方法用 @abstractmethod 标记。两者配合，实例化时才会被拦截。详见「定义抽象类」一节。
2. 直接实例化抽象类会怎样？
Animal() 抛 TypeError: Can't instantiate abstract class ...——抽象类的存在意义就是「只当契约，不当实例」。详见「抽象类基础示例」。
3. 抽象类中可以包含普通方法吗？
抽象类可以有普通方法（默认实现），子类直接继承使用——如 Sequence 的 is_empty 就是普通方法。详见「定义抽象类」要点。

🌿 中级测验 · 应用

4. 子类只实现了部分抽象方法，会发生什么？
漏掉任意抽象方法，子类仍是抽象类——实例化抛 TypeError。详见「子类必须实现所有抽象方法」一节。
5. 抽象属性 salary 的装饰器顺序是？
抽象属性写法：@property 在上、@abstractmethod 在下，顺序不能颠倒。详见「抽象属性」一节。
6. 抽象类最典型的应用场景是？
抽象类常用于插件接口/框架扩展点：如 DataSource 定义 connect/read/close，MySQL/MongoDB 各自实现，调用方只认抽象类型。详见「实际应用场景」一节。

🎯 高级测验 · 综合

7. class B(A) 实现了全部抽象方法，class C(B): pass。C 能实例化吗？
抽象方法沿继承链生效：B 已实现全部抽象方法，B 及其子类 C 都不是抽象类——C 可直接实例化，调用方法沿 MRO 找到 B 的实现。详见「子类必须实现所有抽象方法」一节。
8. 多态场景：process_data(source: DataSource) 接收抽象类型，传 MySQLSource 与 MongoDBSource 都能工作，靠的是？
抽象类契约 + 多态：两个数据源都实现了 connect/read/close 三个抽象方法（否则实例化都过不去），调用方才能「面向抽象编程」——这就是插件接口模式的完整闭环。
9. 抽象基类里定义的普通方法 describe 内部调用了抽象方法 self.area()，子类只实现 area 后调用 describe，会发生什么？
模板方法模式：self.area() 是动态分发——运行时沿实例类型找到子类的实现（子类已实现 area 才能实例化）。这就是抽象类普通方法的价值：骨架放基类、细节留给子类。详见「定义抽象类」的 describe 示例。

最终考核

下面是《19.ABC》源课程作业的改编题——这就是本课的最终考核。规则：不查资料、不运行代码，先在心里选出正确实现，再点击核对。

考核一（作业一·抽象缓存）：抽象基类 Cache 声明 get/set/delete 三个抽象方法，MemoryCache 用字典实现。下列做法中正确的是？
正确做法：MemoryCache(Cache) 继承抽象基类，三个方法全部实现（get → dict.get(key)；set → 赋值；delete → del）。第二个不继承就失去契约约束 ✗；第三个漏实现，实例化直接 TypeError ✗；第四个没有强制力 ✗。
查看源课程参考答案（作业一·MemoryCache） 
from abc import ABC, abstractmethod

class Cache(ABC):
    @abstractmethod
    def get(self, key): pass

    @abstractmethod
    def set(self, key, value): pass

    @abstractmethod
    def delete(self, key): pass

class MemoryCache(Cache):
    def __init__(self):
        self._data = {}

    def get(self, key):
        return self._data.get(key)

    def set(self, key, value):
        self._data[key] = value

    def delete(self, key):
        if key in self._data:
            del self._data[key]

考核二（作业二·抽象序列）：Sequence 声明 append/get/length/__iter__ 四个抽象方法，并带普通方法 is_empty（return self.length() == 0）。实现 ListSequence 时正确的是？
ListSequence 实现四个抽象方法（__iter__ 直接 return iter(self._data)），普通方法 is_empty 自动继承。第二个重复劳动 ✗；第三个漏两个方法，实例化 TypeError ✗；四个抽象方法必须全部实现。
查看源课程参考答案（作业二·ListSequence） 
class Sequence(ABC):
    @abstractmethod
    def append(self, item): pass

    @abstractmethod
    def get(self, index): pass

    @abstractmethod
    def length(self): pass

    @abstractmethod
    def __iter__(self): pass

    def is_empty(self):
        return self.length() == 0

class ListSequence(Sequence):
    def __init__(self):
        self._data = []

    def append(self, item):
        self._data.append(item)

    def get(self, index):
        return self._data[index]

    def length(self):
        return len(self._data)

    def __iter__(self):
        return iter(self._data)

考核三（作业三·思考题）：class B(A) 实现了 foo；class C(B): pass。执行 c.foo(); c.bar()（bar 是 A 的普通方法），输出是？
C 没写任何方法，但 B 已实现抽象方法 foo，所以 C 可以实例化。调用沿 MRO 查找：c.foo() → B.foo（输出 B.foo）；c.bar() → A.bar（普通方法，输出 A.bar）。顺序：B.foo → A.bar。
考核四（思考题第二问）：class D(A): pass（A 有抽象方法 foo，D 不实现），执行 d = D() 会怎样？
D 没有实现抽象方法 foo，仍是抽象类——实例化抛 TypeError: Can't instantiate abstract class D with abstract method foo。错误在创建对象时就暴露，这正是抽象类的价值。
