本课目标

完成本课后，你将能：

  1. 按课件「核心关注点」三方面审一段业务代码：代码组织、功能逻辑、边界
  2. 说清 Service 类模式与 BaseService 的复用价值，跑通三个 Service 的 CRUD 流程
  3. 用 BusinessException/DatabaseException 把底层异常翻译成业务语言
  4. 守住 DTO 边界：入参 Create/Update、返回 Response/Brief，ORM 对象不越过 service 层

知识速览

先花几分钟把核心机制过一遍——细节都在《07.业务逻辑》里，测验和面试会考。

代码组织：类模式 + 异常体系

  • BaseService：所有 Service 继承它，构造器共享 self.db: AsyncSession
  • PageResult[T]：统一分页返回 items/total/page/page_size
  • BusinessException：message（对外）/ detail（对内）/ original_exception（追溯根因）
  • DatabaseException：捕获 sa_exc.IntegrityError 后翻译成业务语言（「关联的分类不存在」「SKU编码重复」）

边界：DTO 进出、ORM 不外泄

  • 入参：Create/Update DTO（Field 约束即验证）；Update 用 model_dump(exclude_unset=True) 只更新传入字段
  • 返回：Response（详情）/ Brief（列表嵌套）/ PageResult（分页），from_attributes + model_validate 把 ORM 对象转 DTO
  • 内部方法：_get_*_orm 私有方法返回 ORM 对象供更新/删除——ORM 只在 service 内部流转
  • 不耦合接口层：service 不 import FastAPI 的 Request/Response/HTTPException

分级测验

即时反馈：点击选项立刻显示对错与解释。题目只考本课与《07.业务逻辑》覆盖的内容。

🌱 初级测验 · 概念

1. 课件「核心关注点」包括哪三个方面？
课件三条：① 代码组织（类模式还是函数模式？异常怎么处理？）；② 功能逻辑是否正确（功能全不全？重要的验证做没做？）；③ 边界是否清晰（入参和返回的是什么？是否耦合了接口层的东西？）。
2. 课件 service 层用的是类模式还是函数模式？
课件代码：ProductService/CategoryService/SkuService 都继承 BaseService，构造器接收 AsyncSession 存到 self.db。
3. 所有自定义业务异常从哪个类派生？它带哪些信息？
课件 exception/base.py：message 可展示给用户；detail 供开发排查；original_exception 保留原始异常。上层可 except BusinessException 统一捕获。

🌿 中级测验 · 应用

4. BaseService 里共享的是什么？
课件 base.py：class BaseService 的 __init__(self, db: AsyncSession): self.db = db——业务逻辑基类，所有 Service 继承此类共享 session。
5. create_product 的返回类型是什么？为什么？
课件边界关注点：入参和返回的是什么？service 对外的返回一律是 schema DTO（from_attributes + model_validate 转换），ORM 对象只在 service 内部流转。
6. 插入关联分类时捕获 IntegrityError 后做什么？
课件 product_service.py：except sa_exc.IntegrityError as e → raise DatabaseException(message="关联的分类不存在", detail=str(e), original_exception=e) from e——对外给用户可读信息，对内保留根因。

🎯 高级测验 · 综合

7. update_product 里 model_dump(exclude_unset=True) 的作用是？
课件注释「仅更新传入的字段」：exclude_unset=True 丢弃未显式设置的字段——否则 update 会把 name=None 之类写进数据库。
8. list_products 的分页是怎么实现的？
课件 list_products：select(func.count()).select_from(query.subquery()) 拿 total；offset=(page-1)*page_size 后 limit(page_size).order_by(id.desc()) 取当页；PageResult 统一返回。
9. 为什么要有 _get_product_orm 这种私有方法，而公开方法只返回 DTO？
课件边界关注点：update/delete 需要 ORM 对象（改属性、级联删除），但公开 API 返回 DTO——私有方法把 ORM 获取逻辑收拢在内部，ORM 不越过 service 边界。
