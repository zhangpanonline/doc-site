  • 工程基础（uv/monorepo/断点调试）→ ch01/02

就业市场画像（课件）

  • 全栈岗位：CRUD → 安全与性能 → 理解中间件 → 统一异常 → 增量测试 → 关键业务日志
  • 共同底座：本课程的 24 章恰好覆盖两个岗位的交集

分级测验

🌱 初级测验 · 概念

1. 课件的通过标准是多少道肯定？
课件：27 个问题 22 个肯定即可——无障碍学后续 AI 课程、超越绝大部分企业要求、高质量完成工作任务。
2. 能力检验的默认前提是什么？
课件原文：你是否能借助 AI、课件、课程视频，可控的完成下面的事项——检验的是工程交付能力（会查、会用、能完成），不是背诵。
3. AI 岗位画像里排第一的需求是？
课件 AI 岗位清单第一条：专注于 AI 能力——岗位的核心是模型与智能能力，Web 技能是「把 AI 能力交付出去」的载体（API/日志/流式/落库/测试）。

🌿 中级测验 · 应用

4. 「给你任意一个函数，把它暴露成 API 接口」考的是哪几章的能力？
检验题 10 的完整动作：定义 DTO（ch02）→ service 封装（ch07）→ APIRouter+Depends（ch08）→ 异常与信封（ch09/10）→ 测试（ch11/12）——一道题串五章。
5. 全栈岗位「理解现有中间件的作用与影响」为什么重要？
课件全栈清单：能理解现有的各个中间件的作用，以及它们产生的影响——存量项目里中间件（信封/耗时/CORS/日志）承载大量约定，新需求要顺着它们改而不是绕开。
6. 检验题 26「有信心通过官方文档上手 Flask/Django」考的是什么？
24 章学的 ASGI/中间件/依赖注入/ORM/模板引擎是 Web 框架通用概念——Flask/Django 只是同概念的不同 API（题源协议 B 的「官方文档一手」习惯此时变现）。

🎯 高级测验 · 综合

7. 检验题 17 问「长事务短事务」，本课程跳过的那章是什么？
课程编号跳号正是 16/19（无课件）：16 长事务和短事务——性能维度的会话策略，其基础（ch05 的执行时机、连接池 ch03）已学；19 AI导购。
8. 两个岗位画像的交集是什么？
对照两份清单：AI 岗位要「暴露 API/日志/流式/落库/测试」，全栈要「CRUD/安全/中间件/异常/测试/日志」——测试、日志、异常、API 四个词两边都出现，就是本课程的骨干。
9. 检验题 27「没见过的 API 借助 AI 快速理解」的正确姿势是？
与题源协议 B 同构：AI 解释 + 官方文档锚定 + 实测验证——本课程每道面试题的来源标注（URL+检索日期）就是「借助 AI 可控完成」的示范。
