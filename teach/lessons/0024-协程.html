知识速览

先花一分钟把核心关系过一遍——细节都在《24.协程》里，测验会考。

async def 协程函数 ─ 调用 ─▶ 协程对象（惰性，未执行）
协程对象 ─ 包装 ─▶ Task（Future 的子类）
Task ─ await ─▶ Future 未完成，协程挂起
Future 完成 ─ 回调 ─▶ Task 恢复执行
Task 完成 ─ 返回 ─▶ 协程的返回值

⚙️ 事件循环（Event Loop）在幕后调度所有 Task 与 Future；asyncio.run 创建它并运行至协程结束。

三个要点

  1. 调用 ≠ 执行：调用 async def 函数只得到一个协程对象，函数体不会立即运行——必须交给事件循环（或 Task）驱动。官方文档：Coroutines
  2. Task 是 Future 的子类，专为驱动协程而生：create_task 创建后协程立即被调度执行；协程执行结束，Task 完成，完成的数据即协程的返回值。官方文档：Awaitables
  3. await = 交出控制权 + 取回结果：只能在协程函数内使用，等待协程对象、Task、Future 等 awaitable，完成后把结果取回给当前协程。

基础测验

点击选项立即获得反馈。答错也没关系——仔细读解释，它会把文档里对应的小节指给你。

1. 调用一个 async def 定义的协程函数，会得到什么？
调用协程函数只会返回一个协程对象，函数体并不会立即执行——它需要被事件循环（或 Task）驱动才会真正运行。回看《24.协程》「协程函数」一节。
2. await 关键字的作用是什么？
await 只能在协程函数内使用：它等待协程对象、Task、Future 等 awaitable 完成，并把结果取回给当前协程。它既不创建线程，也不会让事件循环永久阻塞。
3. 关于 Task 与 Future 的关系，正确的是？
Task 是 Future 的子类，专门用来驱动协程对象；asyncio.create_task() 创建后，协程会被立即调度执行。协程执行结束，Task 完成，完成的数据就是协程的返回值。
4. 协程切换比线程切换便宜得多，主要原因是？
线程切换需要陷入内核态，开销数百个时钟周期；协程由事件循环在用户态调度，只保存少量寄存器上下文，仅需几十个时钟周期。详见文档「协程 VS 线程」对比表。
顺序预测5. 以下代码的输出顺序是？ 
async def main():
    print("A")
    await async_delay(1)
    print("B")

print("C")
asyncio.run(main())
print("D")
调用 main() 只是创建协程对象，所以先打印 C；asyncio.run 驱动协程：打印 A → await 挂起等待延时完成 → 打印 B；协程结束后 run 返回，最后打印 D。

进阶挑战

这三题把「调度」和「场景」合在一起考，是协程理解的分水岭。

顺序预测6. 以下代码的输出顺序是？ 
async def main():
    print("A")
    task = asyncio.create_task(worker())
    await asyncio.sleep(0)
    print("B")
    await task

async def worker():
    print("C")
create_task 把 worker 放进就绪队列，不会立即执行；await asyncio.sleep(0) 让出控制权后，worker 才开始运行打印 C，main 恢复后打印 B。这就是「Task 创建后立即调度」的确切含义。
场景7. 同时爬取一千个网页，最合适的技术是？
爬虫是典型的海量 I/O 密集任务——成千上万个协程的开销远小于几百个线程，且单线程内天然避免数据竞争。这正是协程的主场（Web 服务器、聊天服务同理）。
8. 驱动协程对象执行的机制是？
驱动协程的是事件循环：它负责调度 Task 与 Future；asyncio.run 内部就是创建事件循环，把协程包装成 Task 并驱动其完成。

最终考核

下面是《24.协程》源课程作业的两道实现题改编——这就是本课的最终考核。规则：不查资料、不运行代码，先在心里选出正确实现，再点击核对。作业引用的 async_delay 等 demo 代码已内嵌在折叠区。

考核一（源作业·实现 gather）：用 Future 手写 gather(*aws)——并发执行多个协程，全部完成后按传入顺序返回结果列表。下列实现中正确的是？
正确实现：results = [None] * count 按索引存结果（闭包捕获 idx）；create_task(aw) 包装协程并注册完成回调；finish_count == count 时 future.set_result(results)。第二个顺序错（gather 语义是按传入顺序）✗；第三个协程没被调度，永远等不到 ✗；第四个提前完成，漏最后一个结果 ✗。
查看内嵌 demo 与参考答案（作业一） 
# async_delay.py（课程前文封装，gather 的底层依赖）
import asyncio

def async_delay(duration: int):
    loop = asyncio.get_event_loop()
    future = loop.create_future()
    loop.call_later(duration, future.set_result, None)
    return future

# gather.py（参考答案）
import asyncio
from typing import Coroutine

def gather(*aws: Coroutine) -> asyncio.Future:
    future = asyncio.Future()
    finish_count = 0
    count = len(aws)
    results = [None] * count

    def on_done(f: asyncio.Future, idx: int) -> None:
        nonlocal finish_count
        results[idx] = f.result()          # 按索引存储
        finish_count += 1
        if finish_count == count:
            future.set_result(results)

    for i, aw in enumerate(aws):
        asyncio.create_task(aw).add_done_callback(lambda f, idx=i: on_done(f, idx))

    return future

async def coro(name: str, duration: int):
    await async_delay(duration)
    return f"{name} 完成"

async def main():
    results = await gather(coro("A", 2), coro("B", 1), coro("C", 3))
    print(results)  # ['A 完成', 'B 完成', 'C 完成']
考核二（源作业·实现 Event）：手写 Event 类——wait() 挂起当前协程，set() 唤醒所有等待者。下列实现中正确的是？
正确实现：wait() 里 self._fut = loop.create_future() 然后 await self._fut（挂起直到 set）；set() 里 if self._fut: self._fut.set_result(None)（None 判空防止没等待者时崩溃）。第二个没 await 就不挂起 ✗；第三个空指针 ✗；第四个复用已完成的 Future 会立即返回，第二次 wait 不再等待 ✗。
查看内嵌参考答案（作业二·Event.py） 
import asyncio
from async_delay import async_delay
from gather import gather

class Event:
    def __init__(self):
        self._fut = None

    def set(self):
        if self._fut:
            self._fut.set_result(None)

    async def wait(self):
        loop = asyncio.get_running_loop()
        self._fut = loop.create_future()
        await self._fut

async def test():
    event = Event()

    async def waiter():
        print("waiter: 开始等待")
        await event.wait()
        print("waiter: 被唤醒")

    async def setter():
        print("setter: 1秒后设置事件")
        await async_delay(1)
        event.set()
        print("setter: 事件已设置")

    await gather(waiter(), setter())
# 输出：waiter 开始等待 → setter 1 秒后设置事件 → waiter 被唤醒
考核三（顺序预测）：gather(coro("A", 2), coro("B", 1), coro("C", 3))——B 最先完成、C 最后完成。返回的 results 是？
gather 的语义：并发执行，结果按传入顺序返回。虽然 B 1 秒先完成，结果仍按 A、B、C 的位置排列——这就是「按索引存储」而不是「按完成顺序 append」的原因。
