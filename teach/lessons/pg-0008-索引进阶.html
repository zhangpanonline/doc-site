索引进阶

来源：官方文档 §11.8 部分索引 + §11.3 多列索引（postgres.cn）非渡一课程内容预计 15–20 分钟9 道分级测验 + 4 道最终考核 + 面试实战

本课目标

完成本课后，你将能：

  1. 说出部分索引的定义（谓词定义的子集）与主要动机（官方：避免索引常见值）

知识速览

先花几分钟把核心机制过一遍——细节与测验依据都来自官方文档 §11.8 与 §11.3。

部分索引（官方要点）

  • 定义：建立在表子集上，子集由谓词（WHERE 条件）定义
  • 主要动机（官方原文）：避免索引常见值——常见值查询不走索引，没必要留在索引里
  • 收益：减小索引尺寸、加速查询、加速表更新（不必每次都维护索引）
  • 官方 access_log 例：排除内网 IP 范围——外网 IP 查询走索引、内网 IP 查询不能用该索引
  • 前提：常见值可预知——数据分布不变最适合；分布变化要重建索引

多列索引（官方要点）

  • 官方例：CREATE INDEX ON test2 (major, minor) 服务 WHERE major = c AND minor = c
  • B-tree/GiST/GIN/BRIN 支持；最多 32 列（含 INCLUDE 列）
  • 可服务「索引列任意子集」的查询，但对前导（最左侧）列有约束时效率最高（官方原文——最左前缀出处）
  • INCLUDE 列：非关键列随索引存储（B-tree），覆盖查询免回表

分级测验

即时反馈：点击选项立刻显示对错与解释。题目只考本课与官方文档覆盖的内容。

🌱 初级测验 · 概念

1. 官方说使用部分索引的「一个主要原因」是？
官方原文：使用部分索引的一个主要原因是避免索引常见值——常见值查询本就不走索引。
2. 部分索引的「部分」由什么定义？
官方原文：部分索引建立在表的子集上，该子集由条件表达式（谓词）定义。
3. 多列索引对哪类查询效率最高（官方原文）？
官方原文：当对前导（最左侧）列有约束时，多列 B-tree 索引的效率最高——「最左前缀」的官方出处。

🌿 中级测验 · 应用

4. 部分索引带来的两个收益是？
官方原文：减小索引尺寸、加速使用它的查询；也加速很多表更新操作（索引不需要在所有情况下都被更新）。
5. 官方 access_log 例：查询内网 IP 会发生什么？
官方原文：内网 IP 的查询无法使用部分索引——因为它使用从索引中排除的地址。
6. 官方说部分索引最适合什么场景？
官方原文：部分索引要求常见值能被预知——最适合数据分布不会改变的情况；分布变化要重建（有维护负担）。

🎯 高级测验 · 综合

7. 多列索引的列数上限是（官方）？
官方原文：索引最多可以有 32 列，包括 INCLUDE 列（限制可在源码里修改）。
8. INCLUDE 列的作用是？
INCLUDE 列不参与索引键的排序/查找，但随索引存值——SELECT 只查关键列+INCLUDE 列时 Index Only Scan 免回表。
9. 订单表 90% 行是 status='done'，高频查询只查未完成订单。最佳索引是？
done 是常见值（90%）——按官方「避免索引常见值」原则，只为未完成的 10% 建部分索引：小、快、更新负担轻。

最终考核

四道题覆盖本课全部要点——答完它们，索引进阶就过关了。

考核一：日志表要按 (url, ip) 查外部访客、内网流量占 95%。官方推荐的索引方案是？
官方原例的直接应用：排除内网常见值——索引只覆盖 5% 的有价值行。
考核二：查询是 WHERE a = ? AND b = ?，另有 WHERE a = ? 的查询。索引 (a, b) 与 (b, a) 选哪个？
两种查询都以 a 为条件：a 作前导列时两种查询都能高效利用（官方：前导列有约束时效率最高）。
考核三：SELECT name FROM t WHERE major = 1 AND minor = 2，索引 (major, minor) INCLUDE (name) 的好处是？
查询列全部在「关键列 + INCLUDE 列」里 → 不用回表拿行——覆盖查询的标准配置。
考核四：部分索引的谓词数据分布变了（常见值变了）怎么办？
官方原文：这样的索引可以偶尔被重建来适应新的数据分布，但会增加维护负担。

四道考核全部答对，说明你掌握了索引进阶——继续学习 pg-09 · 全文检索。
