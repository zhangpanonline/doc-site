日志

配合《18.日志》使用预计 15–20 分钟9 道分级测验 + 面试实战

本课目标

完成本课后，你将能：

  1. 说清生产 JSON / 开发文本双模式配置与环境变量的分工
  2. 讲出三类日志（请求/数据库/业务）各自的字段与输出位置
  3. 读通 LogRecord：自动计时 duration_ms、request_id 注入、级别方法族
  4. 说清 service_logger 装饰器的成败分支（业务异常 warning、未知异常 error+exc）

知识速览

先花几分钟把核心机制过一遍——细节都在《18.日志》里，测验和面试会考。

配置与输出（课件）

  • 七级：TRACE/DEBUG/INFO/SUCCESS/WARNING/ERROR/CRITICAL（loguru 扩展了 SUCCESS）
  • 生产：stdout + JSON（serialize=True）——对接云日志系统
  • 开发：stdout 彩色文本 + ERROR 落 errors.log（rotation 10MB / retention 7 天）
  • 级别走环境变量（log_settings.level）；配置在启动时完成（uvicorn 不再打印到控制台）

三类日志（类结构约定字段）

  • 共同：message + duration_ms；request_id 由 ContextVar 注入全链路
  • 请求日志（中间件）：method/path/status_code/client_ip；成功 success()，500 error() 其余 warning()
  • 数据库日志（SQLAlchemy 事件）：before_cursor_execute 计时、after 记 sql/params；慢查询（超阈值）warning
  • 业务日志（service_logger 装饰器）：action/entity/entity_id；成功 success、BusinessException warning、未知异常 error+exc

分级测验

即时反馈：点击选项立刻显示对错与解释。题目只考本课与《18.日志》覆盖的内容。

🌱 初级测验 · 概念

1. 课件生产环境的日志配置是？
课件「配置什么」生产环境：输出方式固定 stdout（方便对接云服务日志系统）、输出级别环境变量配置、输出格式统一 JSON（方便解析）。
2. loguru 比标准 logging 多出来的级别是？
课件七级：TRACE/DEBUG/INFO/SUCCESS/WARNING/ERROR/CRITICAL——SUCCESS 用于「操作成功」语义，请求成功 log.success() 就是用它。
3. logger.bind(request_id="abc-123") 的作用是？
课件：logger.bind 绑定额外的自定义信息——格式串里的 {extra[request_id]} 就取自这里；本课用 ContextVar 全链路注入 request_id 后 setdefault 进 extra。

🌿 中级测验 · 应用

4. 三类日志的差异字段分别是？
课件「输出什么」：共同数据 message+duration_ms；请求日志 method/path/status_code/client_ip；数据库日志 sql/params；业务日志 action/entity/entity_id——用类结构约定字段（dataclass 继承 LogRecord）。
5. LogRecord 的 duration_ms 是怎么算的？
课件 log_record.py：__post_init__ 记 _start_time=perf_counter()；_emit 里 extra 没有 duration_ms 就 round((now-start)*1000, 2)——对象创建到输出之间的耗时自动结算。
6. 数据库日志在 SQL 执行「前」计时，为什么不在执行后？
课件：注册 SQLAlchemy 事件监听器，执行 SQL 前计时，执行后创建日志对象——before/after_cursor_execute 一对事件包围查询，duration_ms 就是这个包围区间的真实耗时；超过阈值（log_settings.slow_query_threshold）输出 warning。

🎯 高级测验 · 综合

7. 请求失败时，500 和 4xx 的日志级别为什么不同？
课件请求日志：500 错误输出 error，其他错误输出 warning——级别即「谁该背锅」：5xx 需要开发介入（error 且带异常），4xx 是业务预期（warning，避免告警疲劳）。
8. service_logger 装饰器里 BusinessException 和未知异常的处理为什么不同？
课件 business_log.py：isinstance(e, BusinessException) → log.warning()（ch07 业务体系，预期内）；否则 log.error(exc=e) → loguru 的 opt(exception=exc) 会把完整异常栈打进日志——两者都会 re-raise，日志是旁路不吞异常。
9. request_id 为什么要放 ContextVar 而不是全局变量？
课件：请求到达后「记录请求 id 到上下文，使得该请求链条中的所有日志都可以拿到该 id」——中间件 set 进 ContextVar，后续所有日志（含数据库/业务日志）_emit 时自动取回注入；并发下各请求互不串（ch17 的并发隔离演示）。
