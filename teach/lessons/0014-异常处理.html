知识速览

先花几分钟把核心机制过一遍——细节都在《14.异常处理》里，测验和考核会考。

try 语句四件套

子句触发时机
try监控的代码块
except捕获匹配的异常（可多个、可带 as e）
else没有异常时执行
finally无论是否异常都执行（清理资源）

三个要点

  1. 异常是继承树：ZeroDivisionError ⊂ ArithmeticError ⊂ Exception。捕获父类会连子类一起捕获；except 顺序应先具体后宽泛。官方文档：Exception hierarchy
  2. 自定义异常继承 Exception：class InsufficientFundsError(Exception)，用 raise 抛出，调用方按类型精确捕获。官方教程：User-defined Exceptions
  3. 异常链：except 里 raise 裸抛保留原上下文（__context__）；raise B from e 显式关联（__cause__）。

基础测验

点击选项立即获得反馈。答错也没关系——仔细读解释，它会把文档里对应的小节指给你。

1. else 子句什么时候执行？
else 只在 try 没有抛出异常时执行；finally 才是无论怎样都执行。详见「异常的捕获」一节。
2. except Exception 能捕获 ZeroDivisionError 吗？
异常有层次结构：ZeroDivisionError → ArithmeticError → Exception。捕获父类会连子类一起捕获——但应尽量精确捕获。详见「异常类型」一节。
3. except 里写 raise（不带任何异常）表示？
裸 raise 重新抛出当前异常（常用于记录日志后继续上抛）。详见「主动抛出异常」一节。
4. 自定义异常的规范做法是？
自定义异常继承 Exception（常规异常基类）；BaseException 还包含 SystemExit/KeyboardInterrupt，不应用于业务异常。详见「自定义异常」一节。
5. raise RuntimeError("B") from e 后，B.__cause__ 是？
from e 显式关联异常链：新异常的 __cause__ 指向 e。不用 from 的隐式关联则只设置 __context__。详见「异常链」一节。
6. 多个 except 子句的书写顺序建议是？
匹配按书写顺序进行：父类在前会把子类异常「抢走」，后面的 except 永远不执行。应先具体后宽泛。

最终考核

下面是《14.异常处理》源课程作业的三道实现题改编——这就是本课的最终考核。规则：不查资料、不运行代码，先在心里选出正确实现，再点击核对。

考核一（作业一·安全除法）：safe_divide 要求——除以 0 返回 0；参数类型错误打印 "参数类型错误" 并返回 None。下列实现中正确的是？
正确结构：try: return a / b，except ZeroDivisionError: return 0，except TypeError: print("参数类型错误"); return None。两种异常类型不同，顺序其实无碍，但分别处理返回不同结果才是题意 ✗（第二个：顺序反了不影响这两个类型，但打印语义错位；第三个把 TypeError 也当 0，返回值错；第四个直接崩）。
查看源课程参考答案（作业一） 
def safe_divide(a, b):
    try:
        return a / b
    except ZeroDivisionError:
        return 0
    except TypeError:
        print("参数类型错误")
        return None

print(safe_divide(10, 2))    # 5.0
print(safe_divide(10, 0))    # 0
print(safe_divide("10", 2))  # 参数类型错误
                             # None
考核二（作业二·重试装饰器）：@retry(max_attempts=3, delay=1)——函数抛异常则等 delay 秒重试，最多重试 3 次，最后一次仍失败则抛出该异常。下列实现中正确的是？
正确结构：for attempt in range(1, max_attempts + 1): try: return func(...) except Exception as e: if attempt == max_attempts: raise; time.sleep(delay)——成功即返回；最后一次失败重新抛出。第二个吞异常 ✗；第三个没重试 ✗；第四个没等待也没重试 ✗。
查看源课程参考答案（作业二） 
import time

def retry(max_attempts, delay=1):
    def decorator(func):
        def wrapper(*args, **kwargs):
            for attempt in range(1, max_attempts + 1):
                try:
                    return func(*args, **kwargs)
                except Exception as e:
                    if attempt == max_attempts:
                        raise
                    time.sleep(delay)
        return wrapper
    return decorator
考核三（作业三·银行账户）：withdraw 要求——冻结抛 AccountFrozenError；金额 ≤ 0 抛 ValueError；余额不足抛 InsufficientFundsError；成功后扣款。下列实现中正确的是？
正确顺序：if self.frozen: raise AccountFrozenError(...) → if amount <= 0: raise ValueError(...) → if amount > self.balance: raise InsufficientFundsError(...) → 全部通过才 self.balance -= amount。第二个漏了两个条件 ✗；第三个余额永远不变 ✗；第四个 assert 可被 -O 优化掉，且类型不符题意 ✗。
查看源课程参考答案（作业三） 
class InsufficientFundsError(Exception):
    """余额不足"""
    pass

class AccountFrozenError(Exception):
    """账户已冻结"""
    pass

class BankAccount:
    def __init__(self, balance=0, frozen=False):
        self.balance = balance
        self.frozen = frozen

    def withdraw(self, amount):
        if self.frozen:
            raise AccountFrozenError("账户已冻结，无法取款")
        if amount <= 0:
            raise ValueError("取款金额必须大于零")
        if amount > self.balance:
            raise InsufficientFundsError("余额不足")
        self.balance -= amount
考核四（异常链预测）：raise RuntimeError("错误B") from e（e 是捕获的 ValueError）后，捕获 RuntimeError 时 __cause__ 与 __context__ 分别是？
from e 是显式关联：__cause__ 指向 e，__context__ 不设置（None）。对比：不用 from 的隐式关联只设置 __context__。详见「异常链」一节。
