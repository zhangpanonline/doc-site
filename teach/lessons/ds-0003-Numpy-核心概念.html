知识速览

先花几分钟把 ndarray 这个数据结构本身过一遍——细节都在《03.Numpy - 核心概念》里，测验和面试会考。

ndarray 与 Python 列表：三点区别

  • 同质化：所有元素必须是相同类型（同一个 dtype）——列表可以混杂字符串、整数、对象，ndarray 不行
  • 连续内存：数据存在一整块连续内存里，所以创建后总大小固定，不能像列表那样原地追加
  • 向量化运算：不用循环就能对整个数组做运算，循环被交给底层 C 去跑
  • 形状三件套：shape 是每个维度长度的元组，ndim 是维度个数（等于 shape 元组长度），size 是元素总数（等于 shape 各元素之积）

dtype：把 C 的类型系统暴露给 Python

  • dtype 就是 C 的类型：int64↔int64_t（8 字节）、int32↔int32_t（4 字节）、float64↔double（8 字节）、float32↔float（4 字节）、bool 1 字节
  • Python 的 int 是不定长对象（光对象头就 28+ 字节），ndarray 用 C 的定长类型才换来了连续存储与向量化
  • 内存账本：itemsize 是单个元素的字节数，总字节数 = size × itemsize；100 万个 float64 ≈ 7.63 MB，换成 float32 立刻降到 ≈ 3.81 MB
  • Agent 场景选型：Embedding 向量用 float32（省一半内存）、Token ID 用 int64、Mask 用 bool；object 要尽量避免，会丢掉向量化优势

strides 与 axis：内存怎么走，运算沿哪走

  • strides 是「在每个维度上前进一个元素要跳过的字节数」：int64 的 (2, 3) 数组步幅是 (24, 8) = (3×8, 1×8)
  • 转置是零拷贝的：arr.T 只是把步幅交换成 (8, 24)、shape 换成 (3, 2)，数据一个字节都没搬
  • 代价是它是视图：t[0, 0] = 99 会把原数组的 arr[0, 0] 一起改掉；要独立副本就用 arr.T.copy()
  • axis 是要被「压掉」的那一维：2D 数组 axis=0 按列（每列求和，结果长度=列数），axis=1 按行（每行求和，结果长度=行数）

🌱 初级测验 · 概念

1. ndarray 与 Python 原生列表的关键区别，主要是下面哪一组？
课件「ndarray」小节列出的正是这三点。官方文档的说法是：NumPy 只在处理「大量同类型（homogeneous）数据」时才真正发光——把 ndarray 当列表用（逐元素循环、混类型）就等于丢掉了它全部优势。
2. arr = np.array([[1, 2, 3], [4, 5, 6]])，那么 arr.shape、arr.ndim、arr.size 分别是？
shape 是「每个维度上的长度」元组：2 行 3 列 → (2, 3)；ndim 是维度个数 → 2；size 是元素总数 → 6，正好等于 shape 各元素之积（官方文档的等式 a.size == math.prod(a.shape)）。对应「shape（形状）」小节。
3. Agent 场景里，Embedding 向量、Token ID、Mask 通常分别用什么 dtype？
课件「Agent 场景」原文：Embedding 向量通常用 float32（比 float64 省一半内存）、Token ID 用 int64、Mask 用 bool（每元素只要 1 字节）。对应「dtype（数据类型）」小节。

🌿 中级测验 · 应用

4. 一个 ndarray 的 shape 是 (2, 3, 4)，它的 ndim 与 size 分别是？
ndim 是 shape 元组的长度——这里有 3 个维度，所以是 3（不是 2、也不是 4）。size 是各维度长度之积：2 × 3 × 4 = 24，与 math.prod(shape) 一致。注意 shape 不会「自动压缩」：即使某一维是 1（如课件的 (2, 3, 1)），它仍然算一个维度。对应「shape（形状）」小节。
5. arr = np.array([[1, 2, 3], [4, 5, 6]], dtype=np.int64)，步幅 strides 是 (24, 8)。执行 t = arr.T 之后，t.shape 与 t.strides 是？
转置只做两件事：shape 由 (2, 3) 变成 (3, 2)，strides 由 (24, 8) 交换成 (8, 24)。数据缓冲区一个字节都没动，所以 t 是 arr 的视图——t[0, 0] = 99 会把 arr[0, 0] 也改成 99。对应「strides（步幅）」小节，官方定义见 numpy.ndarray.transpose：Returns a view of the array with axes transposed。
6. arr 的形状是 (4, 5)。arr.sum(axis=1) 的结果形状是什么？它到底算的是什么？
axis 是要被「压掉」的那一维：axis=1 表示沿第二个维度走完整条行再把它们加起来，长度 5 的那一维消失，结果长度等于 axis=0 的长度 4，所以是 (4,)。课件例子：[[1, 2, 3], [4, 5, 6]] 的 sum(axis=1) → [6, 15]（每行），sum(axis=0) → [5, 7, 9]（每列）。对应「轴（axis）」小节。

🎯 高级测验 · 综合

7. 100 万个 float64 与 100 万个 float32，内存占用分别约为多少？
先看 itemsize：float64 对应 C 的 double（8 字节），float32 对应 C 的 float（4 字节）。100 万 × 8 B = 8,000,000 B ≈ 7.63 MB；100 万 × 4 B = 4,000,000 B ≈ 3.81 MB。NumPy 不做任何压缩——这正是 Embedding 选 float32 的动机。对应「dtype（数据类型）」小节。
8. 执行 np.array([1, 2, "a"], dtype=np.int64) 的结果是？
ndarray 是同质的：一旦显式指定 dtype=np.int64，每个元素都必须能转成 C 的 8 字节整数，"a" 转不了就直接报错（课件输出原文：invalid literal for int() with base 10: 'a'）。dtype 不会被悄悄放宽成 object——静默放宽只在你不指定 dtype、由 NumPy 自己推断时才可能发生。这条「禁止在同一数组里混类型」正是课件给出的最佳实践。对应「dtype（数据类型）」小节。
9. 一个 Agent 把 1000 条文本的 Embedding 存进 emb = np.zeros((1000, 768), dtype=np.float32)。这块缓冲占多少内存？想得到「每条文本的 768 维平均向量」，该用哪个 axis、结果形状是什么？
三笔账一起算：dtype float32 → itemsize 4，总字节 = size × itemsize = 1000×768×4 = 3,072,000 B ≈ 2.93 MB（若误用 float64 就会翻倍到约 5.86 MB）。axis 要把「每条文本」压成一个数，就要压掉 768 那一维，也就是 axis=1：结果形状 (1000,)；mean(axis=0) 得到的是「每个维度上的平均向量」，形状 (768,)，语义完全不同。对应「shape（形状）」「dtype（数据类型）」「轴（axis）」三节。
