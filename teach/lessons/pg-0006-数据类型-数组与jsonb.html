数据类型 · 数组与 jsonb

来源：官方文档 §8.14 数组 + §8.16 JSON 类型（postgres.cn）非渡一课程内容预计 15–20 分钟9 道分级测验 + 4 道最终考核 + 面试实战

本课目标

完成本课后，你将能：

  1. 定义数组列（类型名加 []），说出「尺寸声明被忽略」的官方细节
  2. 复述 json 与 jsonb 的两条官方区别（效率 / 保真度），背出「大多数应用应该用 jsonb」的官方结论
  3. 给 jsonb 建 GIN 索引并解释为什么 jsonb 能索引而 json 不能
  4. 用包含查询（@>）回答「哪些文档包含某字段」类问题

知识速览

先花几分钟把核心机制过一遍——细节与测验依据都来自官方文档 §8.14 与 §8.16。

数组（官方要点）

  • 列可以定义为变长多维数组（官方原文）；任意基类型都可做数组
  • 写法：类型名 + []（官方原例 integer[]、text[][]）
  • 尺寸声明被忽略：integer[3][3] 只是语法存在，当前实现不检查尺寸（官方原文）
  • 字面量 '{10000, 10000, 10000}'；@> 包含、ANY 遍历元素

json vs jsonb（官方两条区别）

  • 效率：json 存文本精准拷贝、每次处理重新解析；jsonb 存二进制分解格式、输入稍慢、处理快很多且支持索引
  • 保真度：json 保留空格/键顺序/重复键；jsonb 不保留——重复键只留最后一个
  • 官方结论：大多数应用应该更愿意把 JSON 数据存储为 jsonb
  • jsonb + GIN 索引 + @> 包含查询 = PG 当文档数据库的底气

分级测验

即时反馈：点击选项立刻显示对错与解释。题目只考本课与官方文档覆盖的内容。

🌱 初级测验 · 概念

1. 定义一维整数数组列的正确写法是？
官方原例：pay_by_quarter integer[]——数组类型就是元素类型名后面加方括号。
2. 官方对 integer[3][3] 尺寸声明的说法是？
官方原文：CREATE TABLE 语法允许指定确切大小，但当前的实现忽略任何提供的数组尺寸。
3. 官方建议大多数应用把 JSON 数据存成？
官方结论原文：通常，大多数应用应该更愿意把 JSON 数据存储为 jsonb——除非有特殊的保真需求。

🌿 中级测验 · 应用

4. json 存储与处理的效率特点是？
官方原文：json 存储输入文本的精准拷贝，处理函数必须在每次执行时重新解析该数据。
5. jsonb 与 json 在保真度上的区别是？
官方原文：jsonb 不保留空格、不保留对象键的顺序、不保留重复的对象键——重复时只保留最后一个值。
6. 为什么 jsonb 支持索引而 json 基本不能？
官方原文：jsonb 数据被存储在分解好的二进制格式中——GIN 可以索引其内部结构（键/值/路径），json 的文本拷贝没有可用结构。

🎯 高级测验 · 综合

7. 查询「tags 数组包含 admin 的用户」——数组列的正确写法是？
数组元素查询用 ANY（= ANY(tags)）或包含运算 @>——LIKE 对数组不适用。
8. jsonb 列插入 {"a": 1, "a": 2} 会怎样？
官方原文：如果在输入中指定了重复的键，只有最后一个值会被保留——json 类型则全部保留。
9. 什么场景必须用 json 而不是 jsonb？
官方原文：除非有特别特殊的需要（例如遗留的对象键顺序假设），大多数应用应该用 jsonb。

最终考核

四道题覆盖本课全部要点——答完它们，数组与 jsonb 就过关了。

考核一：设计「用户标签」与「灵活元数据」两列——分别是数组列与 jsonb。给出完整建表语句。
标签天然是数组（text[]，可 ANY 查询）；灵活元数据用 jsonb（可索引、处理快）——PG 原生的两类能力。
考核二：「查所有 meta 里 role 为 admin 的文档」的 jsonb 高效写法是？
@> 包含查询配合 GIN 索引是 jsonb 的标准姿势；->> 提取式写法走不了 GIN，大表会全扫。
考核三：为什么说「有 jsonb 后很多文档型需求不必上 MongoDB」？
文档型需求的核心是「按内容查文档」——jsonb + GIN 覆盖它；而关系模型的事务、约束、JOIN 依旧可用，两全其美。
考核四：数组下标是从几开始的？
PG 数组下标默认从 1 开始——与多数编程语言的 0 起始不同，写索引访问时别踩。

四道考核全部答对，说明你掌握了数组与 jsonb——继续学习 pg-07 · 函数与窗口函数。
