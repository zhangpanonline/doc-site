本课目标

完成本课后，你将能：

  1. 熟练写 INSERT / DELETE / UPDATE，并避开「忘写 WHERE」两大危险操作

知识速览

先花几分钟把核心机制过一遍——细节都在《04.DML》里，测验和考核会考。

增删改三件套

  1. INSERT 省略列：省略的列用 DEFAULT 或 NULL；PG 特有 RETURNING 直接拿回插入/删除/更新后的行（省一次 SELECT）。
  2. ON CONFLICT（UPSERT）：ON CONFLICT (唯一列) DO UPDATE SET … 冲突则更新，EXCLUDED 指本次要插入的新值；DO NOTHING 忽略冲突。
  3. ⚠️ DELETE / UPDATE 必须写 WHERE：漏了就是「清空全表 / 改全表」。
  4. TRUNCATE vs DELETE：TRUNCATE 快、重置自增序列、不触发 DELETE 触发器；DELETE 逐行、可带 WHERE、序列继续递增。

SELECT 执行顺序（面试必考）

FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY → LIMIT

推论：WHERE 里不能用聚合函数（聚合在 GROUP BY 阶段才有）；HAVING 里能（它在分组之后）。WHERE 过滤「原始行」，HAVING 过滤「分组结果」。

JOIN 与子查询速记

INNER JOIN   两边都匹配的行
LEFT JOIN    左表全保留，右表没匹配补 NULL（最常用）
RIGHT JOIN   右表全保留（可换成 LEFT JOIN）
标量子查询   返回单个值   → WHERE score > (SELECT AVG(score) …)
表子查询     返回多行     → WHERE age IN (SELECT …)
EXISTS       只关心有无  → WHERE EXISTS (SELECT 1 …)

分级测验

三道一组，先做后点——点击选项立刻出对错与解释。

🌱 初级 · 概念

1. INSERT INTO students (name, email) VALUES ('李四', 'lisi@example.com')——省略的 age 和 score 会怎样？
省略的列：有 DEFAULT 用默认值（score → 0.00），没有则 NULL（age → NULL）。前提是这些列没有 NOT NULL 且无默认值。
2. PostgreSQL 特有的 RETURNING 子句的作用是？
RETURNING 是 PG 特有的：INSERT … RETURNING id, name 插入后立刻拿回该行的 id 和 name（省一次 SELECT），DELETE/UPDATE 同样支持。
3. 执行 DELETE FROM students; 会发生什么？
不带 WHERE 的 DELETE = 清空全表数据（结构还在）——正是课件点名的两大危险操作之一。想删结构用 DROP，想快速清空考虑 TRUNCATE。

🌿 中级 · 应用

4. ON CONFLICT (email) DO UPDATE SET age = EXCLUDED.age 中 EXCLUDED 指什么？
EXCLUDED 指代本次要插入的新行：EXCLUDED.age = 新 age 值。所以「SET age = EXCLUDED.age」= 把旧行 age 更新为新插入值，实现 UPSERT。
5. SELECT age, COUNT(*) FROM students GROUP BY age——为什么 SELECT 里只能出现 age 和聚合？
GROUP BY 把行折叠成组：非聚合列必须出现在 GROUP BY 里，否则一组内有多个不同值，数据库不知道取哪个（PG 会直接报错）。这是 SQL 标准的硬性规则。
6. LEFT JOIN 与 INNER JOIN 的结果差异是？
LEFT JOIN = 左表全保留：没匹配的右表列补 NULL（比如找出「从未下单的用户」就靠它 + WHERE IS NULL）。INNER JOIN 两边都只要匹配行。工程上 LEFT JOIN 占九成。

🎯 高级 · 综合

7. 想在 WHERE 里写 COUNT(score) > 3 筛选行，结果会怎样？
执行顺序 WHERE → GROUP BY → HAVING：WHERE 阶段还没有分组，聚合函数无从计算 → 报错。对分组结果过滤必须用 HAVING（如 HAVING COUNT(*) > 3）。
8. 「每个品牌商品数超过 2 的品牌」查询，过滤条件应该写在哪？
「按品牌分组后，组的数量满足条件」= 分组后过滤 → HAVING。WHERE 只能过滤分组前的原始行（比如先 WHERE 掉下架商品）。这正是作业第 17 题的原型。
9. DELETE 清空全表后插入新行，与 TRUNCATE 清空后插入新行，id 分别是？
DELETE 不重置自增序列（序列是独立对象，逐行删除不碰它）；TRUNCATE 重置（直接重置存储，序列归零）。这是 04 课件对比表里 DELETE vs TRUNCATE 的关键差异。

最终考核

下面是《04.DML》源课程作业 35 题中挑出的 5 道改编题——这就是本课的最终考核（表结构：电商数据库，category / product / sku / "order" / order_items）。规则：不查资料，先在脑中写出完整 SQL，再点击核对。全部答对且能讲清理由，才算过关。答案均已在本课程的 scratch 数据库上实际运行验证。

考核一（作业 16·分组统计）：「统计每个分类下有多少个商品」，哪条 SQL 正确？
正确姿势：category LEFT JOIN product + GROUP BY。LEFT JOIN 保证没有商品的分类也出现（商品数 0）；GROUP BY c.name 后 COUNT(p.id) 数每组的非空商品。第一项漏 JOIN 条件成笛卡尔积；第二项 WHERE 里用聚合报错；第四项数的是分类自身行数。
考核二（作业 25·分页 JOIN）：「订单明细，显示订单编号、商品名称、SKU 规格、数量、单价，每页 10 条显示第 3 页」，哪条正确？
四表串联：明细 → 订单（拿 order_no）→ SKU（拿 sku_code）→ 商品（拿 name）。第 3 页每页 10 条 = OFFSET 20（前 20 条属于前两页）。陷阱：LIMIT 10 OFFSET 30 是第 4 页；只查一张表拿不到跨表字段。
考核三（作业 27·子查询）：「哪些商品从未被任何订单购买过」，哪条思路正确？
「从未被购买」= 该商品的任何 SKU 都不在 order_items 里 → NOT EXISTS（相关子查询：product → sku → order_items 层层探测）。第一项 JOIN 出的恰恰是「被买过的」；stock 是库存与购买无关；第四项逻辑自相矛盾。
考核四（作业 30·标量子查询）：「价格高于所有 SKU 平均价格的 SKU」，哪条正确？
标量子查询返回单个值：先把 AVG(price) 算出来，再逐行比较。第一、二项把聚合直接放 WHERE/HAVING 里不行（WHERE 阶段无聚合；无 GROUP BY 的 HAVING 语义不符）；第三项是「高于最高价」（恒空）。
考核五（作业 33·时间分组）：「每个月的订单数量和总金额」，哪条正确？
按月分组：to_char(created_at, 'YYYY-MM') 把时间戳格式化成月份字符串，再 GROUP BY。注意 "order" 是保留字要加双引号。第一项 GROUP BY created_at 按「每秒」分组没意义；第二项同病；第四项漏了 SUM 且按整年取。

💼 面试实战

下面是真实面试官会问的问题，选自中文互联网面试题集（出处附后）。先自己回答，再点击核对。三级面试难度：中级考应用，高级考陷阱，专家考机制与设计。

⚡ 中级面试题

面试题一（超高频）：WHERE 和 HAVING 有什么区别？
核心差异 = 过滤时机：WHERE 在 GROUP BY 前过滤原始行（快、不能用聚合函数）；HAVING 在分组后过滤聚合结果（能用 COUNT/SUM/AVG 等）。「单笔订单 > 100」用 WHERE，「消费总额 > 1000 的客户」用 HAVING。出处：CSDN「SQL 面试高频 50 题精讲」
面试题二（执行顺序）：SQL 各子句的真实执行顺序是？
书写顺序 ≠ 执行顺序。真实执行：FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY → LIMIT。两条推论：WHERE 里不能用 SELECT 中定义的列别名（SELECT 还没执行）；WHERE 里不能用聚合（分组还没发生）。出处：CSDN「面试题常见」

🔥 高级面试题

面试题三（LEFT JOIN 陷阱）：LEFT JOIN 后 WHERE 里过滤右表字段，左表「未匹配」的行会怎样？
LEFT JOIN 保证左表全保留，但 WHERE 作用在 JOIN 之后的结果集上：未匹配行的右表字段是 NULL，WHERE 右表.某列 = 'x' 会把 NULL 行滤掉，LEFT 退化成 INNER。想「连接前」过滤右表，条件要写在 ON 里。出处：CSDN「SQL 面试高频 50 题精讲」
面试题四（NOT IN 陷阱）：子查询结果含 NULL 时，NOT IN 会发生什么？
经典陷阱：x NOT IN (1, 2, NULL) 对每个 x 的比较都涉及 NULL → 结果 UNKNOWN → 全部不满足 → 空结果。生产环境建议用 NOT EXISTS 替代（只关心是否存在，不比较值），或用 NOT IN (子查询 WHERE 列 IS NOT NULL)。出处：CSDN「SQL 面试高频 50 题精讲」

🧠 专家面试题

面试题五（查询设计）：IN 和 EXISTS 怎么选？
IN：先算子查询结果，再与外表匹配——子查询结果小时快；EXISTS：遍历外表逐行探测子查询「是否有」——外表驱动、子查询表大时效率更高，且天然避开 NOT IN 的 NULL 陷阱。出处：CSDN「SQL 面试高频 50 题精讲」
面试题六（概念辨析）：JOIN 和 UNION 的区别是？
方向不同：JOIN 横向（按关联条件把多表字段拼成一行行，列变多）；UNION 纵向（把字段一致的多个结果集上下堆叠，行变多，默认去重、UNION ALL 不去重）。「左右拼接 vs 上下拼接」一句话说清。出处：知乎「宇宙最全系列 | 数据库面试题 v1.0」
