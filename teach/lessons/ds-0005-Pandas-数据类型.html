Pandas - 数据类型

本课目标

完成本课后，你将能：

  1. 说清 Series 是「带标签的一维数组」，并解释 values / index / dtype / shape 各是什么

知识速览

先把本章的三块骨架过一遍——细节都在《05.Pandas - 数据类型》里，测验和面试会考。

Series：带标签的一维数组

  • Pandas 两种核心结构：Series（一列带标签的数据）与 DataFrame（带标签的二维表格）
  • Series 由两部分组成：values（数据本身，类型是 numpy.ndarray）与 index（每个数据点的标签）
  • 不传 index 时自动生成 RangeIndex（0, 1, 2, …）；从字典创建时 key 自动成为索引；索引长度必须与数据长度一致
  • 取值方式不同：s['a'] 按标签、s.iloc[0] 按位置——同一份数据两套寻址，别混
  • 对齐（alignment）是 Pandas 的底层行为：两个索引不完全相同的 Series 相加，结果是索引的并集，两边对不上的标签填 NaN——不是按位置逐元素相加

DataFrame：创建与组成结构

  • 三种常见创建方式：字典（key 是列名、value 是列数据）、嵌套列表（用 columns= 补列名，否则是 0/1/2）、NumPy 二维数组（同样要 columns= 才有列名）
  • 组成结构四件套：index（行标签，默认 RangeIndex）、columns（列名，类型是 pandas.Index）、values / to_numpy()（核心数据，numpy.ndarray）、dtypes（每列一个类型）
  • values 一旦混合类型就退化成 dtype=object 的 ndarray：name → str、age → int64 到了数组里没有列的概念，统一是 object
  • 形状与规模：shape 是 (行数, 列数)、size 是元素总数、ndim 恒为 2
  • dtypes 是属性不是方法，写 df.dtypes，不要加括号

读数据：dtype 与索引列是两个高频雷区

  • pd.read_csv 常用参数：encoding（编码）、header=None（无表头）、index_col（指定索引列）、usecols（只读指定列）、nrows（只读前 N 行）、dtype（指定列类型）
  • pd.read_excel(..., sheet_name='Sheet1') 要指明工作表；pd.read_sql('SELECT ...', conn) 直接把查询结果变成 DataFrame
  • read_sql 是 read_sql_table / read_sql_query 的便捷封装；没装 SQLAlchemy 时，可以直接传 Python 内置的 sqlite3.Connection
  • 不指定 dtype 时 pandas 会自己推断：订单号、邮编、手机号这类「数字长得像数字」的标识列会被转成数值，前导零直接丢掉（007 → 7），ID 列还可能被当成可参与算术的度量
  • 修法是在读入那一刻就把列类型钉死：pd.read_csv(path, dtype={'订单号': str})；等读完再 astype 补救，前导零已经丢了，救不回来

🌱 初级测验 · 概念

1. 课件把 Series 描述为「带标签的一维数组」，它由哪两个核心部分组成？
对应《05.Pandas - 数据类型》的「Series」小节：values 是数据本身（类似 NumPy 数组），index 是每个数据点的标签。columns 是 DataFrame 才有的列标签。
2. 用嵌套列表创建 DataFrame 时，如果不传 columns 参数，列名会是什么？
对应「DataFrame 创建」小节：课件给的列表构造示例都显式写了 columns=['姓名','年龄','城市','薪资']；不传时 pandas 用 0、1、2 这样的整数当列名（「从 NumPy 数组创建」那个例子也一样，columns= 只负责给列贴名字）。
3. pd.read_excel('../linking.xlsx', sheet_name='Sheet1') 里 sheet_name 的作用是？
对应「从文件读取」小节：Excel 文件可以有多张工作表，sheet_name 决定解析哪一张。它不是编码、不是列过滤，也不会改变 DataFrame 的变量名。

🌿 中级测验 · 应用

4. 一份 CSV 里 订单号 列的值形如 007、012，直接 pd.read_csv('orders.csv') 之后这一列变成了 7、12。正确的处理方式是什么？
对应「从文件读取」小节的 dtype 参数与课件里 ID 类列的处理：前导零是在读入被推断成数值类型的那一刻丢掉的，事后 astype(str) 只能拿到 '7'，位数信息已经不存在，zfill 出来的值也不再是原始值。确定性做法是在读入时钉死类型：pd.read_csv('orders.csv', dtype={'订单号': str})。header 与 nrows 跟类型推断无关。
5. s1 = pd.Series([10, 20, 30, 40], index=['a','b','c','d'])，s2 = pd.Series([10, 20, 30, 40], index=['b','c','d','e'])。执行 s1 + s2 的结果是？
对应「Series」小节里的对齐行为：两个索引不同的 Series 做运算，结果索引是并集，某一边缺失的标签记 NaN。（注意默认的 RangeIndex 也是标签——两边都是 0,1,2,3 时看起来像按位置相加，换一套索引就露馅。）
6. 要检查 DataFrame 每一列的数据类型，用哪个写法？
对应「DataFrame 的组成结构」小节：dtypes 是属性，报告每列的类型（name → str、age → int64……），加括号就成了错误的调用。df.dtype 是 Series 才有的单列类型属性，DataFrame 没有它。

🎯 高级测验 · 综合

7. 同事让 AI 写「把两个部门各自汇总出来的 Series 相加，得到公司总销售额」。两个 Series 的索引是各自部门里出现过的员工工号，且集合不完全相同（有的员工两边都在，有的只在一侧）。审查这段代码，最大的隐患是？
对应「Series」小节的对齐语义：只在一侧出现的标签，结果记 NaN——不是报错、不是按位置相加、更不会自动补 0。求和/求平均默认会跳过 NaN，看起来「有结果」，但基数已经从「全部员工」变成「两边都有的员工」，业务含义变了。正确做法是先用 add(other, fill_value=0) 或显式 fillna(0) 明确口径，再决定怎么算。
8. AI 写了这段代码给「订单表」做前置处理：
df = pd.read_csv('orders.csv')
df['下单时间'] = pd.to_datetime(df['下单时间'])
但订单表里的 订单号、收货邮编 两列是带前导零的编号。上线后发现按订单号查单查不到、按邮编分组少了几个区。问题出在哪、怎么改？
对应「从文件读取」与「DataFrame 的组成结构」两节：dtypes 是逐列确定的，所以修法也是逐列——标识列用 dtype={...: str} 保住前导零与「不可运算」的语义，金额、数量这类度量列继续让 pandas 推断成数值。整表 dtype=str 属于另一个极端：后续所有数值计算都要重新转型，代价更大；问题不在文件格式，也不在 to_datetime。
9. 给定 df = pd.DataFrame({'姓名': ['张三','李四'], '年龄': [25, 30]})，下面哪组结论完全正确？
对应「DataFrame 的组成结构」小节：整表没有「一个」dtype，dtypes 逐列报告；而 values / to_numpy() 是一个 NumPy 数组，一列字符串一列整数混在一起，只能退化成 dtype=object。size 是元素总数 4（不是 2），index 是 RangeIndex、columns 是 pandas.Index——选项里的类型正好互换反了。
