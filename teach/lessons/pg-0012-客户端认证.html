客户端认证

本课目标

完成本课后，你将能：

  1. 说出 pg_hba.conf 的定位（官方：基于主机的身份验证、数据目录中）与读取时机

知识速览

先花几分钟把核心机制过一遍——细节与测验依据都来自官方文档 §20.1。

pg_hba.conf（官方要点）

  • 客户端身份验证由 pg_hba.conf 控制，存储在集簇数据目录；HBA = 基于主机的身份验证（官方原文）
  • initdb 初始化时安装默认文件；可用 hba_file 参数改位置
  • 读取时机：启动时 + 主进程收到 SIGHUP 时——改完必须重载
  • 重载三姿势（官方）：pg_ctl reload · pg_reload_conf() · kill -HUP
  • Windows 例外：改动立即生效（官方原文注明）

条目与匹配

  • 五个字段：TYPE DATABASE USER ADDRESS METHOD（连接类型/数据库/用户/地址/认证方法）
  • 从上到下逐条匹配，命中第一条即生效——宽规则放前面会挡住后面的细规则
  • 方法：trust（免认证，仅本机开发）/ scram-sha-256（现代密码默认）/ peer（本地同名系统用户）/ cert（证书）

分级测验

即时反馈：点击选项立刻显示对错与解释。题目只考本课与官方文档覆盖的内容。

🌱 初级测验 · 概念

1. HBA 代表什么（官方）？
官方原文：HBA 代表基于主机的身份验证（Host-Based Authentication）。
2. pg_hba.conf 默认存储在哪里？
官方原文：pg_hba.conf 存储在集簇的数据目录中；也可用 hba_file 参数放别处。
3. 修改 pg_hba.conf 后，Unix 上需要做什么才生效？
官方原文：文件在启动以及主进程收到 SIGHUP 时被读取——改完要 pg_ctl reload / pg_reload_conf() / kill -HUP 通知重读。

🌿 中级测验 · 应用

4. pg_hba 条目的匹配规则是？
逐条顺序匹配、第一条命中即用——所以宽规则（如 host all all 0.0.0.0/0 trust）放前面会把后面的细规则全部挡死。
5. 生产环境用 trust 认证方法的官方层面风险是？
trust = 不做任何认证直接放行——只适合本机开发回环；放生产等于把门拆了。
6. 现代 PG 的默认密码认证方法是？
scram-sha-256 是现代的挑战-应答密码认证（PG 10+ 默认），md5 已不推荐。

🎯 高级测验 · 综合

7. 「远程连接被拒，日志显示 no pg_hba.conf entry」——最可能原因？
该报错的字面意思：没有 hba 条目匹配这次连接的四个维度——需要加 host 条目覆盖该来源地址。
8. peer 认证方法的工作原理是？
peer 只在本地 Unix 域套接字连接可用：系统用户与数据库用户名一致即通过——本机管理的常用方式。
9. 官方说 pg_hba.conf 的读取时机是（Unix）？
官方原文：在启动以及主服务器进程收到 SIGHUP 信号时，pg_hba.conf 文件会被读取——这也解释了为什么改完要 reload。

最终考核

四道题覆盖本课全部要点——答完它们，客户端认证就过关了。

考核一：本机开发用 trust、远程用 scram-sha-256——两条 hba 条目该怎么排序？
顺序规则：先写具体地址的 trust 回环条目，再写全网段的 scram 条目——宽规则在前会把后面的全挡死。
考核二：改完 pg_hba.conf 后新规则没生效，最可能忘了什么？
官方三姿势：pg_ctl reload / SELECT pg_reload_conf() / kill -HUP——忘 reload 是最高频运维坑。
考核三：日志显示 password authentication failed for user X——与 hba 有关吗？
区分两类错误：no pg_hba entry = 没匹配条目（连接被拒）；password authentication failed = hba 放行后密码校验失败——排查方向完全不同。
考核四：host 条目五个字段的正确顺序是？
标准顺序：连接类型 / 数据库 / 用户 / 地址 / 认证方法——手写 hba 条目别写反。

四道考核全部答对，说明你掌握了客户端认证——继续学习 pg-13 · 角色与权限。
