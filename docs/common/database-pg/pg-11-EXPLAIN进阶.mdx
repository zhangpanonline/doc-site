## 查询计划与规划器（官方定位）

官方原文：PG 为每个收到的查询产生一个**查询计划**；选择正确的计划对性能**绝对关键**——系统内置复杂的**规划器**（planner）来选择好的计划。

- **EXPLAIN**：察看规划器生成的计划（估算成本与行数）
- 官方提醒：**阅读查询计划是一门艺术**，需要经验——本节覆盖基础
- 输出格式：默认 **text**（紧凑易读）；程序分析用机器可读格式（XML / JSON / YAML）

## EXPLAIN ANALYZE：估算 vs 实际

官方原文：使用 ANALYZE 选项时，**EXPLAIN 实际执行查询**，显示**每个计划节点内累积的真实行数与真实运行时间**，同时保留普通 EXPLAIN 的估算值——两相对照，规划器「估错」的地方一目了然。

```sql
EXPLAIN ANALYZE
SELECT * FROM tenk1 t1, tenk2 t2
WHERE t1.unique1 < 10 AND t1.unique2 = t2.unique2;
-- 输出同时含 (cost=... rows=...) 估算 与 (actual time=... rows=...) 实测
```

## 关于估算的官方注意事项

官方原文提醒：自己跑出来的**估算成本与行数可能略有不同**，因为：

1. **ANALYZE 的统计信息是随机样本，不是精确值**
2. 成本本质上在某种程度上**依赖于平台**

所以：估算行数（rows）与实际行数（actual rows）出现几倍偏差是常态——真正要看的是**数量级**是否对得上（估算 10 行实际 10 万行，说明统计信息过期，该 `ANALYZE` 表了）。
