系统提示词

本课目标

完成本课后，你将能：

  1. 说清系统提示词在消息序列里的位置，以及它为什么天然承担「全局设定」的角色
  2. 复述编写系统提示词的五条原则——精简、自洽、全局约束、保持静态、结构化——并用正反案例互相校验
  3. 读懂 agent/prompt/system.j2 与 agent/prompt.py 的配合：模板目录、FileSystemLoader、get_template、render
  4. 判断 Jinja2 渲染里的两类静默故障——变量名写错渲染成空、块标签留下多余空行——并给出修法

知识速览

先花几分钟把系统提示词的位置、五条编写原则与本章的渲染链路过一遍——细节都在《16.系统提示词》里，测验和面试会考。

它是什么，为什么在「最前面」

  • 位置：系统提示词往往出现在所有消息的最前面；大模型在训练的过程中，会重点关注系统提示词
  • 载体：本章的 agent/message.py 用 @dataclass 定义了 Message 抽象基类，再由 SystemMessage / UserMessage / AssistantMessage 三个子类分别把 role 默认成 "system" / "user" / "assistant"——发请求时它们被转成 {"role": …, "content": …} 的字典列表
  • 为什么值得单独讲：它不在某一轮对话里，而是作用于整条对话的每一轮——写坏了不会报错，只会让 Agent 的行为慢慢跑偏
  • 最小示例：SystemMessage("当用户向你打招呼时，你仅需回答你好即可") + UserMessage("你好")，第一条消息就把行为定死了

五条核心原则（课件的正反对照）

  • 精简：能不说就不说，能少说就少说，绝对避免无病呻吟。反例是「你现在要充当一名专业代码顾问……希望你认真仔细地阅读……」；正例压缩成一句「你是代码顾问。精准解答编程问题，不懂直接说明，禁止编造信息。」
  • 自洽：提示词不能自我矛盾。反例「回答务必详尽，多角度展开说明；同时所有回复控制在 30 字以内」——两条规则互相打架
  • 全局约束：系统提示词内所有规则作用于整条对话的每一轮交互。反例「当用户要求你写数据分析类代码的时候，你应该使用 Python 来编写」——这是只对某类请求成立的局部规则，课件的正面案例是删掉（<空>）
  • 保持静态：系统提示词内容应当尽量固定不变。反例「当前用户是：<动态内容>，时间是：<动态内容>」——正面案例同样是空
  • 结构化：用 Markdown / XML（或二者混用）分层排版，核心指令、硬性约束、输出规范用标记隔离，便于模型区分层级、识别关键规则，避免文本扁平化造成理解偏差
  • 记忆抓手：精简管「说多少」、自洽管「别打架」、全局约束管「放对地方」、保持静态管「别乱动」、结构化管「怎么排版」

从 .j2 模板到系统提示词：本章工程链路

  • 先收集环境信息：get_cwd()（os.getcwd()）、get_is_git()（跑 git rev-parse --is-inside-work-tree，返回码为 0 且输出为 true 才算在仓库里）、get_language()（macOS 读 defaults read -g AppleLocale，Windows 走 ctypes 读区域设置，其它平台返回空串）
  • 把模板交给 Jinja2：Environment(loader=FileSystemLoader(template_dir)) → env.get_template("system.j2") → template.render(language=…, cwd=…, is_git=…)
  • 封装成通用入口：render_prompt(prompt_name) 把模板目录定为模块同级的 prompt 子目录（os.path.dirname(__file__)），再按 f"{prompt_name}.j2" 取模板——所以 render_prompt("system") 读的就是 agent/prompt/system.j2；加一个新提示词只需丢一个 <name>.j2 进去
  • 模板本身长什么样：system.j2 就是一份结构化的系统提示词——# System / # Doing tasks / # Using your tools / # Tone and style 分段，末尾 # Language 用 {% if language %} 条件块、# Environment 注入 {{ cwd }} 与 {{ is_git }}
  • 本章 agent/ 变更：新增 7 个文件（__init__.py、config.py、message.py、model.py、printer.py、prompt.py、prompt/system.j2），修改 0 个，删除旧的 utils/ 六个文件——这是一次「把散装脚本收进包」的重构
  • 依赖：uv add pydantic-settings==2.14.1（读 .env 配置）、uv add jinja2==3.1.6（模板渲染）

分级测验

即时反馈：点击选项立刻显示对错与解释。题目只考本课与《16.系统提示词》覆盖的内容。

🌱 初级测验 · 概念

1. 关于系统提示词在消息序列里的位置与分量，本章的说法是？
课件原文：系统提示词往往出现在所有消息的最前面，大模型在训练的过程中，会重点关注系统提示词。工程上它由 SystemMessage 承载，role 默认就是 "system"。
2. 反面案例：「你是数据分析助手。回答务必详尽，多角度展开说明；同时所有回复控制在 30 字以内。」它违反的是哪条原则？
这是「自洽」的反面案例——提示词不能自我矛盾：既要「务必详尽、多角度展开」，又要「30 字以内」，两条要求互相打架。课件给的正面对照是：「你是数据分析助手。回答简洁，整体控制在 30 字以内。」
3. 关于「结构化」这条原则，课件推荐的做法是？
课件「结构化」原文：系统提示词采用 Markdown / XML（或二者混用）进行分层排版；核心指令、硬性约束、输出规范使用标记进行隔离，便于模型区分层级、识别关键规则，避免文本扁平化造成理解偏差。课件正面对照即一例：# 角色 / ## 硬性规则 / ## 输出要求。

🌿 中级测验 · 应用

4. 要把 agent/prompt 目录交给 Jinja2 的 FileSystemLoader，并且希望「不管进程从哪个目录启动都能找到模板」。本章 agent/prompt.py 的 render_prompt 选择的是？
本章封装后的 render_prompt 用的是 os.path.join(os.path.dirname(__file__), "prompt")——以模块自身文件位置为基准。对比课件前面探索版写的 os.path.join(os.getcwd(), 'agent/prompt')：它把模板目录绑死在「启动进程时的工作目录」上，换个目录运行就会找不到模板。这正是「探索版 → 封装版」之间一处关键的修正。
5. render_prompt(prompt_name) 是按什么规则定位模板文件的？
课件封装的 render_prompt 把模板目录定为「模块同级的 prompt 子目录」，再用 env.get_template(f"{prompt_name}.j2") 按名字取模板——所以 render_prompt("system") 读的是 agent/prompt/system.j2。本章「新增文件」清单里正好列着这个文件。
6. 「全局约束」原则要求：系统提示词内所有规则作用于整条对话的每一轮交互。据此，课件给的反面案例「当用户要求你写数据分析类代码的时候，你应该使用 Python 来编写」问题出在哪？
课件「全局约束」原文：系统提示词内所有规则作用于整条对话的每一轮交互。反面案例把「数据分析类代码 → 用 Python」当成全局规则写进系统提示词，但它只在一小类请求里成立，会给每一轮对话都带上无关约束；课件给出的正面案例就是 <空>——这类条件性要求属于当轮的用户消息或工具描述，不属于系统层。这也和「精简」互相印证：能不说就不说。

🎯 高级测验 · 综合

7. 模板里 {% if language %} 块与 {% endif %} 各自独占一行，Environment 没有传任何空白相关参数。渲染后 # Language 前后总是多出空行，没有 language 时同样留下空行。正确的解释与修法是？
本章的 Environment(loader=FileSystemLoader(...)) 没传 trim_blocks / lstrip_blocks，两者默认都是关闭的，因此「独占一行的块标签会被移除，但会留下一个空行，内容里的空格照旧保留」。修法有两条：初始化时写 Environment(..., trim_blocks=True, lstrip_blocks=True)，或在标签上用 {%- … -%} 手动吃掉空白。系统提示词是逐字进入模型的文本，这类空白差异值得控制。
8. 模板里写的是 Is a git repository: {{ isgit }}（本意是 is_git），但 render() 只传了 language / cwd / is_git。渲染不报错，这一行后面却是空。原因与修法？
官方对默认 Undefined 的定义是：可以被打印、被迭代、被当作布尔值，其它运算才会抛 UndefinedError，而 str(Undefined) 就是空字符串。所以把 is_git 拼成 isgit 不会报错，只会让环境信息静默丢一块——对系统提示词来说这是最危险的一类 bug：不崩溃、不告警，模型拿到的却是残缺指令。修法：Environment(..., undefined=StrictUndefined) 让拼错的变量立刻失败，或在渲染后断言关键字段非空。注意布尔值本身在 Jinja2 里会渲染成 True / False（课件里 Is a git repository: {{ is_git }} 正是这种用法），所以第 1 条不成立。
9. 审查一份系统提示词：角色与硬性规则用 Markdown 分好了段，但末尾又写上「当前用户：{{ user_name }}，当前时间：{{ now }}」。它违反本章哪条原则？重新设计时这部分该放哪？
课件「保持静态」原文：系统提示词内容应当尽量固定不变；反面案例正是「当前用户是：<动态内容>，时间是：<动态内容>」，正面案例是 <空>。用户与时间每轮都在变，留在系统提示词里等于让这份「全局设定」每轮都不一样。（工程上还有一层代价：提示词缓存按前缀比对，前缀一变就整段重算。）正确做法是把静态的角色与规则留在系统提示词，把随请求变化的用户、时间信息注入到当轮消息或工具返回结果中。
