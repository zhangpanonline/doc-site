词嵌入

配合《10.词嵌入》使用预计 15–20 分钟9 道分级测验 + 面试实战

本课目标

完成本课后，你将能：

  1. 说清 Token ID 序列为什么不能直接拿去训练——它既不能表示语义，也不能表达语义之间的数学关系
  2. 复述「用向量描述 Token」的思路：苹果的 3 维表示、向量空间中「接近」的含义，以及 $苹果\approx Apple$ 这类关系
  3. 解释词嵌入（word embedding）的定义与「镶嵌、植入」的本意，并说明为什么我们只规定维度个数、不规定每一维的含义与取值
  4. 分清上下文长度（本次传入的 Token 数）与上下文窗口长度（模型能容纳的最大 Token 数），会用它做长度预算

知识速览

先花几分钟把词嵌入的来龙去脉过一遍——细节都在《10.词嵌入》里，测验和面试会考。

Token ID 的两个致命问题

  • 无法表示语义：Token ID 只是表示一个文字符号，仅靠单个符号无法表示它背后丰富的语义。课件举例：你知道某个 Token 对应的文字 كِتاب 是什么含义吗？
  • 无法表达语义之间的数学关系[33256, 11789]，那么 $33256 + 11789$ 是什么含义？答案是：没有任何含义。
  • 结论：我们需要更多的维度来描述一个 token——这就是词嵌入要解决的问题。

用向量描述 Token

  • 苹果可以被描述为：一种食物、和科技有关系、昂贵的——数字化成 3 个维度就是（0.9 可被食用的程度、0.6 科技程度、0.5 消费水平）
  • 另一个 Token 的 3 维值是（0.7、0.8、0.3）。把维度值放进三维空间，可以想象这两个 token 在空间里比较接近（课件给出可视化工具 projector.tensorflow.org）
  • 转成多个维度的数字之后，Token 之间会形成有趣的数学关系：$苹果\approx Apple$、$国王 - 王后 \approx 男人 - 女人$、$男人+医生\approx男医生$、$2×开心≈狂喜$
  • 把这个 token 转成多维度数字向量的过程，就叫词嵌入 word embedding；嵌入（Embedding）的本意是把低维离散对象「镶嵌、植入」到一个连续高维几何空间里
  • 工程上，嵌入就是一张矩阵 $E \in \mathbb{R}^{|V| \times d}$（$|V|$ = 词表大小，$d$ = 每个 Token 的维度）：第 $i$ 行就是 Token ID 为 $i$ 的向量，参数量为 $|V| \times d$。官方定义见 PyTorch nn.Embedding 的权重形状 $(num\_embeddings, embedding\_dim)$

维度由谁定？上下文长度与窗口长度

  • 只规定学习方法，永远不要告诉机器答案：三个问题（规定多少个维度？每个维度表达什么含义？每个维度的值是什么？）的答案是——我们仅规定有多少个维度，让机器在训练过程中为每一个 Token 的每一个维度填写具体的值
  • 上下文长度：传入到 transformer 神经网络的 Token 数量（本次实际用了多少）
  • 上下文窗口长度：transformer 神经网络能容纳的最大 Token 数量（模型的硬上限）
  • 两者的关系是「用量 ≤ 容量」：$上下文长度 \le 上下文窗口长度$——超了就会被截断或报错

🌱 初级测验 · 概念

1. 为什么分词得到的 Token ID 序列不能直接拿来做训练？
课件「Token的问题」给出两条根源：Token ID 无法表示语义——它只是表示一个文字符号，仅靠单个符号无法表示背后丰富的语义；Token ID 无法表达语义之间的数学关系——「吃苹果」对应 [33256, 11789]，而 33256 + 11789 没有任何含义。所以需要「更多的维度」来描述一个 token。
2. 「词嵌入（word embedding）」指的是下面哪件事？
课件原文：「把一个token转换成多个维度的数字向量，这一过程称之为词嵌入 word embedding」。嵌入（Embedding）这个词的本意，就是把低维离散对象「镶嵌、植入」到一个连续高维几何空间里。
3. 「上下文窗口长度」指的是什么？
课件「额外的术语」写得很清楚：上下文长度 = 传入到 transformer 神经网络的 Token 数量；上下文窗口长度 = transformer 神经网络能容纳的最大 Token 数量。前者是「这次用了多少」，后者是「最多能装多少」。

🌿 中级测验 · 应用

4. 课件把「苹果」写成三维向量（0.9 可食用 / 0.6 科技 / 0.5 消费水平）。关于这些维度的含义与数值从哪来，哪个说法正确？
课件先抛出三个问题（规定每个 token 有多少个维度？每个维度表达什么含义？每个维度的值是什么？），随后给出原则：「在深度学习中，我们只规定学习方法，永远不要告诉机器答案」——因此我们仅规定有多少维度，让机器在训练的过程中，为每一个 Token 的每一个维度填写具体的值。「可食用程度 / 科技程度 / 消费水平」只是帮助理解三维表示的举例，不是人工写死的字段。
5. 「吃苹果」的 Token 序列是 [33256, 11789]。有人算出 33256 + 11789 = 45045，并认为这个数代表「吃苹果」的语义。怎么判断？
课件正是用这个例子说明第二条根源：Token ID 无法表达语义之间的数学关系。真正能做数学运算的是向量——$苹果\approx Apple$、$国王 - 王后 \approx 男人 - 女人$、$男人+医生\approx男医生$ 全都建立在「多个维度的数字向量」之上，而不是 Token ID 的算术。
6. 某模型的上下文窗口长度为 128K，本次请求实际传入 3000 个 Token。此次的上下文长度与上下文窗口长度分别是？
上下文长度是「本次传进去的 Token 数量」（3000），上下文窗口长度是「模型能容纳的最大 Token 数量」（128K）。两者是「实际用量 ≤ 容量上限」的关系：拿窗口长度当成本次用量来算预算，或在截断时把两者混用，都会算错。

🎯 高级测验 · 综合

7. 课件说词嵌入是 transformer 架构前向传播的第一个阶段。分词器给出 [33256, 11789]，经过词嵌入之后，送进后续网络的是什么？
课件：Token ID 无法表示语义、也无法表达语义关系，因此需要「更多的维度」来描述一个 token；词嵌入就是把一个 token 转换成多个维度的数字向量。所以 [33256, 11789] 变成「两个 d 维向量组成的序列」——长度还是 2，但每个位置已经是向量，后续阶段（注意力等）才有可运算的语义表示。这也是「前向传播的第一个阶段」的含义。
8. 课件列出 $国王 - 王后 \approx 男人 - 女人$、$男人+医生\approx男医生$、$2×开心≈狂喜$。这些式子说明什么？
课件：当我们把 Token 转换成多个维度的数字来表达后，它们之间就可以形成一些有趣的数学关系。嵌入的本意是把低维离散对象「镶嵌、植入」到连续高维几何空间里——语义关系因此变成了几何关系（差值、方向、距离）。这正是后面做语义检索、相似度计算、向量聚类的根基，而这些关系来自训练，不是人工规则。
9. 团队想用「两个 Token ID 的数值差越小就越相近」来实现近义词检索。判断这个方案：
课件强调 Token ID 无法表示语义，也无法表达语义之间的数学关系——它只是词表里的一个编号（编号怎么来的见第 07 章：由合并顺序决定），编号之差没有任何语义承诺。而「苹果 ≈ Apple」这类关系只有在多维度向量空间里才成立。所以近义词检索必须先嵌入、再比距离/相似度。
