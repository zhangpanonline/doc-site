词元

本课目标

完成本课后，你将能：

  1. 说清「直接把 UTF-8 字节数字当分词结果」为什么不行，以及分词表（Vocab）要解决的问题
  2. 复述 BPE 训练词表的核心循环：统计高频相邻对 → 合并 → 写入新 id，直到达到目标词表大小
  3. 用「查表 + 最长匹配」解释分词阶段为什么不再改动词表，并读懂分词结果里的字节片段
  4. 会用课件比率表估算中文／英文文本的 token 量级，判断「一个汉字一个 token」这类说法对不对

知识速览

先花几分钟把词元的来龙去脉过一遍——细节都在《07.词元》里，测验和面试会考。

从字符编码到词元

  • 最简单的中文「分词」方案是把文字转成 UTF-8 编码的数字："你好Hello!123" → 15 个数字
  • 不能直接用它的三个原因：长度膨胀（中文一字 = 3 个字节数字，计算量／显存／训练速度全恶化）、信息浪费（每层都要重复学「228,189,160 = 你」）、语义不明（很难学到字、词的边界规律）
  • 目标形态是「每个有意义的字／词对应一个数字」：你好 → 10000、Hello → 10001、! → 10002、123 → 10003；整句只要 4 个数字，且每个数字对应可被学习的语义
  • 要实现这种映射，必须建立一张「词典」——分词表（token vocabulary，Vocab）

BPE：词表是怎么长出来的

  • 统计大量文字，合并高频出现的组合——这就是 BPE（字节对编码）的核心
  • 初始词表是 256 个单字节（vocab = {i: bytes([i]) for i in range(256)}），这样任何文本都不会出现「未知字符」
  • 循环里的每一轮做三件事：① 统计当前序列中相邻对的出现次数；② 取最高频的一对，把「两个 id 的字节拼起来」作为新 id 加进词表；③ 在序列里把这一对全部替换成新 id
  • 反复执行到 len(vocab) 达到 target_vocab_size 为止。实测课件 corpus.txt（8268 字符 / 23616 字节）：合并 144 次，词表 256 → 400，序列压缩 23616 → 12786（54.1%）

分词：查表 + 最长匹配

  • 词表固定下来后就不再改动：分词阶段只读词表做匹配，就能高效把文本变成 token 序列
  • 课件实现是贪心最长匹配：从可匹配的最长片段往下试，命中就前进相应字节数
  • 单个汉字被拆成多个 token 的两个原因：词表太小（有些词还没收录就到了词表上限）、训练语料里没出现过该词
  • token 量级估算（课件比率表）：1 个汉字 = 海外模型 1.3～1.5 token、国产模型 0.8～1 token；1 个英文字母平均 0.25～0.33 token；1 个英文单词平均 1.3 token
  • 不同的训练语料、不同的分词算法 → 不同格式与内容的词表 → 不同的分词结果

分级测验

即时反馈：点击选项立刻显示对错与解释。题目只考本课与《07.词元》覆盖的内容。

🌱 初级测验 · 概念

1. 把 "你好Hello!123" 按 UTF-8 编码，会得到多少个字节数字？
课件示例1：中文一个汉字 = 3 个 UTF-8 字节数字，「你好」6 个 + Hello 5 个 + ! 1 个 + 123 3 个 = 15 个数字，即 [228, 189, 160, 229, 165, 189, 72, 101, 108, 108, 111, 33, 49, 50, 51]。这正是「长度膨胀」的直观来源。
2. 分词表（token vocabulary，Vocab）是什么？
课件：想实现「你好 → 10000、Hello → 10001」这类映射，就必须建立一个"词典"，称之为分词表（token vocabulary，Vocab）。有了它，整句只要 4 个数字就能表达，同时每个数字对应一个可以被学习的语义。
3. 为什么不直接把 UTF-8 的数字序列当作分词结果？
课件给出的三条原因：长度膨胀——中文一个汉字 = 3 个 UTF-8 字节数字，将来的计算量、显存占用、训练速度全部恶化；信息浪费——模型每一层都要重复学习「228,189,160 = 你」这种固定组合；语义不明——模型很难学到词语、字的边界规律。

🌿 中级测验 · 应用

4. 课件 bpe_train(corpus, target_vocab_size=400) 的初始词表是 256 个单字节。训练结束时，词表大小与合并次数分别是？
每合并一次只往词表里加 1 个新 id，所以合并次数 = 目标 400 − 初始 256 = 144。实测课件 corpus.txt（8268 字符 / 23616 字节）的输出正是「合并次数: 144」「词表: 256 → 400」，序列压缩 23616 → 12786（54.1%）。
5. 词表训练完成以后，对一句新文本分词时，为什么不需要重新统计相邻对、重新合并？
课件原文：「词表固定下来后，就不再改动了。后续的分词动作，只需要读取词表进行匹配，就能高效完成分词。」课件实现用的是贪心最长匹配：for length in range(min(max_len, 剩余字节数), 0, -1)，从最长片段往下试，命中就前进对应字节数。
6. 用这份 400 词表切「人工智能模型通过深度学习来理解自然语言。」，结果里出现了 <字节 e6>、<字节 e887> 这样的片段。这说明什么？
课件给的原因：词表太小，有些词还没收录就已经达到了词表上限；或者训练语料中没有出现过该词。实测这句话 20 字 / 60 字节 → 18 个 token，其中「深」被切成 <字节 e6><字节 b7><字节 b1>，「自」切成 <字节 e887><字节 aa>，「然」切成 <字节 e7><字节 84><字节 b6>；而「人工智能」「模型」「通过」「学习」「语言」都是一次命中的整词 token。

🎯 高级测验 · 综合

7. 同一份语料、同一份分词代码，只把 target_vocab_size 从 400 提到 4000，对同一段测试文本最可能发生的整体变化是？
课件指出汉字被拆成多个 token 的原因之一是「词表太小，有些词还未收录就已经达到了词表上限」——词表变大，被切碎的片段减少，序列更短。但词表变大意味着 embedding 与输出层的参数、计算量上升，而且语料里没出现过的高频组合依然进不来（总结：不同语料、不同算法 → 不同词表），所以这是权衡，不是单调收益。
8. 一份 1 万汉字的中文文档，按课件的比率表，海外模型与国产模型的 token 数大致落在哪个区间？
课件比率表：1 个汉字 = 海外模型 1.3～1.5 token、国产模型 0.8～1 token；1 个英文字母平均 0.25～0.33 token；1 个英文单词平均 1.3 token。所以「一个汉字 = 一个 token」的直觉是错的，中文文本按 token 计费或做长度拦截时，要用 1.3～1.5 倍（海外模型）来估。
9. 两个团队各自用不同语料训练了词表大小同为 400 的 BPE 词表，用同一份分词代码切同一句话，结果不一样。最合理的判断是？
课件总结原文：「不同的训练语料、不同的分词算法，得到不同的格式和内容的词表，从而得到不同的分词结果」。分词阶段是「查表 + 最长匹配」：查的表不一样，切出来的序列自然不一样——这也是换了模型之后必须重新统计 token 数的原因。
