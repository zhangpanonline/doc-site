本课目标

完成本课后，你将能：

  1. 说出数据迁移解决的三个问题（数据保留 / 多环境同步 / 可回滚）
  2. 跑通 Alembic 三大命令：db-migrate（生成）/ db-upgrade（执行）/ db-downgrade（回滚）
  3. 说清 env.py 里 target_metadata 与 sqlalchemy.url 覆盖的作用
  4. 背下两条禁区，并按「改模型 → 生成 → 审查 → 执行」四步走日常开发

知识速览

先花几分钟把核心机制过一遍——细节都在《06.数据迁移》里，测验和面试会考。

Alembic 三命令（Makefile 封装）

  • db-migrate：alembic revision --autogenerate -m "init"——对比模型与数据库生成候选迁移脚本
  • db-upgrade：alembic upgrade head——执行到最新版本
  • db-downgrade：downgrade -1 回退一步 / downgrade abc123 回退到指定版本
  • env.py 关键：target_metadata = Base.metadata（autogenerate 的对比基准）+ 项目配置覆盖 alembic.ini 的 sqlalchemy.url（同步驱动 postgresql://）

红线与流程（课件要点）

  • 两条禁区：手动修改数据库；修改已执行过的迁移
  • 等式：迁移脚本执行完 == 本地数据库最新状态 == 生产数据库最新状态
  • 日常四步：改动模型 → 生成迁移脚本 → 审查（是否丢数据、回滚与迁移是否互逆）→ 执行
  • 回滚哲学：尽量不用（表结构≠模型状态会带来更多 Bug）；不一致最多允许是暂时状态，绝不能是长期状态

分级测验

🌱 初级测验 · 概念

1. 数据迁移解决了什么问题？（作业题）
课件开头三个问题：① 保证过往数据不被删除；② 生产/测试/开发环境表结构同步；③ 能回滚到之前的表结构。
2. 生成迁移脚本、执行迁移、执行回滚分别对应哪个 Makefile 目标？
课件 Makefile：db-migrate 生成（revision --autogenerate）、db-upgrade 执行（upgrade head）、db-downgrade 回滚（downgrade 版本号）。
3. autogenerate 生成迁移脚本的底层命令是？
课件执行命令：make db-migrate message="init" 内部就是 alembic revision --autogenerate -m "init"。

🌿 中级测验 · 应用

4. env.py 里 target_metadata = Base.metadata 的作用是？
课件注释：「告诉 Alembic 你的模型元数据，用于自动生成迁移」——autogenerate 拿它和数据库当前结构做对比，差异变成候选迁移。
5. 课件里为什么把 alembic.ini 的 sqlalchemy.url 改成从项目配置读取？
课件 env.py：config.set_main_option("sqlalchemy.url", ...) 用 db_settings 覆盖 ini——环境切换只改 .env；注释说明迁移用同步驱动 postgresql://（不需要 +asyncpg）。
6. 课件「日常开发」四步中，审查迁移脚本要检查哪两点？
课件日常开发第 3 步：审查迁移脚本（可使用 AI）——① 是否会导致数据丢失；② 回滚和迁移是否互逆。

🎯 高级测验 · 综合

7. 某次迁移有问题但已经执行过了，怎么办？
课件常见问题：迁移执行过说明表结构已有问题——生成新迁移让表结构适配模型，审核后执行。迁移脚本是常量，一旦执行永远不可变更。
8. 什么时候应该使用回滚？
课件常见问题：尽量不回滚（结构≠模型不一致）；确需回滚后要么重跑迁移回到一致、要么生成新迁移再执行。不一致最多允许是暂时状态，绝不能是长期状态。
9. 某次迁移执行失败了，怎么处理？
课件常见问题：「根据错误信息查看是哪个脚本执行失败，修复它重新运行即可。」
