知识速览

先花几分钟把核心机制过一遍——细节都在《17.用户系统》里，测验和面试会考。

密码保存（课件）

  • 哈希算法：无密钥、不可逆（SHA256）——固定输入固定输出；彩虹表：预计算常见明文哈希，可倒推
  • 加盐：随机盐 + 多轮计算（bcrypt 两者都有，每用户盐不同）——同样密码两次哈希不同
  • 消息认证码：带密钥的哈希（HMAC-SHA256），JWT 签名即此——控制「生成哈希的权力」
  • JWT 加盐吗？不加——签名已用 secret_key，且 JWT 不加密（payload 只编码），别把敏感信息放里面

凭证与认证链（课件代码）

  • 过期时间：设置表 jwt_expire_minutes（ch15 系统设置实战！默认 120 分钟）；密钥：web_settings.jwt_secret_key（WEB_JWT_SECRET_KEY）
  • get_current_user：HTTPBearer 取 token → decode（无效→AuthException）→ sub 转 user_id → 查库返回 User
  • 登录失败统一话术：「用户名或密码错误」——不区分哪个错，防用户名枚举
  • ContextVar：不传参拿上下文数据，并发任务互不干扰（contextvars 官方机制）

🌱 初级测验 · 概念

1. 密码保存用哪类算法？为什么？
课件场景：密码保存——注册时哈希保存，登录时同算法哈希比对。不可逆意味着库泄露后攻击者拿不到明文密码（配合加盐防彩虹表）。
2. 彩虹表攻击是什么？怎么防？
课件原文：彩虹表——预先将常见字符进行 Hash 运算得到结果，可倒推明文。加盐方法 1 随机盐（彩虹表失效），方法 2 多轮计算（暴力破解变慢），现实两者结合（bcrypt）。
3. JWT 需要加盐吗？（课件思考题）
JWT 签名 = HMAC-SHA256(secret, content)，secret 就是「盐」的作用（带密钥的哈希）；payload 仅 Base64 编码，任何人可解——所以 JWT 里绝不能放密码/身份证等敏感明文。

🌿 中级测验 · 应用

4. 课件代码里 JWT 过期时间在哪设置、密钥在哪配置？
user_service.login：select(Setting.value).where(key=="jwt_expire_minutes")，读不到用 120——ch15 系统设置的实战用法；secret 走 WEB_JWT_SECRET_KEY 环境变量（pydantic-settings）。
5. login 里查不到用户和密码错为什么用同一句话？
课件 login：if user is None or not verify_password(...): raise AuthException("登录失败：用户名或密码错误")——一个条件一个话术，攻击者无法用响应区分「用户不存在」与「密码错误」。
6. get_current_user 依赖里 decode 失败会怎样？
课件 core/auth.py：except jwt.InvalidTokenError as e: raise AuthException(...) from e——业务异常体系扩展（ch07/09），响应由全局处理器出统一 {"code","message"}。

🎯 高级测验 · 综合

7. register 里为什么「先查重 + IntegrityError 双保险」？
课件 register：select 查重提前抛「用户名已存在」；try flush except IntegrityError 再转 DatabaseException——并发注册同时通过查重时，数据库唯一索引是最后防线（ch07 的翻译模式）。
8. ContextVar 演示里 Bob 先完成打印，输出顺序为什么是 Bob 再 Alice？
课件输出：你好，Bob（先）/ 你好，Alice（后）——gather 并发下 Bob sleep 0.1 先醒；关键是 say_hello() 无参却拿到各自正确的 name，ContextVar 按任务上下文隔离，不会串。
9. /api/auth/me 接口是怎么「知晓当前登录用户」的？
课件 api/auth.py：profile 的参数声明依赖 get_current_user（HTTPBearer 取 token → decode → 查库），FastAPI 自动解析注入——需要登录的接口加这一行即可，OpenAPI 文档上也会标出需要 Bearer 认证。
