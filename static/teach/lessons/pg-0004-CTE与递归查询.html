CTE 与递归查询

知识速览

先花几分钟把核心机制过一遍——细节与测验依据都来自官方文档 §7.8。

递归 CTE 的形式与求值（官方原文）

  • 形式：非递归项 + UNION [ALL] + 递归项；只有递归项能引用查询自身输出
  • 五步循环：算非递归项 → 入结果+工作表 → 循环（工作表替换自引用算递归项 → 去重 → 入结果+中间表 → 中间表替换工作表）直到工作表为空
  • 去重差异：UNION 每轮去重；UNION ALL 不去重——终止条件无效时无限循环
  • 本质：RECURSIVE 在内部是迭代评估；适用分层/树形结构（官方 BOM 部件展开原例）

官方原例：1 到 100 求和

WITH RECURSIVE t(n) AS (
    VALUES (1)
    UNION ALL
    SELECT n+1 FROM t WHERE n < 100
)
SELECT sum(n) FROM t;   -- 5050

工作表每步只有一行、取值 1→100；第 100 步 WHERE 无输出，查询终止。

分级测验

即时反馈：点击选项立刻显示对错与解释。题目只考本课与官方文档覆盖的内容。

🌱 初级测验 · 概念

1. 官方文档说 WITH 提供了一种什么样的书写方式？
WITH 把子查询拆成带名字的辅助语句，主查询像引用表一样引用——复杂 SQL 的可读性基石。
2. 递归 CTE 的标准形式是？
官方原文：一个递归 WITH 查询的通常形式总是一个非递归项，然后是 UNION（或 UNION ALL），再然后是一个递归项。
3. 递归 CTE 中，哪部分可以引用查询自身的输出？
官方原文：其中只有递归项能够包含对于查询自身输出的引用——非递归项引用自身会直接报错。

🌿 中级测验 · 应用

4. 官方五步求值机制中，「工作表」的作用是？
官方原文：用当前工作表的内容替换递归自引用来计算递归项——工作表就是「上一轮新产生的行」。
5. 递归中 UNION 与 UNION ALL 的去重差异是？
官方原文：对 UNION（但不对 UNION ALL）抛弃重复行——去重差异直接影响「能否终止」。
6. 官方说 RECURSIVE 在内部是如何执行的？
官方原文：RECURSIVE 允许递归指定查询，但在内部这样的查询是迭代评估的。

🎯 高级测验 · 综合

7. 官方举的 BOM 例子说明递归查询适合什么场景？
官方原文：递归查询通常用于处理分层或树形结构数据；BOM 例查产品的所有直接和间接子部件。
8. 递归项用 UNION ALL 且 WHERE 条件永远为真，会发生什么？
UNION ALL 不去重、工作表永远非空 → 无限递归。递归 CTE 必须有明确终止条件（WHERE 无输出才停）。
9. 官方 1..100 求和的例子在第 100 步终止，直接原因是？
官方原文：在第 100 步，由于 WHERE 子句导致没有输出，因此查询终止——工作表为空的判定。

最终考核

四道题覆盖本课全部要点——答完它们，CTE 与递归查询就过关了。

考核一：员工表（id, name, manager_id），要列出 CEO 的所有层级下属。递归 CTE 的递归项里应该写什么关联？
树形结构的标准模式：递归项把「上一轮的员工 id」当作下一轮的 manager_id——每轮向下钻一层。
考核二：求值机制的完整顺序是？
官方五步：先非递归项播种，再以工作表为「上一轮」循环扩展，直到工作表为空。
考核三：为什么递归 CTE 里通常推荐 UNION ALL 而非 UNION？
UNION 每轮全量去重有开销；树形结构（每条路径天然唯一）用 UNION ALL 更快——代价是要自己保证终止条件。
考核四：CTE 在同一个 WITH 里定义了两个辅助语句，后面的可以引用前面的吗？
WITH 里按声明顺序组织：后面的辅助语句可以引用前面已声明的 CTE——复杂查询的层层拆解就是靠这个。

四道考核全部答对，说明你掌握了 CTE 与递归查询——继续学习 pg-05 · 数据类型 · 基础。
