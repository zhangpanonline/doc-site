知识速览

先花几分钟把核心机制过一遍——细节都在《25.部署-总结》里，测验和面试会考。

部署全景（ch21-24 串线）

  • 微服务架构：AI 服务不直接对外——由后端服务调用或经网关转发
  • Dockerfile → ACR：多阶段构建推镜像仓库（版本 tag，不用 latest）
  • ACK → ALB：k8s 集群管 Pod，负载均衡路由流量；域名 CNAME 到 ALB
  • 云效流水线：两个节点——PR（CI 跑测试）、tag（CD 构建部署）

面试要点（课件的诚实框架）

  • 坦诚层级：未亲自参与部署但了解流程，细节不深——比硬编更可信
  • 能讲清单：微服务架构、ACK、ALB、Dockerfile、ACR、流水线两节点
  • 兜底一句：经过短时间学习，自己搭建部署流水线没有问题（ch21-24 已实操）

分级测验

🌱 初级测验 · 概念

1. 课件面试要点里「AI 服务不直接对外」是什么意思？
课件要点：微服务架构：AI 服务不直接对外——它是能力组件，被业务后端调用（或经网关），公网入口统一走 ALB。
2. 云效流水线的两个触发节点是？
课件要点：云效流水线的两个节点——PR、tag。PR 进主干前跑集成验证（ch24 CI）；打 tag 是「发布信号」触发 CD 构建部署（ch24 TAG 版本纪律）。
3. 部署面试题的「诚实框架」第一步是什么？
课件面试要点结构：① 坦诚层级（未亲自参与但了解流程）；② 能讲的清单（架构/工具/流程各点）；③ 兜底（短时间学习可自建流水线）——诚实+有料，面试官信得过。

🌿 中级测验 · 应用

4. 从代码提交到线上服务，经过哪些环节（按课件串线）？
ch21-24 串线：CI（测试）→ CD（镜像+部署）→ ACR（仓库）→ ACK（集群）→ ALB（入口）→ 域名。课件的 CI/CD 图与服务器架构图就是这个链路。
5. 为什么 PR 和 tag 分开触发，而不是都用 push？
课件两节点语义：PR 触发 CI——每个待合入变更都验证（防回归）；tag 触发 CD——只有打了发布 tag 才构建部署（发布是显式决策，不是每次 push 都上线）。
6. 「和后端/运维配合编写 Dockerfile」说明 AI 工程师的部署职责边界是？
课件要点：和后端/运维配合编写 Dockerfile——AI 工程师懂应用依赖（ch21 的 uv sync 等），平台规范（基础镜像/端口约定）与运维对齐；ACK/ALB 等基础设施由专业角色维护。

🎯 高级测验 · 综合

7. 面试官追问「细节不太了解」时，怎么接才不掉分？
课件框架的三层：坦诚层+清单层+兜底层——「细节不太了解」之后紧跟可讲的清单（微服务/ACK/ALB/ACR/流水线节点），说明了解流程框架；兜底一句体现学习能力与实操底气（ch21-24 都做过了）。
8. ch21 到 ch24 四章的递进关系是什么？
四章递进：ch21 解决「怎么打包」→ ch22 解决「放哪/连谁」→ ch23 解决「怎么编排与对外」→ ch24 解决「怎么自动化」——每章的交付物都是下一章的前提。
9. 作业题「讲一讲你们的部署流程」的标准答法结构是？
作业题答法：先定位（AI 服务在微服务里的位置）→ 顺链路讲（两节点流水线→镜像→集群→入口）→ 划清自己的职责（Dockerfile 与应用侧）→ 兜底（可自建）——诚实框架 + 完整链路 = 高分答案。
