数据操作

本课目标

完成本课后，你将能：

  1. 说出 SQLAlchemy 的三种数据操作方式（Raw SQL / Core 表达式 / ORM）与各自适用场景
  2. 亲手演示 SQL 注入，并说清参数化绑定为什么能防住
  3. 用 session_factory 完成手动提交与 begin() 自动提交，说清 session 的三大能力
  4. 按「执行时机」说清 flush / commit / autoflush / expire_on_commit 的区别

知识速览

先花几分钟把核心机制过一遍——细节都在《05.数据操作》里，测验和面试会考。

三层数据操作（课件要点）

  • Raw SQL：text() + f-string 拼接——灵活但开发成本高、易出错、有注入风险、不适配方言
  • Core 表达式：insert/select/update/delete + Python 表达式条件（== 而非 =）——类型化、无注入、适配方言
  • ORM：操作 Python 对象，session.add() / 改属性 / session.delete()，SQLAlchemy 负责同步
  • 选型（课件总结）：简单 CRUD 用 ORM；复杂查询（聚合、批量更新）混用 Core；前两者都难处理才用 Raw SQL（必须参数化）

会话与执行时机

  • session_factory 单例：统一 class_=AsyncSession, expire_on_commit=False；begin() 块结束自动提交
  • flush：执行记录的操作，不提交；commit：先自动 flush，再提交
  • autoflush（默认 True）：session.execute() 前先把 pending 操作 flush 到数据库
  • expire_on_commit=True：提交后对象字段全部过期，再读字段会重新查询——损耗性能，通常关闭

分级测验

🌱 初级测验 · 概念

1. SQLAlchemy 提供了几种操作数据的方式？（作业题）
课件总结：简单 CRUD 用 ORM，复杂查询（聚合、批量更新）混用 Core 表达式，前两者都难处理才考虑 Raw SQL（注意注入）。
2. 课件里 search_products 用 f-string 直接拼 LIKE 条件，会有什么风险？
课件实测：输入 %' OR 1=1 -- 后全表暴露；delete_product_by_id("1 OR 1=1") 直接清空整张表。
3. 课件修复注入的方案是？
课件写法：text("SELECT * FROM product WHERE name LIKE :keyword") + {"keyword": f"%{keyword}%"}。数据库先解析 SQL 结构，参数值作为纯数据填入，输入永远不会被当作 SQL 指令执行。

🌿 中级测验 · 应用

4. Core 表达式里 where 条件怎么写？
课件注释：where() 用 Python 表达式构建条件——Python 的 == 而非 SQL 的 =。底层自动参数化绑定，从根上杜绝注入。
5. async with session_factory.begin() as session 里的 begin() 有什么作用？
课件对比：insert_with_manual_commit 用 with session_factory() 手动 await session.commit()；insert_with_auto_commit 用 begin() 块结束自动提交。
6. 课件总结里 session 的能力包括哪些？
课件总结三条：① 模型结合；② 统一管理事务；③ 记录操作、统一执行。session 是 ORM 的入口，不是建表或连接池的替代品。

🎯 高级测验 · 综合

7. flush 和 commit 有什么区别？（作业题）
课件执行时机第 1/2 条：session.flush() 执行记录的操作但不提交；session.commit() 先自动 flush，再提交。
8. autoflush=True（默认值）时，session.execute() 会发生什么？
课件执行时机第 3 条 + SQLAlchemy 官方文档：autoflush 是在 Session.execute() 等 SQL 执行方法开头发生的可配置自动 flush（针对 ORM 构造的 SQL）；autoflush=False 时仅执行传入 SQL，pending 操作保留不动。
9. expire_on_commit=True 时，提交后读取对象字段会发生什么？（作业题）
课件执行时机第 4 条：提交后 session 把关联对象每个字段标记为过期（可能已与数据库不一致），读取时重新查询同步。该配置损耗性能且带来其他问题，通常关闭（课件在 session_factory 里配了 expire_on_commit=False）。
