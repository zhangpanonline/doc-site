知识速览

先花几分钟把核心机制过一遍——细节与测验依据都来自官方文档 §24.1。

VACUUM 四个职责（官方原文）

  • ① 恢复或重用被更新/删除行占用的磁盘空间
  • ② 更新统计信息（规划器使用）——与 ANALYZE 职责重叠，可分开调
  • ③ 更新可见性映射——加速 Index Only Scan
  • ④ 防事务 ID 回卷导致的老旧数据丢失（官方原文）
  • 官方补充：每个原因指示不同的频率和范围执行 VACUUM

两种变体与配套

  • 标准 VACUUM：回收死元组空间供重用；快；可与生产操作并行（官方原文）；实测补充：会截断表尾部的空页——删除的是表尾数据时文件也会变小（pg16 实测 3.6MB→40KB），中部空洞则要 FULL
  • VACUUM FULL：收回更多空间、压缩表文件（含中部空洞）；慢得多；需独占锁——生产慎用
  • ANALYZE：收集统计（随机样本），规划器估算的基础
  • autovacuum：后台自动执行 VACUUM/ANALYZE 的守护进程——手动只是补充或替代（官方原文）

分级测验

即时反馈：点击选项立刻显示对错与解释。题目只考本课与官方文档覆盖的内容。

🌱 初级测验 · 概念

1. 官方说 VACUUM 必须怎样执行？
官方原文：PostgreSQL 的 VACUUM 命令出于几个原因必须定期处理每一个表。
2. VACUUM 的四个职责中，哪一个与「规划器估算」相关？
官方原文：更新被 PostgreSQL 查询规划器使用的数据统计信息——ANALYZE 的职责所在。
3. 「更新可见性映射」的收益是什么？
官方原文：更新可见性映射，它可以加速只用索引的扫描。

🌿 中级测验 · 应用

4. 标准 VACUUM 与 VACUUM FULL 的官方对比是？
官方原文：VACUUM FULL 可以收回更多磁盘空间但是运行起来更慢；标准形式可以和生产数据库操作并行运行。
5. autovacuum 的角色（官方）是？
官方原文：手动 VACUUM 用于对守护进程（autovacuum）的活动进行补充或者替换。
6. 官方说四个职责的执行频率应该怎样？
官方原文：每一个原因都将指示以不同的频率和范围执行 VACUUM 操作——因此 VACUUM 与 ANALYZE 可以分开调度。

🎯 高级测验 · 综合

7. 「事务 ID 回卷」的危害是（官方）？
官方原文：保护老旧数据不会由于事务 ID 回卷或多元组 ID 回卷而丢失——这是 VACUUM 是「必须项」的原因。
8. 表膨胀严重（海量死元组），想彻底压缩表文件，但生产不能长时间停机。怎么办？
官方原文「标准 VACUUM 可与生产并行」——先标准版止损；FULL 需独占锁，放维护窗口或用 pg_repack 在线替代。
9. 某表频繁 UPDATE，autovacuum 被关闭，长期不 VACUUM。会依次出现哪些症状？
四职责逐一失守：空间不回收、统计不更新、可见性映射陈旧、回卷风险累积——官方「必须定期处理每一个表」的原因链。

最终考核

四道题覆盖本课全部要点——答完它们，日常维护就过关了。

考核一：VACUUM 与 ANALYZE 的分工是？
官方四个职责中统计信息只是其一，且「每个原因指示不同的频率和范围」——所以两者独立可调。
考核二：DELETE 十万行后表文件没变小，该怎么理解与处理？
标准 VACUUM 的语义就是「恢复或重用」而非缩小文件——文件缩小是 VACUUM FULL 的活，且代价大。
考核三：Index Only Scan 突然退化为回表（多出 heap fetch），VACUUM 四职责里哪个相关？
官方原文：更新可见性映射，它可以加速只用索引的扫描——映射陈旧时优化器无法确认行可见性，只能回表。
考核四：监控发现某表 n_dead_tup 持续增长且 autovacuum 迟迟不触发。合理的干预顺序？
先止损（手动 VACUUM 并行安全），再治本（autovacuum 配置或长事务/复制槽阻塞）——官方「手动是补充或替代」的正确用法。

四道考核全部答对，说明你掌握了日常维护——继续学习 pg-16 · 服务器配置。
