RETURNING 与 UPSERT

来源：官方文档 §6.4 + INSERT 命令参考（postgres.cn）非渡一课程内容预计 15–20 分钟9 道分级测验 + 4 道最终考核 + 面试实战

本课目标

完成本课后，你将能：

  1. 说出 RETURNING 的动机（官方原文：避免额外查询）与三大典型场景
  2. 写对 ON CONFLICT ... DO NOTHING / DO UPDATE，说清 conflict_target 的四种指定方式
  3. 解释 EXCLUDED 的语义，用 WHERE 子句做精细化的条件更新
  4. 识别「先 SELECT 再 INSERT/UPDATE」的竞态写法，并改写为 UPSERT

知识速览

先花几分钟把核心机制过一遍——细节与测验依据都来自官方文档 §6.4 与 INSERT 命令参考。

RETURNING：改完直接拿回行

  • 官方动机：避免执行额外的数据库查询来收集数据，难以可靠识别被修改行时更有价值
  • INSERT 返回默认数据：serial/identity 新分配的 id 最有用——INSERT ... RETURNING id
  • UPDATE 返回修改后的新内容（官方明确默认是新内容）；RETURNING * 简写按顺序取所有列
  • RETURNING 的写法与 SELECT 输出列表规则相同，INSERT ... SELECT 同样支持

UPSERT：ON CONFLICT

  • DO NOTHING：冲突跳过——幂等批量导入
  • DO UPDATE SET：冲突更新；EXCLUDED.列名 引用「本应插入的那行」的值
  • conflict_target：列/表达式列表 · ON CONSTRAINT 约束名 · 部分唯一索引 WHERE 谓词 · 缺省（任意唯一冲突）
  • WHERE 条件：DO UPDATE ... WHERE 新值更大 只更新满足条件的冲突行

分级测验

即时反馈：点击选项立刻显示对错与解释。题目只考本课与官方文档覆盖的内容。

🌱 初级测验 · 概念

1. 官方文档说 RETURNING 的主要价值是什么？
官方原文：使用 RETURNING 可以避免执行额外的数据库查询来收集数据，尤其在难以可靠识别被修改行时更有价值。
2. INSERT INTO users(...) VALUES (...) RETURNING id; 中，id 是 serial 列时返回什么？
官方原例：serial 列提供唯一标识符时，RETURNING 返回分配给新行的 ID——这正是「依赖计算的默认值」的典型场景。
3. UPDATE 语句中 RETURNING 默认返回什么内容？
官方原文：在一个 UPDATE 中，提供给 RETURNING 的默认数据是修改后行的新内容。

🌿 中级测验 · 应用

4. ON CONFLICT DO NOTHING 的行为是？
DO NOTHING = 什么都不做地跳过冲突行——幂等批量导入的标准姿势，不会报错也不会覆盖。
5. DO UPDATE SET name = EXCLUDED.name 中，EXCLUDED 指什么？
EXCLUDED 是 UPSERT 专用别名：引用「本应插入的那行」的列值——SET 里用它取「新来的值」，区别于表内现有行的值。
6. conflict_target 的指定方式不包括下列哪种？
官方语法三种：列/表达式列表、ON CONSTRAINT 约束名、部分索引谓词——外加完全缺省（任意唯一冲突都触发）。「按行数据内容」不是合法指定。

🎯 高级测验 · 综合

7. AI 写「先 SELECT 查是否存在，再决定 INSERT 还是 UPDATE」。在并发场景这有什么问题？
SELECT 与 INSERT 之间其他事务可以插入同一行——这就是 TOCTOU 竞态。UPSERT 把「检测冲突 + 决定动作」交给数据库原子完成。
8. DO UPDATE SET score = EXCLUDED.score WHERE EXCLUDED.score > users.score 的作用是？
DO UPDATE 支持 WHERE：只更新满足条件的冲突行——「只允许分数上涨」这类业务规则可以原子地落在一条 SQL 里。
9. 批量导入 CSV 时想「重复行静默跳过、并统计实际插入数」，最佳组合是？
DO NOTHING 是幂等导入标准姿势；配合 RETURNING 可拿到实际插入的行做统计（跳过行不返回）。

最终考核

四道题覆盖本课全部要点——答完它们，RETURNING 与 UPSERT 就过关了。

考核一：用户表以 email 唯一，需要「存在则更新昵称、不存在则插入」，正确的单条语句是？
UPSERT 一条语句原子完成：冲突检测走唯一约束（email），冲突时用 EXCLUDED 的新值更新。
考核二：INSERT ... ON CONFLICT DO UPDATE ... RETURNING id，冲突被更新的行会返回吗？
RETURNING 对整条语句生效：插入的行与 DO UPDATE 更新的行都会返回——拿回 id 用于后续逻辑时插入/更新路径统一。
考核三：积分系统要「只允许分数上涨」的幂等上报，为什么 WHERE 条件必须写在 DO UPDATE 里而不是应用层判断？
「检测冲突 + 比较新旧值 + 决定是否更新」必须在同一条语句的锁保护下完成；应用层先读再写，两个并发上报仍可能同时通过判断。
考核四：表只有主键唯一约束，INSERT 省略 conflict_target 直接写 ON CONFLICT DO NOTHING，合法吗？
conflict_target 可以完全缺省：此时任意唯一约束或唯一索引冲突都触发冲突动作——多约束场景的便捷写法。

四道考核全部答对，说明你掌握了 RETURNING 与 UPSERT——继续学习 pg-03 · 子查询与集合运算。
