接入路线：四步，一个配置中心

  • 本章 to do list（原文四条）：① mcp 独立配置；② 进一步封装描述和工具；③ 注册工具；④ 修改系统提示词模板和注入
  • ① 独立配置 agent/.agents/mcp.json：servers 下每台服务器自带 type——{"time": {"type": "stdio", "command": "uvx", "args": ["mcp-server-time"]}} 与 {"microsoft-learn": {"type": "http", "url": "https://learn.microsoft.com/api/mcp"}}
  • ②③ 封装与注册：把 MCP 客户端封装成一个 普通工具 use_mcp，再和其他工具一样 registry.register(use_mcp)——Agent 眼里它和 read_file、bash_command 没有区别
  • ④ 提示词注入：list_mcp_info() 把所有服务器的工具清单序列化成 JSON，经 render_prompt(mcp_servers=...) 落到 system.j2 的 # MCP 小节——模型因此「知道有哪些远程工具可用」
  • 四步演示（课件原文）： 
    from agent.agent import Agent
from agent.printer import ModelPrinterListener

listener = ModelPrinterListener()
agent = Agent(model_listener=listener)

agent.session.print_friendly()   # 先看看系统消息里注入了什么
agent.invoke("当前时间是？")      # 模型 → use_mcp → time 服务器 → 时间字符串
agent.session.save()             # 会话落盘

骨架一：connect_mcp 与 run_async

  • 配置在导入时就加载：模块顶层 open(.../.agents/mcp.json) → mcp = json.load(_f)，随后 _client = MCPClient(mcp)——所以配置写错会在 import 阶段就炸
  • 两条传输分支（@asynccontextmanager）： 
    if server_config["type"] == "stdio":
    params = StdioServerParameters(
        command=server_config["command"], args=server_config.get("args", []))
    async with stdio_client(params) as (read, write):
        async with ClientSession(read, write) as session:
            await session.initialize()          # 握手：版本 + 能力协商
            yield session
elif server_config["type"] == "http":
    async with streamable_http_client(server_config["url"]) as (read, write, _):
        async with ClientSession(read, write) as session:
            await session.initialize()
            yield session
else:
    raise ValueError(f"不支持的服务器类型: {server_config['type']}")
  • run_async：线程里的 asyncio.run：Agent 主循环是同步的，而 MCP SDK 只给异步 API——于是开一个 threading.Thread，在里面 asyncio.run(coro)，用 nonlocal result, error 把结果或异常带回来，最后在主线程 raise error
  • MCPClient 四个方法一一对应：alist_tools() / acall_tool() 是异步实现，list_tools() / call_tool() 只是 run_async(...) 的同步包装；模块级函数 list_mcp_tools() 返回 _client.list_tools()
  • 工具签名：@tool(server_name="mcp服务器的名称", tool_name="工具名称", arguments="工具参数，无参工具可以不用传递") 装饰 use_mcp(server_name, tool_name, arguments=None)，函数体只有一行——return _client.call_tool(server_name, tool_name, arguments)

骨架二：提示词注入链路与三处错误处理缺口

  • 注入链路：list_mcp_info() → list_mcp_tools() → 每个服务器一条 {"server": 名字, "tools": [{name, description, inputSchema}, …]} → json.dumps(result, ensure_ascii=False, indent=2) → render_prompt(..., mcp_servers=list_mcp_info()) → system.j2 的 MCP 小节里 {{ mcp_servers }} 被包在 ```json 代码块中
  • 缺口 ①：静默降级——list_mcp_info() 整个函数体包在 try / except Exception 里，异常一律 return ""。好处是 MCP 挂了不阻塞对话；代价是模型看到的工具清单变成空串，而提示词仍然告诉它「可以用 use_mcp」，日志里也没有任何痕迹
  • 缺口 ②：KeyError 抛穿循环——MCPClient.acall_tool 里是 config = self.servers[server_name]。模型把服务器名写错时字典下标直接抛 KeyError，run_async 在主线程重抛，异常穿过 tool(**args)、registry.invoke，把整个 ReAct 循环打断——模型连「名字写错了」这条反馈都拿不到
  • 缺口 ③：Session.__init__ 双次渲染——if not system_prompt: system_prompt = render_prompt("system") 之后，注入时又写了一次 render_prompt("system")：传入的自定义提示词被丢弃，且 render_prompt 被调用两次。接入 MCP 后它的代价从「渲染一段文本」升级为「真实连接每台 MCP 服务器」，这就是下一题（高级第 7 题）要推演的账
  • 顺带一提：session.py 的 print_friendly 里出现了 except json.JSONDecodeError, TypeError:——这是 Python 2 的旧写法，在 Python 3 下文件根本无法通过语法解析（应写成 except (json.JSONDecodeError, TypeError):）

🌱 初级测验 · 概念

1. 本章 agent/ 工程相对上一章的变更账目是？
课件原文：「本章 agent/ 工程相对上一章的变更：新增 0 个文件、修改 5 个文件」，随后逐一给出这 5 个文件的全文。.agents/mcp.json 属于配置，不在这次的「文件变更」清单里；tool/use_mcp.py 是「修改」而不是「新增」，说明它在上一章（MCP Client）已经存在。
2. use_mcp 这个工具要求模型传入哪三个参数？
装饰器原文：@tool(server_name="mcp服务器的名称", tool_name="工具名称", arguments="工具参数，无参工具可以不用传递")，函数签名是 def use_mcp(server_name: str, tool_name: str, arguments: dict = None)。command/url 是 mcp.json 里的连接配置，不该由模型提供——模型只负责选「哪台服务器上的哪个工具、传什么参数」。
3. MCP 服务器的连接配置写在哪里？最终注册进 registry 的是哪个工具？
to do 第一条就是「mcp 独立配置」，落地为 .agents/mcp.json（例如 time 走 stdio 的 uvx mcp-server-time，microsoft-learn 走 http）。use_mcp.py 末尾用 @tool(...) 把 use_mcp 包装成工具，tool/__init__.py 里 registry.register(use_mcp)。connect_mcp 是异步上下文管理器、list_mcp_tools 是查询函数，两者都不是 Tool。

🌿 中级测验 · 应用

4. run_async() 为什么要专门开一个线程、在里面跑 asyncio.run(coro)？
Python 官方文档对 asyncio.run 的两条硬约束是判据：「This function cannot be called when another asyncio event loop is running in the same thread.」以及「This function should be used as a main entry point for asyncio programs, and should ideally only be called once.」本章的调用方是同步的 query()，所以用 threading.Thread 开一块干净地盘，让 asyncio.run 在那里建循环、跑协程、关循环。它不是性能优化：t.join() 会把主线程阻塞到结束，多台服务器仍是串行。异常传递靠 nonlocal result, error 暂存，回到主线程再 raise error。
5. connect_mcp 的两条分支分别怎么写？配置里的 type 不认识时又会怎样？
对照课件代码：stdio 分支构造 StdioServerParameters(command=server_config["command"], args=server_config.get("args", []))，用 async with stdio_client(params) as (read, write) 拿到读写流；http 分支用 async with streamable_http_client(server_config["url"]) as (read, write, _)（注意是三个返回值）。两条分支随后完全一致：ClientSession(read, write) → await session.initialize() → yield session。else 分支明确 raise ValueError——写错 type 不会被静默忽略。
6. list_mcp_info() 做了什么？它的返回值最后出现在哪里？
代码链路：list_mcp_info() 内部 from agent.tool.use_mcp import list_mcp_tools → 遍历 item["server"] 与 item["tools"].tools（ListToolsResult 的 tools 字段）→ 抽 name/description/inputSchema → json.dumps(result, ensure_ascii=False, indent=2)；except Exception: return ""。render_prompt 的渲染上下文新增 mcp_servers=list_mcp_info()，模板侧是 # MCP 小节 + 「当前可用的 MCP 服务器及工具」+ ```json 代码块包住 {{ mcp_servers }}。注意它是「给模型看的清单」，不是「注册给模型调用的工具」。

🎯 高级测验 · 综合

7. 推演 Session.__init__ 的这两行：if not system_prompt: system_prompt = render_prompt("system") 之后紧跟 self.add_message({"role": "system", "content": render_prompt("system")})。接入 MCP 之后，代价为什么明显变大？
两个问题：① 局部变量 system_prompt 赋值完就被丢掉，注入用的是新一次 render_prompt("system")——所以 Session(system_prompt="我的提示词") 完全无效；② 双次渲染在接入 MCP 前只是多渲染一段文本，接入后 render_prompt 里多了 mcp_servers=list_mcp_info()，而 list_mcp_info → list_mcp_tools → MCPClient.alist_tools 会对 self.servers 逐台 connect_mcp：每台都要先 initialize（官方规范规定初始化握手必须是客户端与服务器的第一次交互）再 list_tools。所以新建一次 Session 的发现开销是 $2 \times N_{\text{servers}}$ 条连接链，本章配置下 N=2（含一台走公网的 Microsoft Learn）就是 4 条，且都是同步阻塞的。修法：只渲染一次并复用局部变量；进一步把清单缓存起来（进程级/会话级 + TTL），或把工具发现从构造函数里挪出去。
8. 模型把 server_name 写成了 "times"（mcp.json 里只有 time）。这一轮会发生什么？
三处代码叠起来看：MCPClient.acall_tool 里是字典下标 config = self.servers[server_name]（不是 .get），缺键抛 KeyError；run_async 在子线程里 try/except Exception 把异常存进 error，回到主线程 if error: raise error 原样重抛；_ToolRegistry.invoke 只是 result = tool(**args)，没有任何 try/except。于是异常一路上抛、打断 ReAct 循环。这与本章「统一错误处理」的目标正好相反：对 Agent 来说，参数写错应该是一句可读的环境反馈（role=tool 内容），而不是让会话崩掉。修法是把 server_name/tool_name 的校验失败翻译成字符串返回值，或给 _client.call_tool 包一层 try/except。
9. 下面哪一条对 agent.invoke("当前时间是？") 整条链路的描述与本章代码一致？
链路的关键是「MCP 工具不是独立注册的工具」：registry 里只有 use_mcp 这一个网关卡，模型按提示词里的清单选服务器与工具名。stdio 那台由 uvx mcp-server-time 起子进程（配置里 command/args 就是干这个的），握手后才能 call_tool；返回值经 registry.invoke 组装成 {"role": "tool", "tool_call_id": ..., "name": "use_mcp", "content": ...} 回到上下文，下一轮模型据此生成自然语言回答。time 服务器提供的工具名与时区参数，与上一章《25.MCP Client》里 get_current_time + {"timezone": "Asia/shanghai"} 的演示一致——本章只是把它接进了 Agent 的工具集。
