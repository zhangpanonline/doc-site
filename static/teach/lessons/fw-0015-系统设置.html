知识速览

先花几分钟把核心机制过一遍——细节都在《15.系统设置》里，测验和面试会考。

声明式配置 + 启动同步

  • SETTINGS_DTO：frozen dataclass 定义设置组与设置项（key/value/display_name/description）——代码即配置清单
  • initialize()：启动时把数据库收敛到 DTO——DTO 有而库没有 → 建；DTO 没有而库有 → 删；都在 → 同步 display_name/description（value 不动，保留用户配置）
  • lifespan：asynccontextmanager 启动阶段跑 initialize，yield 前完成
  • update_settings：只改 value（按 key 批量 in 查询），display_name 等由 DTO 管

模型与落地流程

  • SettingGroup：key 唯一；Setting：group_id 外键 CASCADE + (group_id, key) 联合唯一
  • 落地三层：模型层（复制模型+登记+迁移）→ 业务层（DTO/service/测试×2+跑测）→ API 层（API/main/测试×2+跑测+查文档+手测+冒烟+提交）

分级测验

🌱 初级测验 · 概念

1. 课件落地流程分几层？总共几步？
课件落地流程：模型层（复制模型→登记 model/__init__→迁移）；业务层（复制 DTO→service→两类测试→跑测）；API 层（复制 API→main→两类测试→跑测→查文档→手测→冒烟→提交）。
2. SETTINGS_DTO 是什么？
课件 service 顶部：SETTINGS_DTO: list[SettingGroupDef] 用 frozen dataclass 声明 aliyun_oss 组与 5 个设置项——数据库里有什么设置，由这份清单决定。
3. Setting 表上 (group_id, key) 的联合唯一约束叫什么、防什么？
课件 model/setting.py：__table_args__ = (UniqueConstraint("group_id", "key", name="uq_setting_group_key"),)——同组内 key 唯一，跨组同名 key 允许。

🌿 中级测验 · 应用

4. initialize 的「双向同步」具体怎么双向？
课件 initialize 三段：① 遍历 SETTINGS_DTO 建/更新组；② 删除库中多余的组；③ 逐组建/删设置项、同步 display_name/description——value 只在 update_settings 里由用户改，initialize 不覆盖。
5. initialize 放在 lifespan 里而不是路由里，为什么？
课件 main.py：@asynccontextmanager lifespan 在 yield 前 await SettingService(session).initialize()——应用开始接请求前设置表已就绪，GET /api/settings 永远有数据；且不会每个请求都跑一遍同步。
6. update_settings 为什么用 select(Setting).where(key.in_(keys)) 一次查询？
课件 update_settings：update_map 建 key→value 后 in_ 一次取回所有目标行，逐个改 value 再 flush——N 个设置项 1 次查询；没匹配到的 key 静默忽略（新键由 DTO/initialize 负责）。

🎯 高级测验 · 综合

7. initialize 里先建组再 flush、再建设置项，为什么必须分两步？
课件 initialize：建完组 await self.db.flush()（不提交但发出 INSERT、拿回 id），随后 Setting(group_id=db_group.id) 才能挂外键；新组的查询再 select 一次也是为拿 id——ch05 的执行时机知识在此落地。
8. 数据库里出现了一个 SETTINGS_DTO 里没有的组，会发生什么？
课件 initialize 第二段：for group_key in set(db_groups.keys()) - dto_group_keys：先删该组所有 setting，再删组——库向 DTO 收敛。反向「加进 DTO」做不到（代码是源），这正是声明式配置的含义。
9. 课件落地流程 API 层最后三步是「检查接口文档→手动测试→冒烟测试→提交」，体现了什么？
落地流程把前 12 章串起来：查接口文档（ch10 信封 schema 是否同步）、手测一次（ch12 测试无法覆盖一切）、冒烟（ch12 红线）——自动化测试之后仍留人工关卡，最后才提交。
