知识速览

先花几分钟把核心机制过一遍——细节都在《09.统一异常处理》里，测验和面试会考。

五条最佳实践（作业题考点）

  • ① 异常的自定义处理收拢到统一代码位置
  • ② 请求-响应链条中的异常不能中断服务器
  • ③ 服务端的敏感信息不能暴露给响应
  • ④ 按异常类型响应不同字段：status code / code（业务码）/ message
  • ⑤ API 文档中需要包含全局异常表

全局处理器机制

  • ERROR_MAP：异常类型 → (业务错误码, HTTP 状态码, 默认消息)——硬编码字典，设计即文档
  • _lookup：按 type(exc).__mro__ 逐级查表，找不到回退到 Exception 兜底（500001）
  • 三路分支：HTTPException 走协议表；RequestValidationError 拼 loc: msg；BusinessException 用 message；未知异常用默认消息
  • 三处注册：add_exception_handler 覆盖 RequestValidationError / HTTPException / Exception

🌱 初级测验 · 概念

1. 统一异常处理五条最佳实践，第一条是？
课件五条之首：自定义处理收拢到统一位置——本课的 handler/handlers.py 就是那个位置，全站异常走一个 exception_handler。
2. 课件「现状」里，业务层抛出的 BusinessException 原来被谁处理？
课件现状清单：BusinessException 在业务层主动抛出，被 FastAPI 当做 Exception 自动处理——拿不到业务错误码与定制消息，这就是要统一处理的动机。
3. 响应字段设计里，status code / code / message 分别是什么？
课件最佳实践第 4 条：status code 是 HTTP 响应码；code 是错误业务码（如 404001/422001/500001，同一 HTTP 码下可细分）；message 是错误消息。

🌿 中级测验 · 应用

4. ERROR_MAP 里 RequestValidationError 和 DatabaseException 的 code 为什么可以相同？
课件 errors.py：两者都是 ("422001", 422, "数据验证错误")——客户端收到 422001 就知道「我的数据不对」，无论底层是 Pydantic 校验还是数据库约束冲突。
5. _lookup 为什么按 type(exc).__mro__ 逐级查找？
课件 _lookup：for exc_type in type(exc).__mro__ 查 ERROR_MAP，命中即返回；NotFoundException 没直接登记也能命中 BusinessException 分支……实际 NotFoundException 在表里，兜底靠 Exception: ("500001", 500, "服务器内部错误")——未知异常绝不裸奔。
6. HTTPException 分支里，body 消息去哪找？
课件 handlers.py：isinstance(exc, HTTPException) 分支——code=str(status_code)，body 用 PROTOCOL_ERROR_MAP.get(exc.status_code, exc.detail)。404/405/415 有定制文案，其余协议错误透出 detail。

🎯 高级测验 · 综合

7. RequestValidationError 的 message 是怎么拼出来的？
课件 _format_validation_error：loc = ".".join(str(p) for p in err["loc"])，返回 f"{loc}: {err['msg']}"——把 Pydantic 的结构化错误转成人话，多条用换行拼接。
8. 为什么 API 层把 HTTPException(404) 换成 NotFoundException？
课件 api 三文件统一改动：raise NotFoundException(message="商品不存在")。好处：① 业务码 404001 由处理器统一生成，接口层不碰响应格式；② 将来改响应结构（加 request_id 等）只改 handler；③ 与 ch07 边界原则一致——接口层只声明「发生了什么」，怎么响应是统一设计的事。
9. 接口文档里的全局异常表是怎么来的？（作业题关联）
课件 docs.py：遍历两张映射表生成「业务错误/协议错误」两个 markdown 表，main.py 里 description=generate_error_docs() 注入——错误码字典是单一数据源，文档随配置自动同步（最佳实践第 5 条）。
