  2. 解释这门课为什么只讲「与 Agents 应用开发相关」的部分

知识速览

先花几分钟把课程的骨架过一遍——细节都在《01.课程导言》里，测验和面试会考。

四个库的分工

  • NumPy & Pandas：数据分析和科学计算的基石，是 Agent 处理结构化数据的核心工具
  • Matplotlib & Seaborn：把枯燥的数据转化为直观图表，是 Agent「秀出」分析成果的关键
  • 一句话记忆：前两个管「算」，后两个管「看」

课程定位（最重要的一条）

  • 目标是为 Agents 应用开发做准备——不是模型训练、微调、部署或推理
  • 讲四个库时只讲与 Agents 应用开发相关的内容：够用、能用、能读懂 AI 给出的代码
  • 因此不铺陈统计学体系，也不穷举可视化样式——重点在「读懂 + 改造 + 验证」

课程地图与工具链

  • 依赖顺序：Jupyter → NumPy（核心概念 → 数据操作）→ Pandas（数据类型 → 数据清洗）→ Matplotlib（核心概念 → 动画 → 交互式组件）→ Seaborn
  • Pandas 建立在 NumPy 之上：Series / DataFrame 的底层就是 ndarray，所以先学 NumPy
  • 工程管理：uv（uv add <package>）；课件全部是 .ipynb，用 VS Code 的 Jupyter 插件运行
  • 解释器：必须选本工程虚拟环境里的 Python

🌿 中级测验 · 应用

4. 课程为什么把 NumPy 排在 Pandas 之前？
Pandas 是建立在 NumPy 之上的数据处理库：不理解 ndarray 的 shape / dtype / axis，后面 Pandas 的广播与对齐就很难真正看懂。
5. 课件为什么要用 Jupyter Notebook，而不是普通 .py 文件？
数据处理的真实工作方式是「读入 → 试探性转换 → 观察中间结果」循环，Notebook 的分段执行 + 即时输出正好匹配；与运行速度、中文、虚拟环境都无关。
6. 安装依赖时用 uv add numpy 而不是 pip install numpy，主要区别是？
uv 是工程级的依赖管理：uv add 会把依赖登记进工程的 pyproject.toml 并锁定版本（uv.lock），换台机器 uv sync 就能复现同一套环境；pip 只影响当前环境，无法随工程交接。

🎯 高级测验 · 综合

7. 一个 Agent 要「读一份 CSV，算出各城市薪资中位数，画成柱状图返回给用户」，四个库的分工链路是？
链路：Pandas 负责读入与分组，分组聚合的底层数值运算由 NumPy 承担，绘图交给 Matplotlib，统计类图表的样式与默认聚合由 Seaborn 接管。课程正是按这条链路排的章序。
8. 「只讲与 Agents 应用开发相关的内容」这条约束，意味着本课程不做哪些事？
课件「项目背景」原文：为 Agents 应用开发做准备，而非模型训练、微调、部署或推理；内容范围限定在「讲解这些库时只讲与 Agents 应用开发相关的内容」。课程后面用真实招聘数据做清洗与可视化，恰恰说明不是不用真实数据。
9. AI 生成的代码里有 import numpy as np，运行却报 ModuleNotFoundError: No module named 'numpy'。在 Notebook 里最可能的根因与正确修法是？
课件「课件规范」要求：Jupyter 的 Python 解释器必须使用当前工程的虚拟环境，切勿使用其他环境。装到了别处、解释器选了系统 Python，就会出现「明明装了却 import 不到」。
