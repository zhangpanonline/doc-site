知识速览

先花几分钟把核心机制过一遍——细节都在《30.断点调试》里，测验和考核会考。

调试链路

调试客户端（VSCode） ─ DAP 协议 ─▶ 调试适配器（debugpy） ─ 控制 ─▶ 被调试程序（demo.py）

⚙️ sys.settrace 是「适配器」观察程序的最小实现：每个事件（line/call/return）回调一次 tracer。

三个要点

  1. settrace 的 tracer 回调三个参数：frame（当前栈帧，f_lineno 行号）、event（line/call/return 等事件）、arg；返回自身以持续追踪。官方文档：sys.settrace
  2. launch vs attach：launch 由调试器启动程序（单文件调试用 ${file}）；attach 连接已在运行的程序（工程调试：debugpy 监听 5678 端口等待客户端）。官方文档：debugpy
  3. 工程调试三步：uv add --dev debugpy → Makefile 里 python -m debugpy --listen 5678 --wait-for-client 入口 → 客户端 attach localhost:5678。

基础测验

点击选项立即获得反馈。答错也没关系——仔细读解释，它会把文档里对应的小节指给你。

1. 调试的三大组件是？
客户端（VSCode）通过调试协议（DAP）与适配器（debugpy）通信，由适配器控制被调试程序。详见「调试组件」图。
2. sys.settrace(my_tracer) 中 tracer 的 event 参数不会出现哪个值？
tracer 的 event 是解释器执行事件：line（执行一行）、call（调用函数）、return（函数返回）、exception 等。click 是 GUI 事件，与解释器无关。
3. tracer 回调的 frame 参数有什么用？
frame.f_lineno 是当前执行到的行号——适配器核心逻辑就是打印「事件 + 行号」来观察程序执行轨迹。详见「调试适配器的核心逻辑」。
4. launch.json 中单文件调试的 type 字段是？
"type": "debugpy" 指定使用 debugpy 调试适配器；"program": "${file}" 用当前打开的文件。详见「单文件调试」配置。
5. launch 与 attach 调试模式的区别是？
request: "launch" 是调试器拉起程序；request: "attach" 是程序先跑起来（debugpy 监听端口），调试器再连上去。工程调试用 attach。详见「工程调试」一节。
6. --wait-for-client 参数的作用是？
--wait-for-client 让被调试程序等待客户端 attach（否则程序可能已跑完，断点都来不及命中）。详见「配置调试器」。

最终考核

下面是《30.断点调试》源课程作业（复现 monorepo 工程的调试）的改编题——这就是本课的最终考核。规则：不查资料、不运行代码，先在心里选出答案，再点击核对。

考核一（settrace 预测）：用 settrace 追踪 demo.py（三行函数 + 调用 + print），tracer 打印的第一条记录是？
实测第一条是 call 事件（行号 0）——exec(code) 本身触发 call 事件；随后才是逐行 line 事件（行号 4、11…），调用 main() 时穿插 call、函数结束有 return 事件。事件顺序：call → line → call（main）→ line → return。
考核二（launch.json 配置）：调试「当前打开的文件」，正确的 launch.json 配置是？
单文件调试："type": "debugpy" + "request": "launch" + "program": "${file}"（当前打开的文件）。type 写 python/pdb 都不是 VSCode debugpy 扩展的名字 ✗；不写 program 不知道调谁 ✗。
考核三（attach 配置）：工程调试——debugpy 已监听 5678 端口，客户端 attach 配置正确的是？
attach 配置："request": "attach" + "connect": {"host": "localhost", "port": 5678}——与 debugpy 的 --listen 5678 对应。launch 会试图自己启动程序（重复启动）✗。
考核四（工程调试复现）：monorepo 里给 web-service 配调试，Makefile 目标正确的是？
工程调试命令三要素：--package web-service 用成员依赖环境；python -m debugpy --listen 5678 --wait-for-client 启动适配器并等客户端；最后是被调试入口。第二个不监听无法 attach ✗；第三个没经过调试器 ✗；第四个端口随意且不是调试器用法 ✗。
