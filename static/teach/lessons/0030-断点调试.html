知识速览

先花几分钟把核心机制过一遍——细节都在《30.断点调试》里，测验和考核会考。

调试链路

调试客户端（VSCode） ─ DAP 协议 ─▶ 调试适配器（debugpy） ─ 控制 ─▶ 被调试程序（demo.py）

⚙️ sys.settrace 是「适配器」观察程序的最小实现：每个事件（line/call/return）回调一次 tracer。

三个要点

  1. settrace 的 tracer 回调三个参数：frame（当前栈帧，f_lineno 行号）、event（line/call/return 等事件）、arg；返回自身以持续追踪。官方文档：sys.settrace
  2. launch vs attach：launch 由调试器启动程序（单文件调试用 ${file}）；attach 连接已在运行的程序（工程调试：debugpy 监听 5678 端口等待客户端）。官方文档：debugpy
  3. 工程调试三步：uv add --dev debugpy → Makefile 里 python -m debugpy --listen 5678 --wait-for-client 入口 → 客户端 attach localhost:5678。

分级测验

点击选项立即获得反馈。答错也没关系——仔细读解释，它会把文档里对应的小节指给你。三级难度：初级考概念，中级考应用，高级考综合与陷阱。

🌱 初级测验 · 概念

1. 调试的三大组件是？
客户端（VSCode）通过调试协议（DAP）与适配器（debugpy）通信，由适配器控制被调试程序。详见「调试组件」图。
2. launch.json 中单文件调试的 type 字段是？
"type": "debugpy" 指定使用 debugpy 调试适配器；"program": "${file}" 用当前打开的文件。详见「单文件调试」配置。
3. tracer 回调的 frame 参数有什么用？
frame.f_lineno 是当前执行到的行号——适配器核心逻辑就是打印「事件 + 行号」来观察程序执行轨迹。详见「调试适配器的核心逻辑」。

🌿 中级测验 · 应用

4. launch 与 attach 调试模式的区别是？
request: "launch" 是调试器拉起程序；request: "attach" 是程序先跑起来（debugpy 监听端口），调试器再连上去。工程调试用 attach。详见「工程调试」一节。
5. --wait-for-client 参数的作用是？
--wait-for-client 让被调试程序等待客户端 attach（否则程序可能已跑完，断点都来不及命中）。详见「配置调试器」。
6. sys.settrace(my_tracer) 中 tracer 的 event 参数不会出现哪个值？
tracer 的 event 是解释器执行事件：line（执行一行）、call（调用函数）、return（函数返回）、exception 等。click 是 GUI 事件，与解释器无关。

🎯 高级测验 · 综合

7. 用 settrace 追踪 exec(code)，tracer 打印的第一条记录是？
实测第一条是 call 事件（行号 0）——exec(code) 本身触发 call 事件；随后才是逐行 line 事件，调用函数时穿插 call、函数结束有 return。事件顺序：call → line → call（函数）→ line → return。
8. 工程调试——debugpy 已监听 5678 端口，客户端 attach 配置正确的是？
attach 配置："request": "attach" + "connect": {"host": "localhost", "port": 5678}——与 debugpy 的 --listen 5678 对应。launch 会试图自己启动程序（重复启动）✗。
9. monorepo 里给 web-service 配调试，Makefile 目标正确的是？
工程调试命令三要素：--package web-service 用成员依赖环境；python -m debugpy --listen 5678 --wait-for-client 启动适配器并等客户端；最后是被调试入口。第二个不监听无法 attach ✗；第三个没经过调试器 ✗；第四个端口随意且不是调试器用法 ✗。

最终考核

下面是《30.断点调试》源课程作业（复现 monorepo 工程的调试）的改编题——这就是本课的最终考核。规则：不查资料、不运行代码，先在心里选出答案，再点击核对。

考核一（settrace 预测）：用 settrace 追踪 demo.py（三行函数 + 调用 + print），tracer 打印的第一条记录是？
实测第一条是 call 事件——exec(code) 本身触发 call 事件（源课程 demo 中行号为 0）；随后才是逐行 line 事件，调用 main() 时穿插 call、函数结束有 return 事件。事件顺序：call → line → call（main）→ line → return。关键点：首事件是 call 而不是 line。
考核二（launch.json 配置）：调试「当前打开的文件」，正确的 launch.json 配置是？
单文件调试："type": "debugpy" + "request": "launch" + "program": "${file}"（当前打开的文件）。type 写 python/pdb 都不是 VSCode debugpy 扩展的名字 ✗；不写 program 不知道调谁 ✗。
考核三（attach 配置）：工程调试——debugpy 已监听 5678 端口，客户端 attach 配置正确的是？
attach 配置："request": "attach" + "connect": {"host": "localhost", "port": 5678}——与 debugpy 的 --listen 5678 对应。launch 会试图自己启动程序（重复启动）✗。
考核四（工程调试复现）：monorepo 里给 web-service 配调试，Makefile 目标正确的是？
工程调试命令三要素：--package web-service 用成员依赖环境；python -m debugpy --listen 5678 --wait-for-client 启动适配器并等客户端；最后是被调试入口。第二个不监听无法 attach ✗；第三个没经过调试器 ✗；第四个端口随意且不是调试器用法 ✗。

💼 面试实战

下面是真实面试官会问的问题，选自中文互联网面试题集（出处附后）。先自己回答，再点击核对。三级面试难度：中级考应用，高级考陷阱，专家考机制与设计。

⚡ 中级面试题

面试题一（调试原理·高频）：Python 调试器（pdb/debugpy）是怎么「停住」程序的？
调试器的核心机制是 sys.settrace：向解释器注册追踪函数后，每个执行事件（line/call/return/exception）都会回调 tracer——调试器在其中检查断点、暂停执行、读取栈帧变量。debugpy 就是在 DAP 协议之上的工业级实现。出处：CSDN「100 道 Python 面试必背题目（基础理论 + 工程实践篇）」
面试题二（调试实践·追问）：线上/远程服务出问题时，你常用的排查手段？
工程实践的标准回答：① 完善日志（分级别、带上下文）是第一道防线；② 疑难问题用 debugpy attach 远程连接（--listen 端口）打断点排查；③ 最小复现（剥离无关代码缩小范围）；④ 事后补测试防回归。「生产环境 print」会被视为不专业的信号。出处同面试题一

🔥 高级面试题

面试题三（breakpoint 机制·深水区）：breakpoint() 与 PYTHONBREAKPOINT=0 环境变量的关系是？
breakpoint()（3.7+）是 import pdb; pdb.set_trace() 的内置化：其行为由 PYTHONBREAKPOINT 环境变量控制——设为 0 时全局禁用所有断点（防止调试代码泄漏到生产），设为别的调用名则可替换调试器。这解释了很多团队「生产环境必须设 PYTHONBREAKPOINT=0」的规范。出处：PHP 中文站「为什么 Python 异步代码比同步代码难调试」
面试题四（异步调试·陷阱）：VS Code 调试 asyncio 程序，断点「看起来跳过了 await 之后的行」，为什么？
await 之后的恢复调度发生在 asyncio 库内部——VS Code 默认 "justMyCode": true 只调试用户代码，调度帧被跳过，看起来像「断点跳行」。解法：launch.json 里设 "justMyCode": false，并确认协程确实被调度（否则断点打在「幻影函数」上）。出处同面试题三

🧠 专家面试题

专家题一（调试手段·工程）：循环跑了几百次才出问题，最快定位方式？
条件断点（断点上右键设条件，如 i == 500）让程序只在命中条件时暂停——循环类问题的定位神器；日志断点（logpoint）则在不暂停的情况下输出变量。熟练使用它们是调试效率的专家标志。出处：CSDN「100 道 Python 面试必背题目（工程实践篇）」
专家题二（调试策略·设计）：生产环境问题排查，为什么「先日志后断点」？
生产环境的标准策略：日志先行（分级、带上下文，可长期留痕、离线复现）；疑难问题才考虑远程 attach 断点——因为断点会暂停进程，生产请求被挂起甚至雪崩。日志是「可回放的事后证据」，断点是「交互式的事中手术」，场景决定手段。出处同专家题一
