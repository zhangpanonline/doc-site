知识速览

先花几分钟把核心机制过一遍——细节都在《21.部署-认识Docker》里，测验和面试会考。

镜像三件套与多阶段构建

  • Dockerfile：配置文件，通过它产生镜像（FROM/WORKDIR/RUN/COPY/ENV/EXPOSE/CMD）
  • 镜像：包含运行所需的一切（python、uv、.venv）；容器：镜像启动的实例，运行 CMD
  • 多阶段：builder 阶段装依赖（slim 镜像 + uv sync），最终镜像只 COPY .venv——构建产物小 90%
  • slim 镜像：比完整 python 镜像小 90%，提升构建速度与产物大小

docker run 六个生产参数

  • -d 后台运行；--name 命名；-p 9090:8080 宿主机:容器端口映射
  • -e 环境变量（环境配置全部注入：COMMON/WEB/DB/LOG 前缀）
  • --restart unless-stopped：意外退出/宿主机重启自动拉起（手动停止除外）
  • --memory=512m --cpus=1：资源上限，防单容器耗尽宿主机

分级测验

🌱 初级测验 · 概念

1. Docker 要解决的核心问题是什么？
课件三个问题：多应用环境互不干扰？准备环境文件的过程快捷高效？应用更新后快速更新？——「环境、文件、启动命令」的标准化。
2. Dockerfile 和镜像、容器的关系是？
课件定义：Dockerfile 一个配置文件，通过该文件产生一个镜像；容器通过镜像启动，启动时运行镜像中的 CMD。
3. 为什么选 python:3.14-slim 而不是完整 python 镜像？
课件 Dockerfile 注释：依赖轻量级 python 镜像，比完整镜像小 90%，提升构建速度和构建产物的大小。

🌿 中级测验 · 应用

4. RUN 和 CMD 的区别是？
课件注释：RUN 命令在镜像构建过程中执行（装 uv、uv sync）；CMD 将来启动镜像时需要执行的命令（uvicorn 启动）。
5. 多阶段构建里最终镜像为什么要 COPY --from=builder /app/.venv？
课件 Dockerfile：builder 阶段装好依赖（uv sync --no-dev --no-editable），最终镜像 COPY --from=builder /app/.venv + ENV PATH——构建工具链留在 builder 里，运行时镜像只含 .venv。
6. -p 9090:8080 的含义是？
课件参数表：-p (publish) 端口映射，宿主机 9090 → 容器内部 8080（应用在容器里监听 8080，对外暴露 9090）。

🎯 高级测验 · 综合

7. --restart unless-stopped 和「手动 docker stop」的关系是？
课件参数表：unless-stopped——容器意外退出或宿主机重启时自动重新启动（除非你手动停止了它）。生产默认策略。
8. 数据库连接、JWT 密钥这些配置在容器里怎么注入？
课件 duyi-service 启动示例：-e DB_HOST/-e DB_NAME/-e WEB_JWT_SECRET_KEY 等一串 -e——容器内应用仍走 .env/env 变量（ch02 配置体系），值在运行时注入，镜像不含环境差异。
9. 课件「容器简易部署流程」四步是什么？
课件四步：1 开发 → 2 本地 Dockerfile 构建镜像 → 3 将镜像传输给服务器 → 4 服务器运行容器。第 3 步在 ch24 会被镜像仓库（ACR）取代。
