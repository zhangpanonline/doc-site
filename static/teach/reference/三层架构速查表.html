三层架构速查表

配合《三层架构互动教学课程》使用。源课程：gitee.com/dev-edu/python-framework。

经典三层（对照本课代码）

层职责本课对应
接口层接请求、校验、回响应app/api/ + schema DTO
业务层业务规则、用例编排app/service/
数据层持久化与查询app/model/ + core/database

依赖方向：接口 → 业务 → 数据；下层不得反向 import 上层。middleware/exception 是横切关注点，不属于某层。

模型分化

模型定位User 示例字段
model持久化模型含 password_hash、is_deleted
BO业务对象，按用例聚合UserIdentity(username, password_hash) / UserInfo(email, phone)
DTO传输对象，只带客户端需要的id / username / email

转换发生在层边界（service 出口 model_validate → DTO）。password_hash 绝不出服务端边界。

依赖倒置

原则
依赖指向抽象，不指向具体实现。
本课落地
Depends(get_db) 注入会话；BusinessException → 全局处理器翻译 HTTP。
收益
换数据库/换框架/换入口（REST→WebSocket），业务层零改动。
