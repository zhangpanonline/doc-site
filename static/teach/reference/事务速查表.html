事务速查表

配合《事务互动教学课程》与《05.事务》使用。建议打印一份放在手边。

事务命令

BEGIN;                      -- 开启事务
-- …一组操作…
COMMIT;                     -- 提交，全部永久生效
ROLLBACK;                   -- 回滚，全部撤销
SAVEPOINT a;                -- 事务内存档点
ROLLBACK TO SAVEPOINT a;    -- 部分回滚（事务继续）
SHOW transaction_isolation; -- 查看隔离级别
SET TRANSACTION ISOLATION LEVEL READ COMMITTED;  -- 事务内设置

ACID

特性全称说明
A原子性 Atomicity要么全成功，要么全回滚
C一致性 Consistency前后都满足约束——最终目的
I隔离性 Isolation并发事务「应该」互不干扰
D持久性 Durability提交后永久生效，崩溃不丢

四种并行问题

问题一句话
脏读读到别人未提交、后被回滚的数据
不可重复读同一行两次读值变了（别人 UPDATE/DELETE 已提交）
幻读范围查询两次行数变了（别人 INSERT 已提交）
更新丢失后提交的修改覆盖先提交的

隔离级别矩阵（PostgreSQL）

隔离级别脏读不可重复读幻读更新丢失
READ COMMITTED（默认）❌可能可能可能
REPEATABLE READ❌❌❌可能
SERIALIZABLE❌❌❌❌

PG 无 READ UNCOMMITTED（设置后按 RC 处理）；PG 的 RR 基于快照防幻读（与 MySQL 不同）；MySQL/InnoDB 默认 RR。

场景选型

场景推荐级别
大多数 Web 应用、报表READ COMMITTED（默认够用）
财务系统、对账REPEATABLE READ
抢购、库存扣减、防超卖SERIALIZABLE

核心要点

  • 事务 = 打包操作，全成功或全失败
  • 转账两步必须同生共死——失败就 ROLLBACK
  • 一致性是目的，A/I/D 是手段
  • 行内值变 = 不可重复读；行数变 = 幻读
  • 级别越高隔离越好、并发越差
  • pgAdmin 会自动提交——演示事务先关掉它
