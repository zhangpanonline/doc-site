数据迁移速查表

配合《数据迁移互动教学课程》使用。源课程：gitee.com/dev-edu/python-framework。

三命令

命令底层作用
make db-migrate message="init"alembic revision --autogenerate对比模型与数据库，生成候选迁移脚本
make db-upgradealembic upgrade head执行迁移到最新版本
make db-downgrade version=-1alembic downgrade -1回退一步 / 回退到指定版本

env.py 配置要点

from app.core.config import db_settings
from app.model.base import Base

config.set_main_option("sqlalchemy.url",
    f"postgresql://{db_settings.user}:{db_settings.password}@"
    f"{db_settings.host}:{db_settings.port}/{db_settings.name}")

target_metadata = Base.metadata   # autogenerate 对比基准
  • 迁移用同步驱动 postgresql://（不需要 +asyncpg）
  • 模型必须经 app/model/__init__.py 显式 import，否则生成空迁移

红线与流程

禁区 1
手动修改数据库。
禁区 2
修改已执行过的迁移（脚本是常量，执行后永远不可变更）。
等式
迁移脚本执行完 == 本地最新状态 == 生产最新状态。
日常四步
改动模型 → 生成迁移 → 审查（数据丢失？迁移与回滚互逆？）→ 执行。
已执行的有问题
生成新迁移适配模型，审核后执行；不改不删历史迁移。
执行失败
看错误信息定位脚本，修复后重新运行。
回滚
尽量不用（结构≠模型带来更多 Bug）；不一致最多允许暂时，绝不能长期。
