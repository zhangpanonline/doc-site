推理机制速查表

配合《推理机制互动教学课程》使用。

两个阶段：Prefill 与 Decode

阶段在算什么运算形态瓶颈对应延迟指标
预填充 Prefill把整段输入一次送进模型，算出中间状态（keys/values），用来生成第一个新 token矩阵 × 矩阵，高度并行，能把 GPU 吃满算力首 token 延迟 TTFT
解码 Decode自回归地一次生成一个 token，直到命中停止条件矩阵 × 向量，算力用不满访存受限（数据从显存搬到计算单元的速度）相邻 token 间隔 ITL

两个指标必须分开看、分开调——用一个「平均速度」混着算会掩盖真实瓶颈。

K-V 缓存：用显存换计算

bytes per token = 2 × n_layers × (n_heads × d_head) × dtype_bytes
                 └─ K 与 V 两份

算例：Llama 2 7B（n_layers=32，d_model=4096，FP16 即 2 字节）
     2 × 32 × 4096 × 2 = 512 KB / token
为什么需要
Decode 每一步都要用到前面所有 token 的 K/V；不缓存就要每步重算，重复计算随序列长度急剧膨胀。
常见形态
多数实现里每一层都有自己的 K-V 缓存。
代价
批量推理时每个请求单独分配，占用随批量大小 × 序列长度线性增长——长上下文与 RAG 的吞吐瓶颈就在这里。

采样策略：Temperature / Top-K / Top-P

策略机制关键点
温度 TemperatureSoftmax 前把 logits 除以 $T$：$p_i = \dfrac{\exp(z_i/T)}{\sum_j \exp(z_j/T)}$$T=1$ 不干预；$T<1$ 更确定、$T>1$ 更随机；$T=0$ 即贪心
Top-K只从概率最高的 K 个词里采样，其余置零K 是固定数量（如 K=50）
Top-P（核采样）按概率从高到低累加，达到 P 即停，只从这个动态「核心」集合采样集合大小随分布自适应，所以比 Top-K 灵活
官方 API 口径：
  top_k：为下一个 token 考虑的最可能候选的“数量”
  top_p：考虑的最可能候选的“百分比”（如 0.8 → 概率分布的前 80%）

vLLM 工程细节：
  temperature=0 → 贪心，实现上强制 top_p=1.0、top_k=0、min_p=0.0
  top_k=0（或 -1）→ 含义是“考虑全部 token”

易错点

  • 把 Prefill 与 Decode 混为一谈，用一个吞吐数字评估两种负载
  • 以为 K-V 缓存是「免费的加速」——它用显存换计算，长上下文下显存先爆
  • 同时开 Top-K 与 Top-P 却不清楚谁先生效（先按 K 截断、再按 P 截断，语义会叠加）
  • 把「首 token 延迟」的优化手段用在「逐 token 间隔」上（两者瓶颈不同：算力 vs 访存）
