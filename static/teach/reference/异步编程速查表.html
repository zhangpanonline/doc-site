await asyncio.sleep(1)                 # 非阻塞等待
task = asyncio.create_task(coro())     # 包装协程并调度
results = await asyncio.gather(a(), b())                     # 并发，按传入顺序返回
results = await asyncio.gather(a(), b(), return_exceptions=True)  # 异常作为结果
done, pending = await asyncio.wait(tasks, return_when=asyncio.FIRST_COMPLETED)
async with asyncio.TaskGroup() as tg:  # 3.11+ 结构化并发，异常取消全组
    t1 = tg.create_task(a())
async with asyncio.timeout(2):         # 3.11+ 超时（TimeoutError）
    await slow()
await asyncio.wait_for(slow(), timeout=2)   # 旧式超时
await asyncio.to_thread(time.sleep, 1)      # 同步阻塞丢给线程池
lock / event / semaphore / queue       # asyncio.Lock() 等同步原语

三大陷阱与最佳实践

  • ❌ 协程里 time.sleep → 阻塞整个事件循环：改 await asyncio.sleep 或 await asyncio.to_thread(time.sleep, 1)。
  • ❌ 忘了 await 协程对象 → 永远不执行：asyncio.run(main(), debug=True) 会警告 "was never awaited"。
  • ❌ 手动 new_event_loop/run_forever：一律 asyncio.run(main()) 作入口。
  • ✅ CancelledError 清理后必须 raise：吞掉取消信号的任务会「赖着不走」。
  • ✅ 循环内取 loop 用 get_running_loop()：模块级 get_event_loop 可能拿错。
