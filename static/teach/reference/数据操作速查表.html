三种操作方式

方式特点适用场景
Raw SQL灵活高性能；开发成本高、易错、有注入风险、不适配方言前两者难处理的场景（小概率）
Core 表达式类型化、自动参数化、无注入、适配方言复杂查询（聚合、批量更新）
ORM操作 Python 对象，自动同步简单 CRUD

耗时操作（如 I/O）尽量不要放到一次连接中。

参数化绑定（防注入）

# 危险：拼接
sql = f"SELECT * FROM product WHERE name LIKE '%{keyword}%'"

# 安全：结构与数据分离
result = await conn.execute(
    text("SELECT * FROM product WHERE name LIKE :keyword"),
    {"keyword": f"%{keyword}%"})

数据库先解析 SQL 结构，参数值作为纯数据填入——输入永远不会被当作 SQL 指令执行。

会话与执行时机

session 三能力
模型结合；统一管理事务；记录操作、统一执行。
flush()
执行记录的操作，不提交。
commit()
先自动 flush，再提交。
autoflush
默认 True：execute() 等执行 SQL 前先把 pending 操作 flush 掉。
expire_on_commit
True 时提交后对象字段全部过期，再读字段触发重新查询——损耗性能，通常关闭。
refresh()
把数据库真实值同步回模型对象（expire_on_commit=False 时才可能需要）。
session_factory = async_sessionmaker(
    get_engine(),
    class_=AsyncSession,
    expire_on_commit=False)   # 单例统一配置

async with session_factory.begin() as session:  # 块结束自动提交
    session.add(product)
