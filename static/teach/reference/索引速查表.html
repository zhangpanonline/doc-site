索引速查表

配合《索引互动教学课程》与《06.索引》使用。建议打印一份放在手边。

演示流程

INSERT 50 万行 → ANALYZE → 无索引 EXPLAIN → CREATE INDEX
→ ANALYZE → 有索引 EXPLAIN → DROP INDEX 清理

CREATE INDEX idx_order_created_at ON "order"(created_at);
DROP INDEX idx_order_created_at;
ANALYZE "order";   -- 刷新统计信息，让优化器感知索引

B+ 树要点

特性带来的好处
非叶子只存 key树矮（2~4 层），磁盘 IO 少
叶子用双向链表相连范围查询顺链扫描，极快
所有数据在叶子查找路径稳定 O(log n)

EXPLAIN type 等级（好 → 差）

system > const > eq_ref > ref > range > index > ALL
ALL = 全表扫描（最差，PG 显示 Seq Scan）

索引失效常见场景

  • 对索引列做运算/函数：created_at + 1 > … → 挪到常量侧
  • LIKE '%xxx'：前导 % 无法用树定位
  • 最左前缀断层：(a,b) 上查 b 失效
  • 隐式类型转换：字符串列传数字
  • OR 关联非索引列

核心要点

  • 索引 = 排序好的查找结构（B+ 树），书目录的比喻
  • 代价：占空间 + 写操作变慢——不是越多越好
  • ANALYZE 刷新统计，否则优化器可能不选索引
  • 回表：二级索引拿主键后再查聚簇索引
  • 覆盖索引：查询列全在索引里，免回表
  • 慢查询排查：EXPLAIN → type/rows/Extra → 建索引或改写
