配置与 use_mcp 骨架

{
  "servers": {
    "time": { "type": "stdio", "command": "uvx", "args": ["mcp-server-time"] },
    "microsoft-learn": { "type": "http", "url": "https://learn.microsoft.com/api/mcp" }
  }
}
结构代码要点
配置加载模块顶层 open(.../.agents/mcp.json) → json.load → _client = MCPClient(mcp)（import 阶段即读取）
connect_mcp@asynccontextmanager；stdio → StdioServerParameters(command=..., args=...) + stdio_client；http → streamable_http_client(url)（解包 三个 返回值）；两者都进 ClientSession 并 await session.initialize()；其它 type → raise ValueError("不支持的服务器类型: ...")
run_async开 threading.Thread → 内部 asyncio.run(coro) → nonlocal result, error 带回 → t.join() → 主线程 raise error
MCPClientalist_tools（逐台 connect_mcp + list_tools）/ acall_tool（call_tool）为异步实现；list_tools / call_tool 是同步包装；模块级 list_mcp_tools()
工具包装@tool(server_name="mcp服务器的名称", tool_name="工具名称", arguments="工具参数，无参工具可以不用传递")；def use_mcp(server_name, tool_name, arguments=None) 只返回 _client.call_tool(...)
为什么要有 run_async
Agent 主循环是同步的，MCP SDK 只提供异步 API；asyncio.run 不能在已有事件循环的线程里调用，所以借新线程拿一个全新事件循环（t.join() 会阻塞主线程，不是并发优化）。
两种传输（官方定义）
stdio：客户端把 MCP 服务器作为子进程启动，JSON-RPC 走它的 stdin/stdout，换行分隔；Streamable HTTP：服务器是独立进程、按 MCP 端点收 HTTP 请求。规范建议「Clients SHOULD support stdio whenever possible」。

提示词注入链路

list_mcp_info()                  # 逐个服务器取工具；字段 name / description / inputSchema
  ↓ list_mcp_tools()             # MCPClient.list_tools() → run_async(alist_tools())
  ↓ json.dumps(..., ensure_ascii=False, indent=2)   # 异常 → return ""
render_prompt(..., mcp_servers=list_mcp_info())
  ↓ Jinja2
system.j2 的 "# MCP" 小节：```json  {{ mcp_servers }}  ```
  • 它是「清单」不是「注册」：MCP 工具没有逐个注册进 registry，registry 里只有 use_mcp 一个网关；模型靠提示词里的 JSON 才知道有哪些服务器、哪些工具、参数 schema 长什么样。
  • 模型控制的代价：官方定位 MCP 工具是 model-controlled（模型自己发现并调用）。清单缺失或过期时，模型只能猜 server_name/tool_name——所以清单的准确性与可用性标记是接入层的一部分。
  • 工具只能传三样：server_name / tool_name / arguments；command、url 属于配置，不由模型提供。

错误处理缺口与修法

缺口现象修法
list_mcp_info 整段 try/except Exception: return ""MCP 不可达时静默降级：清单变空串，提示词仍教模型用 use_mcp，模型开始编服务器名，日志里毫无痕迹区分「无配置 / 不可达」，打 warning 或在清单里标记 error；给发现过程加超时
acall_tool 里 self.servers[server_name]服务器名写错 → KeyError → run_async 主线程重抛 → 穿过 tool(**args)、registry.invoke，打断整个 ReAct 循环，模型拿不到反馈改成校验 + 把「无此服务器/工具」作为 role=tool 内容回传；只让客户端自身 bug 抛出
Session.__init__ 双次 render_prompt("system")传入的 system_prompt 被丢弃（自定义提示词失效）；且每次新建 Session 触发两轮 MCP 工具发现 = 约 2 × N_servers 条连接链（每台都要 initialize + list_tools），远端不可达时构造函数被超时拖住只渲染一次并复用局部变量（system_prompt = system_prompt or render_prompt("system")）；清单加缓存/TTL，别把外部 IO 放进构造函数
print_friendly 里 except json.JSONDecodeError, TypeError:Python 2 旧语法，Python 3 下模块直接 SyntaxError写成 except (json.JSONDecodeError, TypeError):
一句话原则
模型能自我修正的错误 → 回传成 role=tool 内容；客户端自身的 bug → 才允许抛出终止。本章的 MCP 调用路径基本都走在「抛穿」那一侧。
生命周期
官方规范：初始化阶段必须是客户端与服务器的第一次交互（协商协议版本与能力）。本章「一次调用一次连接」意味着每次都要重跑这次握手——常驻会话 + 连接池是生产化的第一步。
版本与信任边界
SDK 官方建议给依赖加上界（如 mcp>=1.27,<2），课程钉的是 1.28.1；mcp.json 里能写 command 就等于能起本地进程，务必当可执行代码管理（评审 + 白名单 + 版本锁定）。
