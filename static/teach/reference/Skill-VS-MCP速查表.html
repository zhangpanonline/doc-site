Skill-VS-MCP速查表

配合《Skill-VS-MCP互动教学课程》使用。

一句话定位

SkillMCP
是什么可插拔的专业提示词模块（SKILL.md 目录）通过标准协议暴露工具与数据的服务器
定位差异告诉模型怎么做（流程与方法）告诉模型谁来做（已实现好的执行者）
产物形态自然语言指令（frontmatter + 正文）带 JSON Schema 的接口（tools/list / tools/call）
一句话记忆上层要活底层要稳

前提：课件原话——Skill 和 MCP 完全是两个东西，之所以放一起讨论，是因为在使用感官上有共同点：① 各有事实标准，因此容易形成社区与聚合站，能拿到大量现成的 SKILL 与 MCP 工具；② 功能体验重叠——获取某个城市的天气，用 Skill 能做，用 MCP 也能做。

差异表 · 八个维度（原表照录）

维度SkillMCP

接入成本低高

确定性低高

越权风险高低

口径：未命中＝本轮没被用到时的常驻开销；命中＝本轮真正被用上时的单次开销。Skill 未命中只挂描述（低）、命中读整份正文（高）；MCP 的工具定义通常预加载（高，可做渐进式披露）、命中只是走一次调用（低）。

最佳实践：MCP 定义底层工具，Skill 定义业务流程

层交给谁课件给的清单
底层工具MCP文件读写 · 命令执行 · 网络搜索 · 接口搜索与调用 · 代码执行 · 其他对确定性、安全性要求高的操作
业务流程Skill机票怎么定、行程怎么规划 · 退货能不能退、怎么退 · 怎么介绍产品 · 怎么成交 · 其他对灵活性、专业性要求高的流程
选型两问
① 这件事要的是确定性/安全还是灵活/专业？② 它会被频繁改动、由业务方多人贡献吗？前一问答「确定性」→ MCP；后一问答「是」→ Skill。
越权风险从哪来
Skill 靠自然语言指挥模型，可能被越权提问带偏；MCP 的行为被 schema 与实现钉死。故「资金、对外消息、危险命令」类动作应由工具兜底，Skill 只写判定与调用时机。
MCP 上下文怎么救
不要把工具定义一次性全量预加载；按需发现/加载工具定义（渐进式披露）是课件在差异表里给出的解法。
Skill 上下文怎么省
description 决定命中与否（写清适用场景，别写「处理相关问题」）；长参考资料拆成按需引用的附加文件，避免命中时整份灌进上下文。
两者怎么配合
Skill 描述业务流程时，把 MCP 工具当作执行底座——「判定在 Skill，动作在 MCP」。

易错点

  • 拿「能不能做」选型——功能体验重叠是常态（天气那个例子），要看八个维度的取舍。
  • 把两者当替代关系——「MCP 贵就全换 Skill」会同时丢掉确定性与安全性；正确动作是分层 + 对 MCP 做渐进式披露。
  • 把反直觉的数字记反——Skill 是「未命中低、命中高」，MCP 是「未命中高、命中低」。
  • 给每个小流程造一个 MCP 服务器——MCP 接入成本高、可扩展性低、贡献人群窄，堆量场景应交给 Skill。
  • 让 Skill 直接算钱/发消息——越权风险高的典型，副作用动作必须收进带 schema 的工具。
