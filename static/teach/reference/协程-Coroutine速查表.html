协程-Coroutine速查表

配合《协程互动教学课程》与《26.协程 Coroutine》使用。建议打印一份放在手边。

术语表

协程函数
async def 定义的函数。调用它不会执行函数体，而是返回一个协程对象。
协程对象
协程函数调用的产物。需要事件循环（或 Task）驱动才会真正执行。
awaitable
可被 await 等待的对象：协程对象、Task、Future。
await
只能在协程函数内使用；等待 awaitable 完成，并把结果取回给当前协程。
Task
Future 的子类，专门用于驱动协程对象；create_task 创建后立即调度（放入就绪队列）。
Future
表示「未来的结果」的对象，完成时触发回调（见《25.Future类》）。
事件循环
用户态调度器，负责调度 Task 与 Future；asyncio.run 内部创建并驱动它。
回调地狱
层层嵌套注册回调的写法，代码横向增长、可读性差——协程要解决的问题。

语法速查

定义与调用

async def test():                       # 协程函数
    resp = await async_request(...)     # 等待 awaitable，取回结果
    return "ok"

coro = test()                           # 协程对象（此时函数体未执行）

Task 与 asyncio.run

task = asyncio.create_task(coro)        # 包装成 Task，立即调度执行
# 协程执行结束 → Task 完成 → task.result() 即协程返回值

result = asyncio.run(coro)              # 内部转换为 Task，阻塞直到完成
print(result)                           # "ok"

手动驱动（理解机制用，日常别这么写）

r = coro.send(None)                     # 启动协程，拿到第一个 awaitable
def done_callback(fut):
    try:
        r = coro.send(fut.result())     # Future 完成 → 协程恢复
        r.add_done_callback(done_callback)
    except StopIteration as e:          # 协程执行完毕
        f.set_result(e.value)           # e.value 即返回值

线程 vs 协程（速览）

维度🧵 线程🍃 协程
运行载体内核态，操作系统调度用户态，事件循环调度
切换成本昂贵，数百个时钟周期极廉价，几十个时钟周期
资源开销高，每线程栈空间数 MB极低，协程栈仅几 KB
数据同步共享内存，需锁，易死锁/竞态单线程内天然无数据竞争
利用多核✅ 原生支持❌ 单线程内不支持
适用场景CPU 密集 / 实时性高的 I/O海量 I/O 密集（爬虫、Web 服务）
典型数量级百级别万 / 十万级别

常见误区

  • 调用协程函数 ≠ 执行函数体。忘记 await 或忘记交给事件循环，函数体根本不会运行。
  • await 只能出现在协程函数（async def）内部。
  • create_task 创建的是「已调度的 Task」：协程会立即进入就绪队列，但何时真正执行由事件循环安排。
  • asyncio.run 会阻塞当前线程直到协程完成：写在它后面的代码要等协程结束才会执行（顺序预测题常考）。
