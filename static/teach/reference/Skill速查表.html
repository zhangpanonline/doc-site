Skill速查表

配合《Skill互动教学课程》使用。

它解决什么问题

Skill 是一套可插拔的专业提示词模块：每个 Skill 对应一个特定场景（处理越权提问、数据分析、客服应答等），只有当用户问题匹配该场景时，内容才会被注入上下文——按需加载避免了系统提示词的无限膨胀。

做法系统提示词里放什么代价
全量硬塞所有场景的完整说明（数据来源、字段含义、产品参数、活动、购买链接……）严重的提示词膨胀；与当前任务无关的指令每轮都在干扰
Skill 按需加载只有「技能名 + description」清单多一次工具调用；换来按需注入与可插拔

课件的判断依据：这些提示词只有在某些场景下才会触发（用户「有时候」要销售分析、「经常」问产品）。

渐进式披露：三级加载

级别内容何时进入上下文本章对应
第一级每个 Skill 的 name + description启动时预载进系统提示词prompt.py 的 list_skills() → system.j2 清单
第二级SKILL.md 正文（完整指令）模型判定相关时读入use_skill 工具按需返回
第三级及以后技能目录里被引用的脚本 / 参考文档 / 模板需要时按名再读use_skill 返回的 path 指向技能目录

description 决定「什么时候想起来」，正文决定「想起来之后怎么做」——写成空串或含糊描述，技能就永远不会被触发。

SKILL.md 格式速查

agent/.agents/skills/<技能名>/
└── SKILL.md          # frontmatter + 正文（本章两个技能：no-permission、frontend-design）

---                   # 文件必须以 --- 开头
name: no-permission   # 必需；限 64 字符，小写字母 / 数字 / 连字符
description: 当用户和你和开发无关的问题时，使用此技能   # 必需、非空；写清「做什么 + 何时用」
---

统一回复：“我是一个编程助手，我无法回复你这个问题，请把话题限制在开发领域”
frontmatter 字段必需说明
name是技能名，同时是目录名与运行时路由键（SKILL_BASE_DIR / skill_name / "SKILL.md"）
description是模型判断「何时加载」的主要依据，非空
license / compatibility / metadata否许可、环境要求、自定义键值
allowed-tools否该技能可使用的预先批准的工具（空格分隔，实验性）——技能层的权限声明

本章工程链路

# 1. 新增 agent/tool/use_skill.py
SKILL_BASE_DIR = Path(__file__).parent.parent / ".agents" / "skills"
skill_file = SKILL_BASE_DIR / skill_name / "SKILL.md"   # 不存在 → FileNotFoundError
parts = content.split("---")                            # 取 frontmatter
meta = yaml.safe_load(parts[1]) if len(parts) >= 3 else {}
return json.dumps({"meta": meta, "content": content, "path": str(skill_file)})

# 2. 修改 agent/prompt.py：list_skills() 扫描技能目录 → [{技能名: meta}, …]
# 3. 修改 agent/prompt/system.j2：两层 for 渲染清单（外层列表、内层 items()）
# 4. 修改 agent/tool/__init__.py：registry.register(use_skill)

# 5. 安装公共 Skill（需先装 node；公共技能检索 https://www.skills.sh/）
npx skills add https://github.com/anthropics/skills --skill frontend-design
agent/skills-lock.json

权限与信任边界
技能正文会逐字进入模型上下文：恶意 skill 可能引入漏洞或指使模型外泄数据。只从可信来源安装，来源不够可信时先审计内容、代码依赖与捆绑脚本，并警惕让模型访问不可信外部网络的指令。
验证触发
agent.invoke("最近天气如何？")——越权提问应被 no-permission 接管；agent.session.print_friendly() / session.tools 查看当前上下文与工具清单。

易错点

  • 把正文抄进系统提示词：等于放弃这一整章——第一级清单常驻、第二级正文按需，界线不能破。
  • 手工切 frontmatter：split("---") 靠「切出至少三段」判断，文件没有 frontmatter 或开头多空行 / BOM 时 meta 会静默变成 {}；frontmatter 内部出现 --- 还会截断。应断言以 --- 开头、split("---", 2) 或换解析器，并对必需字段做非空校验。
  • 用 yaml.load 读技能：官方警告它和 pickle.load 一样能调用任意 Python 函数；第三方 SKILL.md 是外部数据，必须用 yaml.safe_load。
  • 技能名对不上：frontmatter 的 name、目录名、模型传参三者必须一致，否则 FileNotFoundError 会直接穿到调用方（本章 registry.invoke 没有兜底）。
  • description 写成空或含糊：模型失去唯一触发线索，技能装了等于没装；反过来写成「用于所有问题」则会过度触发，把正常问题也拦掉。
