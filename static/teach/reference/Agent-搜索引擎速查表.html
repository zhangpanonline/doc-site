Agent-搜索引擎速查表

配合《Agent-搜索引擎互动教学课程》使用。

为什么要换搜索引擎

本章的问题意识：问题的关键是，web_search 工具应该返回给 AI 什么调用结果？把传统搜索引擎的结果页直接交给 Agent，会遇到下面这串问题。

传统结果页的问题对 Agent 的实际影响
内容被大量标签、样式、JS 代码污染更多的 token 消耗
页面里塞满广告图片、菜单、banner注意力被分散；包含大量无关信息
很多 CSR（客户端渲染）页面抓不到内容
链接层级深深层链接无法一次性获取

本章列出的、更适合 Agent 调用的搜索引擎：Firecrawl · Tavily · AnySearch · Brave · Exa。本章实战用 Tavily。

Tavily 三类能力 → 两个工具

能力入参（本章课件）返回什么封装成的工具
client.searchquery="可控核聚变最新研究进展"结构化搜索结果web_search（@tool(query="搜索关键字")）
client.extracturls=[…]、include_images=…指定 URL 的网页内容fetch_url（@tool(urls="要抓取的url链接数组")）
client.crawlurl=…、max_depth=3、limit=50、instructions="找到所有和网络相关的知识"站点遍历结果本章未封装成工具，仅演示用法
安装
uv add tavily-python==0.7.26（课件锁定版本）。
密钥
官网获取 API KEY 后保存到环境变量；agent/config.py 新增 TavilySettings，model_config = {"env_prefix": "TAVILY_"}，代码里只写 TavilyClient(api_key=tavily_settings.api_key)。
为什么两个工具都要
search 用关键词发现来源，模型此时手里没有 URL；extract 按已知 URL取正文。少任何一个，链路都是断的。

集成链路（本章 agent/ 变更）

# 新增 agent/tool/web.py
@tool(query="搜索关键字")
def web_search(query: str):
    "根据关键字进行网络搜索，返回结构化的搜索结果"
    client = TavilyClient(api_key=tavily_settings.api_key)
    response = client.search(query=query)
    return json.dumps(response, ensure_ascii=False)

@tool(urls="要抓取的url链接数组")
def fetch_url(urls: list[str]):
    "根据提供的url数组，抓取网页内容，返回结构化的搜索结果"
    client = TavilyClient(api_key=tavily_settings.api_key)
    response = client.extract(urls=urls, include_images=False)
    return json.dumps(response, ensure_ascii=False)

# 修改 agent/tool/__init__.py
from agent.tool.web import web_search, fetch_url
registry.register(web_search)
registry.register(fetch_url)
文件类型要点
agent/tool/web.py新增两个联网工具，返回值统一是 JSON 字符串
agent/config.py修改新增 TavilySettings（env_prefix = "TAVILY_"）与 tavily_settings
agent/model.py修改流式/非流式响应的归一化处理，供工具调用链路使用
agent/tool/__init__.py修改import 两个新工具并 registry.register
分析.md删除本次工程清理

合计：新增 1、修改 3、删除 1。运行链路（原理图）：用户问题 → 模型（上下文 + 工具）→ web_search 工具调用 → 调用结果回填 → Reasoning / Acting 循环 → 普通回复 → 退出循环。

官方参数与成本速查（Tavily）

项目官方约束什么时候调
query官方建议 < 1500 字符；多主题需求拆子查询分别发查询变长、意图变杂时先改写
search_depthbasic（默认）1 credit；advanced 2 credits、相关性最高延迟更高冷门主题 / 刚发布内容 / 多侧面问题才上 advanced
max_results官方提示设得过高可能返回更低质的结果Agent 场景常用 3–5 条
include_raw_content返回完整正文；官方推荐「先 search 拿 URL，再 Extract 取内容」的两段式需要正文时改用 Extract，不要批量开
Extract urls一次最多 20 个 URL，超限 400（Max 20 URLs are allowed.）超过就分批 urls[i:i+20]
Extract 返回结构成功在 results，逐个失败在 failed_results；HTTP 200 也要同时检查两个数组存在 failed_results 时显式告知模型
query + chunks_per_source（Extract）给 query 后返回按相关性重排的片段，chunks_per_source 1–5（每片 ≤500 字符）长文档只取相关片段，防止上下文爆炸
成本量级$C \approx 2N_{\text{adv}} + N_{\text{basic}} + \lceil U/5 \rceil$（basic 抽取每 5 个成功 URL 计 1 credit）估算日调用量对应的预算

官方文档：Search · Extract · Best Practices for Search · Best Practices for Extract · tavily-python

易错点清单

  • 把用户整段长需求直接当 query（官方上限 1500 字符），检索意图被稀释
  • API KEY 硬编码进源码——本章要求存环境变量，由 TavilySettings 读取
  • 写了 @tool 却忘记 registry.register，模型侧看不到工具
  • 工具返回 dict 而不是字符串：tool 消息的 content 需要文本（本章统一 json.dumps）
  • ensure_ascii=True（默认）会把中文转成 \uXXXX，难读又费 token
  • 一次性给 extract 超过 20 个 URL，整批被 400 拒绝
  • 只看 results 不看 failed_results，静默丢掉失败来源
  • 把完整响应（含 raw_content、图片）长期留在上下文——工具结果会累积，token 与注意力双重损耗
